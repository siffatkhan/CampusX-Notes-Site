Day 4

The Perceptron

The perceptron is the single most important building block in deep learning — it is a mathematical function/model originally designed for supervised machine learning, and because of the way it is structured, it turned out to also be the foundational unit that every larger neural network is built from. Understanding it fully pays off for everything that follows.

The Math

Given inputs \(x_1, x_2, \dots\), each input has an associated weight \(w_1, w_2, \dots\) that represents the strength of that feature — how much that particular input matters for the decision being made. All the weighted inputs are summed together along with a bias term \(b\) to produce a single number \(z\):

$$ z = w_1x_1 + w_2x_2 + b $$

That \(z\) is then passed through an activation function \(f\), producing the final output:

$$ y = f(z) $$

The activation function's job is to squash \(z\) — which can be any real number — into a constrained, useful range, such as \([0, 1]\) or \([-1, 1]\). So the target/prediction \(y\) is a function of \(z\), and \(z\) itself is a function of the weighted inputs and the bias.

Neuron vs. Perceptron

A biological neuron is enormously complex — it can receive billions of inputs, and we still don't fully understand everything that happens inside its nucleus as it processes them. A perceptron is a deliberate simplification: we know exactly what happens — multiply each input by a weight, sum them with a bias, and pass the result through an activation function. The perceptron is inspired by the neuron, but it is not a true copy of it. One concrete difference is neuroplasticity: a biological neuron's input connections can physically strengthen or weaken over time as the brain adapts, whereas a perceptron's weights only change when an external training algorithm updates them — they don't self-organize.

"A perceptron is nothing but a line"

Because \(z = w_1x_1 + w_2x_2 + b\) is a linear equation, the decision boundary a perceptron draws between two classes is always a straight line (or, in higher dimensions, a flat hyperplane). This is both its power and its fundamental limitation: it can only separate data that is linearly separable — data that can be split cleanly by a straight line. Give it nonlinear data, and the perceptron simply fails, no matter how it's trained.

Why a perceptron cannot learn XOR

XOR (exclusive OR) outputs 1 when its two binary inputs differ (0,1 → 1 and 1,0 → 1) and 0 when they match (0,0 → 0 and 1,1 → 0). Plot these four points on a 2D plane and there is no single straight line that separates the "1" outputs from the "0" outputs — the true points sit on opposite corners from each other. Since a perceptron can only draw a straight-line decision boundary, and XOR is fundamentally a nonlinear function, a single perceptron can never learn it. This single failure is historically significant — it's the reason the field moved toward stacking multiple perceptrons into multi-layer networks, which can bend and combine multiple lines into a nonlinear boundary.

What Happens Inside a Single Neuron

In a standard neural network, essentially every neuron except the input neurons carries an activation function. The general rule:

  • Hidden neurons — each has an activation function.
  • Output neurons — each has an activation function appropriate for the task (or linear, for regression).
  • Input neurons — typically have no activation function; they simply pass the raw input features forward.
  1. Receive inputs from the previous layer.
  2. Multiply each input by its corresponding weight.
  3. Add all the weighted inputs together.
  4. Add a bias.
  5. Apply the activation function.
  6. Output the result to the next layer.

Written generally, for any number of inputs:

$$ z = w_1x_1 + w_2x_2 + \cdots + w_nx_n + b, \qquad a = f(z) $$

where \(x_i\) = inputs, \(w_i\) = weights, \(b\) = bias, \(z\) = weighted sum (pre-activation), \(f\) = activation function, \(a\) = the neuron's output.

Day 5

The Perceptron Trick

Before loss functions and gradient descent, the original perceptron algorithm learned its weights through a simple, geometric, iterative rule known as the perceptron trick. A tool like Desmos is useful here — it lets you visualize a line in the 2D plane and watch it move as you change its coefficients, which builds real intuition for what the trick is doing.

Step 1 — Which side of the line is a point on?

Take the line's equation and simply substitute the point's coordinates into it. If the resulting value is less than 0, the point lies in the negative region; if it is greater than 0, the point lies in the positive region. This one check is the entire basis of the algorithm: for every misclassified point, we know exactly which side of the line it incorrectly falls on.

Step 2 — Move the line toward the misclassified point

Once we know a point is on the wrong side, we nudge the line's weights and bias using that point's own coordinates:

  • If a point that should be positive is sitting in the negative region, we add the point's coordinate values to the line's weights (and bias) — this pulls the line toward the negative region, bringing that point onto the correct side.
  • If a point that should be negative is sitting in the positive region, we subtract the point's coordinate values — this pushes the line toward the positive region instead.

The reason this works is geometric: adding a point's own coordinates to a line's coefficients shifts and rotates the line in the direction of that point, effectively "pulling" the boundary across it. Repeating this update, one misclassified point at a time, over many iterations is literally how the classical perceptron algorithm finds its weights.

Three problems with the perceptron trick

  1. No guarantee of the best line. The trick only reacts to whichever point is currently misclassified. If a badly-placed point (say, an outlier) forces an update, the line can shift toward accommodating that one point — there's nothing in the algorithm ensuring the resulting line is actually the best possible separator overall.
  2. No way to quantify quality. The trick tells you "move the line" but gives you no numeric score for how good or bad the current line is. You can't compare two candidate lines, or track whether the model is actually improving — there's no measurement, only a reactive nudge.
  3. Convergence problems. Sometimes the line simply refuses to settle — it keeps oscillating between updates and never converges to a stable solution, particularly if the data isn't cleanly linearly separable.

All three problems point to the same underlying gap: there is no formal, differentiable measure of error to optimize. That gap is exactly what a loss function fills.

Day 6

The Perceptron Loss Function

A loss function is a function that tells us numerically how good or bad our model is currently performing — exactly the missing piece from the perceptron trick. Perceptron error is calculated differently from how logistic regression or linear regression calculate theirs: instead of a distance-based or probability-based error, the perceptron uses hinge loss:

$$ L = \frac{1}{n}\sum_{i=1}^{n} \max\big(0,\, -y_i \cdot f(x_i)\big) $$

Here \(n\) is the number of rows (samples), \(y_i\) is the true label (+1 or −1), and \(f(x_i)\) is the model's raw prediction for that row. The term \(-y \cdot f(x)\) is the key to reading this formula: when the prediction has the same sign as the true label (a correct classification), \(y \cdot f(x)\) is positive, so \(-y \cdot f(x)\) is negative, and \(\max(0, \text{negative number})\) evaluates to 0 — a correctly classified point contributes zero loss. When the prediction has the opposite sign from the true label (a misclassification), \(y \cdot f(x)\) is negative, so \(-y \cdot f(x)\) is positive, and that positive value becomes the penalty added to the loss. In short: correct points cost nothing, wrong points cost something proportional to how wrong they are, and the total loss is the average of those penalties across all \(n\) rows.

Different tasks pair a specific activation function on the output layer with a specific loss function suited to measuring error for that task:

Day 7

The Problem With the Perceptron

Even with a proper loss function to guide it, a single perceptron has a hard ceiling: it can only work on linearly separable data. Give it data that requires a curved or complex boundary and it simply cannot converge to a correct solution, no matter how the loss function or trick are tuned — the model's own structure (one straight-line boundary) is the bottleneck, not the training method.

Hands-on tool: playground.tensorflow.org is a great tool for interactively experimenting with neural networks — you can watch, in real time, how adding layers and neurons lets a network bend a straight decision boundary into a curved one that separates nonlinear data like the "circle" dataset.

The fix: Multi-Layer Perceptron (MLP)

The solution to the single perceptron's linear-only limitation is to stack multiple perceptrons together into layers — an MLP. Instead of one straight-line boundary, a network of many perceptrons can combine several lines into a boundary of arbitrary complexity. The genuinely hard part of making this work is not the architecture itself, but training it — specifically, the algorithm called backpropagation, which figures out how to adjust every weight in every layer of a multi-layer network based on the final output error. That is the subject of the next few pages.

Hard

5 questions on Day 4–7. Pick an answer for each, then check.

1. Why can a single perceptron never learn the XOR function?

Explanation: A perceptron is "nothing but a line" — its decision boundary is always linear. XOR is a nonlinear function (its 1-outputs sit on opposite corners from its 0-outputs), so no straight line can separate them.

2. In the perceptron trick, a positive-class point is currently misclassified into the negative region. What update is applied?

Explanation: If we need to move the line toward the negative region (to correctly capture a positive point stuck there), we add the point's values to the weights and bias — this pulls the line toward it.

3. A point is correctly classified by the perceptron (prediction and true label share the same sign). What is its hinge loss contribution?

Explanation: For a correct prediction, \(y \cdot f(x)\) is positive, so \(-y \cdot f(x)\) is negative, and \(\max(0, \text{negative})=0\). Correctly classified points contribute zero loss.

4. Which activation/loss pairing is used for multiclass classification?

Explanation: Per the activation/loss table: Softmax activation is paired with Categorical Cross-Entropy loss specifically for multiclass classification.

5. What is the real bottleneck that a single perceptron cannot overcome even with a good loss function?

Explanation: The loss function only improves how well the single line is fit — it can't change the fact that the model's structure is one straight-line boundary. Fixing this requires a structural change: stacking perceptrons into an MLP.
