5. Loss Functions in Deep Learning

Loss vs. Cost · Survey by Task · MSE, MAE, Huber · Binary & Categorical Cross-Entropy · Sparse Categorical Cross-Entropy

Day 11

What a Loss Function Is

A loss function is a method of evaluating how well your algorithm is modeling your dataset. A high value of loss means the algorithm is performing poorly; a low value means it is performing well. Loss functions matter because you cannot improve what you cannot measure — the loss function is, in a real sense, the "eye" of a machine learning algorithm: it is the only signal that tells the algorithm which direction to move its parameters in to get better.

Loss function vs. cost function

Loss function — the error computed for a single training example. Cost function — the sum (or average) of the loss over an entire batch or dataset. In other words, loss is per-sample, and cost aggregates many losses into one number that a training algorithm like gradient descent actually tries to minimize.

Regression

Mean Squared Error (MSE) — L2 Loss

$$ MSE = \frac{1}{n}\sum_{i=1}^{n}(y_i - \hat{y}_i)^2 $$

Meaning: MSE squares each error and then averages the squares. Because squaring a number always makes it positive and grows disproportionately for larger inputs, large errors become very large under MSE. Intuition: "punish large mistakes more."

The outlier example

Take errors of 2, 3, 4, and 100 across four samples. Squaring each gives 4, 9, 16, and 10000. The single outlier error of 100 contributes 10000 to the sum, while the other three combined contribute only 29 — one outlier dominates everything. This is the central weakness to understand about MSE: it is extremely sensitive to a small number of large errors.

Advantages
  • Differentiable everywhere — works cleanly with gradient descent
  • Easy to optimize
  • Has one local minimum (for linear models), so optimization doesn't get stuck

Why squaring helps: it removes the negative sign (so errors don't cancel out), makes the function smooth, and is easy to optimize using gradient descent.

Disadvantages
  • Its unit becomes squared (e.g. rupees² for a salary prediction), which is hard to interpret back in the original unit
  • Not robust to outliers — as shown above, big errors become extremely big and dominate the result

Rule of thumb

More outliers in your data → prefer MAE. Clean data with few/no outliers → MSE is a good default. Also important: to apply MSE correctly, the last (output) layer's activation function must be linear — MSE is designed to compare unbounded real-valued predictions against real-valued targets, so squashing the output through a sigmoid or softmax first would distort the comparison.

Regression

Mean Absolute Error (MAE) — L1 Loss

$$ MAE = \frac{1}{n}\sum_{i=1}^{n}|y_i - \hat{y}_i| $$

MAE takes the absolute value of each error (ignoring its sign) rather than squaring it, then averages those magnitudes. Applying MAE to the same outlier example — errors 2, 3, 4, 100 — gives \((2+3+4+100)/4 = 27.25\). Compare this to MSE's massively outlier-skewed result: the 100 still pulls the average up, but nowhere near as violently as squaring did, because MAE grows only linearly with the size of the error rather than quadratically.

Advantages
  • Same unit as the output — directly interpretable
  • More robust to outliers than MSE, since it doesn't amplify large errors quadratically
Disadvantages

Not differentiable at exactly zero error — the absolute value function has a sharp corner there, which complicates gradient-based optimization at that point (though in practice this is rarely a serious obstacle).

Regression

Huber Loss

Huber Loss is designed as a compromise between MSE and MAE: it behaves like MSE (quadratic, smooth) for small errors, and like MAE (linear, less sensitive to outliers) for large errors, switching between the two behaviors at a threshold value \(\delta\):

$$ L_\delta(y, \hat{y}) = \begin{cases} \frac{1}{2}(y-\hat{y})^2 & \text{if } |y-\hat{y}| \le \delta \\ \delta\left(|y-\hat{y}| - \frac{1}{2}\delta\right) & \text{otherwise} \end{cases} $$

The practical benefit is exactly what its two-regime design suggests: Huber gives you the smooth, easily-optimized behavior of MSE for the bulk of "normal" errors, while capping the outsized influence that a handful of large outlier errors would otherwise have under pure MSE — giving you much of MAE's outlier robustness without fully losing MSE's smoothness near zero.

Classification

Binary Cross-Entropy (Log Loss)

Binary cross-entropy — also called log loss — is used whenever the classification problem has exactly two classes (e.g. spam vs. not spam). It pairs naturally with a sigmoid output neuron, which produces a probability between 0 and 1 for the positive class, and the loss penalizes the model heavily when it is confidently wrong (predicts close to 0 when the true label is 1, or vice versa).

$$ L = -\frac{1}{n}\sum_{i=1}^{n}\Big[y_i\log(\hat{y}_i) + (1-y_i)\log(1-\hat{y}_i)\Big] $$

Binary cross-entropy is differentiable, so gradient descent can be applied to it directly. One caveat worth remembering: unlike MSE for a simple linear model, the loss surface for binary cross-entropy on a neural network is not guaranteed to have a single global minimum — it can have multiple local minima, which is one reason training a classifier's weights can be sensitive to initialization and optimizer choice.

Classification

Categorical Cross-Entropy

Categorical cross-entropy generalizes binary cross-entropy to problems with more than two classes — for example, a target feature with categories like "yes," "no," and "maybe." It is the loss function used in softmax regression: the output layer applies the softmax activation function, which converts the raw output scores into a proper probability distribution across all classes (all values between 0 and 1, summing to 1), and categorical cross-entropy then measures how far that predicted distribution is from the true one-hot-encoded label.

$$ L = -\sum_{c=1}^{C} y_c \log(\hat{y}_c) $$

Output layer sizing rule

In multiclass categorical classification, the number of neurons in the output layer must equal the number of classes. If there are three classes in the target, the output layer needs exactly three neurons — each one producing the (softmax-normalized) probability that the input belongs to that particular class.

Classification

Sparse Categorical Cross-Entropy

Sparse categorical cross-entropy computes mathematically the same thing as categorical cross-entropy, but it accepts the true label as a plain integer class index (e.g. \(2\) for the third class) instead of requiring you to first convert it into a one-hot encoded vector (e.g. \([0, 0, 1]\)). Because it skips the one-hot encoding step entirely, it is faster and uses less memory — a practical convenience that matters a great deal once you're working with a large number of classes, where one-hot vectors would otherwise be mostly zeros wasting space and computation.

Hard

5 questions on Day 11 loss functions. Pick an answer for each, then check.

1. What is the precise distinction between a "loss function" and a "cost function"?

Explanation: Loss = single training example's error. Cost = sum of all the losses across a batch/dataset.

2. Given errors 2, 3, 4, and 100, why does MSE react so much more dramatically to the outlier than MAE does?

Explanation: Squaring the error 100 gives 10000, dwarfing the other squared errors (4, 9, 16) — one outlier dominates. MAE just sums |100| = 100, still noticeable but far less extreme, since it grows linearly.

3. To correctly apply MSE as your loss function, what must be true about the output layer's activation function?

Explanation: MSE (used for regression) requires the last neuron's activation to be linear, so the network can output any real-valued prediction to compare against the real-valued target.

4. A dataset has 3 classes. Per the source notes' rule, how many neurons should the output layer have for categorical cross-entropy?

Explanation: In multiclass categorical classification, the number of output neurons must match the number of classes — one neuron per class, each outputting that class's softmax probability.

5. What is the key practical advantage of sparse categorical cross-entropy over regular categorical cross-entropy?

Explanation: Sparse categorical cross-entropy takes the integer class index directly instead of a one-hot vector — mathematically equivalent to categorical cross-entropy, but faster and lighter on memory since it skips the one-hot encoding step.
