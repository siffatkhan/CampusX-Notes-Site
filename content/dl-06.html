Day 12

Backpropagation — What It Is

Backpropagation is the algorithm used to train neural networks with gradient descent. A neural network only has two kinds of learnable numbers — its weights and biases — and backpropagation is simply the procedure that figures out, for every single one of them, "should this number go up or down, and by how much, so that the network's predictions get a little better?" It does this by pushing the prediction error backward through the network, layer by layer, from the output toward the input — hence the name.

Backpropagation follows a fixed series of steps that repeat over and over during training:

  1. Step 0 — Initialize: set the weights w and bias b, either randomly or to simple starting values (e.g. w = 1, b = 0). They have to start somewhere before anything can be learned.
  2. Step 1 — Select a point: pick one row (one training example) from the dataset.
  3. Step 2 — Forward propagation: push that row through the network — a series of dot products and activations — to produce a prediction \( \hat{y} \).
  4. Step 3 — Choose a loss function: measure how wrong the prediction was, e.g. \( (y-\hat{y})^2 \).
  5. Step 4 — Update: adjust every weight and bias using gradient descent so that, next time, the loss would be a little smaller.
The one distinction to hold onto for this whole page: the derivative used in gradient descent does not tell you how much the prediction changes when you nudge a weight. It tells you how much the loss changes when you nudge that weight. Gradient descent then moves the weight in whichever direction makes the loss smaller. The source material is explicit and repeated about this point precisely because it's the thing people misunderstand first — it feels intuitive to think "changing w changes ŷ," which is true, but the quantity backprop actually computes and acts on is "changing w changes L."
Day 13

Backpropagation — The How

Take the simplest possible model — a single neuron with one input, doing something equivalent to linear regression — and walk through exactly what "update the weight" means mathematically.

  1. Make a prediction.
    $$ \hat{y} = wx + b $$
  2. Calculate the loss.
    $$ L = (\hat{y} - y)^2 $$
  3. Compute the derivative of the loss with respect to the weight.
    $$ \frac{\partial L}{\partial w} $$

    This answers exactly one question: "If I change the weight w by a tiny amount, how much will the loss L change?" — nothing about how much ŷ itself moves, only how the final loss reacts.

  4. Update the weight using gradient descent.
    $$ w_{new} = w_{old} - \alpha \frac{\partial L}{\partial w} $$

    where \( \alpha \) is the learning rate — a hyperparameter controlling how big a step is taken in the direction that reduces the loss. The same update rule applies to the bias b, using \( \partial L / \partial b \) instead.

The Full Backpropagation Algorithm

Stitching the steps into one training loop over many epochs:

for epoch in range(epochs):
    epoch_losses = []

    for i in range(len(training_data)):
        # 1. select one row (stochastic-style update)
        x, y = random_row(training_data)

        # 2. forward propagation — predict
        y_hat = forward_pass(x, weights, biases)

        # 3. compute loss for this row
        loss = (y_hat - y) ** 2
        epoch_losses.append(loss)

        # 4. update every weight and bias via gradient descent
        gradients = backward_pass(loss, weights, biases)
        weights, biases = gradient_descent_update(weights, biases, gradients, lr=alpha)

    # track how the model is doing this epoch
    avg_epoch_loss = sum(epoch_losses) / len(epoch_losses)
    print(f"epoch {epoch}: avg loss = {avg_epoch_loss}")

Watching the average epoch loss fall (and eventually flatten out) across epochs is the single most direct way to see backpropagation working.

A Full Worked Numeric Example

Extended notes — the source explicitly asks, in its own words, "make me understand how we back propagate with some example, take some dataset and show everything happen in back propagation," and never follows through with one. This worked example is written from scratch to actually answer that question, using a tiny two-layer network with concrete numbers all the way through.

Take the smallest network that still has something to "propagate back" through: one hidden neuron and one output neuron, both using the sigmoid activation \( \sigma(z) = \frac{1}{1+e^{-z}} \), which has the convenient derivative \( \sigma'(z) = \sigma(z)\big(1-\sigma(z)\big) \).

SymbolMeaningValue
x₁, x₂two input features for one training row1.0, 0.5
ytrue label for this row1
w₁, w₂, bₕinput → hidden neuron weights & bias0.3, −0.2, 0.1
wₒ, bₒhidden → output weight & bias0.5, −0.1
αlearning rate0.1

Step 1 — Forward Propagation

Hidden neuron pre-activation and activation:

$$ z_h = w_1 x_1 + w_2 x_2 + b_h = (0.3)(1.0) + (-0.2)(0.5) + 0.1 = 0.30 $$ $$ a_h = \sigma(z_h) = \sigma(0.30) \approx 0.5744 $$

Output neuron pre-activation and activation (the network's prediction):

$$ z_o = w_o a_h + b_o = (0.5)(0.5744) + (-0.1) \approx 0.1872 $$ $$ \hat{y} = \sigma(z_o) = \sigma(0.1872) \approx 0.5467 $$

Step 2 — Compute the Loss

$$ L = (\hat{y}-y)^2 = (0.5467 - 1)^2 \approx 0.2055 $$

The network predicted 0.5467 for a row whose true label is 1 — a real but moderate mistake, and this is the number backpropagation is trying to shrink.

Step 3 — Backward Pass: Output-Layer Gradient

To update wₒ, the chain rule breaks \( \partial L / \partial w_o \) into three easier pieces — "how loss depends on ŷ," "how ŷ depends on zₒ," and "how zₒ depends on wₒ":

$$ \frac{\partial L}{\partial w_o} = \frac{\partial L}{\partial \hat{y}} \cdot \frac{\partial \hat{y}}{\partial z_o} \cdot \frac{\partial z_o}{\partial w_o} $$
PieceFormulaValue
∂L/∂ŷ2(ŷ − y)2(0.5467−1) ≈ −0.9066
∂ŷ/∂zₒŷ(1−ŷ)0.5467×0.4533 ≈ 0.2478
∂zₒ/∂wₒaₕ0.5744
$$ \frac{\partial L}{\partial w_o} \approx (-0.9066)(0.2478)(0.5744) \approx -0.1291 $$

Step 4 — Backward Pass: Hidden-Layer Gradient (the actual "back-propagating")

To update w₁, the error signal has to travel one layer further back — through aₕ and zₕ — before it reaches w₁. This extra hop, chaining derivatives across two layers instead of one, is exactly what makes this "backpropagation" rather than a single derivative:

$$ \frac{\partial L}{\partial w_1} = \underbrace{\frac{\partial L}{\partial z_o}}_{\text{reused from step 3}} \cdot \frac{\partial z_o}{\partial a_h} \cdot \frac{\partial a_h}{\partial z_h} \cdot \frac{\partial z_h}{\partial w_1} $$
PieceFormulaValue
∂L/∂zₒ(∂L/∂ŷ)(∂ŷ/∂zₒ), already computed in step 3(−0.9066)(0.2478) ≈ −0.2247
∂zₒ/∂aₕwₒ0.5
∂aₕ/∂zₕaₕ(1−aₕ)0.5744×0.4256 ≈ 0.2445
∂zₕ/∂w₁x₁1.0
$$ \frac{\partial L}{\partial w_1} \approx (-0.2247)(0.5)(0.2445)(1.0) \approx -0.0275 $$

Notice that \( \partial L/\partial z_o \) — computed once in step 3 — is reused rather than recomputed here. This reuse of already-computed pieces, flowing backward through the layers, is the entire efficiency trick behind backpropagation (and is exactly what the "MLP Memoization" topic in the next chapter is about).

Step 5 — Update the Weights

$$ w_o^{new} = 0.5 - (0.1)(-0.1291) \approx 0.5129 $$ $$ w_1^{new} = 0.3 - (0.1)(-0.0275) \approx 0.3027 $$

Both gradients were negative, so both weights moved slightly up — which makes sense: the prediction (0.5467) was too low relative to the target (1), so gradient descent nudges the weights in whatever direction increases ŷ, which in turn shrinks the loss. Every other weight and both biases would update the same way, in parallel, using their own chain-rule paths back through the network. Repeat this whole cycle — forward pass, loss, backward pass, update — for every row, for many epochs, and the average loss steadily falls. That full repeated cycle is backpropagation.

Day 14

Backpropagation — The Why

When a function depends on just one parameter, its rate of change is called a derivative, written \( d/dx \). When a function depends on several parameters at once, the individual per-parameter rates of change are called partial derivatives, and the collection of all of them together is called the gradient — written \( \partial z/\partial x \), \( \partial z/\partial y \), and so on for every parameter z depends on.

A neural network's loss function is exactly this multi-parameter case, stacked several layers deep: the loss depends on \( \hat{y} \), which depends on \( z \) (the neuron's pre-activation), which depends on the activation output of the previous layer, which in turn depends on that layer's own weights. Because the loss is a function of many weights and biases chained through many intermediate steps, computing "how does the loss change if I nudge this one weight" always means taking a partial derivative and applying the chain rule through every intermediate step in between — exactly what the worked example above did explicitly for w₁ and wₒ.

This is also why the algorithm is called backpropagation and not "the derivative algorithm": a single derivative would suffice for one parameter, but a deep network's loss is a nested function of hundreds, thousands, or billions of weights, so the error signal has to be propagated backward, layer by layer, computing the gradient with respect to every one of them.

Day 14

Epochs, Iterations, Batch Size & Convergence

The training loop from the algorithm above raises a natural question: how many times does the weight actually get updated? That depends on three related but distinct ideas.

FeatureEpochIteration
DefinitionOne full pass through the entire training dataset.One weight-update step, using one batch of data.
ScopeThe outer loop of training.The inner loop of training.
Weight updatesHappens multiple times per epoch.Happens exactly once per iteration.
Impact of countToo many epochs can lead to overfitting.More iterations directly increase training time.

Concrete Example

A dataset has 1,000 images, and the batch size is set to 200.

  • 1 batch = 200 images.
  • 1 iteration = the model processes 1 batch (200 images) and updates its weights once.
  • 1 epoch = the model must see all 1,000 images, which takes 1,000 ÷ 200 = 5 iterations.

Training for 10 epochs at this batch size therefore runs a total of 10 × 5 = 50 iterations, i.e. 50 separate weight-update steps.

The Role of Batch Size

Batch size is the dial that determines how many iterations make up one epoch, and it defines the three flavors of gradient descent:

  • Batch Gradient Descent: batch size equals the entire dataset — 1 iteration = 1 epoch. Every weight update uses the full dataset's gradient, which is stable but slow and memory-heavy.
  • Stochastic Gradient Descent (SGD): batch size = 1 — one iteration per individual row, so as many iterations per epoch as there are rows. Noisy updates, but very fast per step and can escape shallow local minima.
  • Mini-batch Gradient Descent: the dataset is split into reasonably sized blocks (e.g. 32, 64, 128 rows), giving multiple iterations per epoch. This is the practical middle ground used almost everywhere in real training.
Convergence is the point where the model stops meaningfully learning because it has found weights that minimize the loss function well — a stable local or global minimum. Early in training, error drops quickly; as training continues, the drop flattens out. Once the change in loss between epochs becomes tiny or zero, the model has converged.

Test Your Understanding

Hard

5 questions on Backpropagation. Pick an answer for each, then check.

1. What does ∂L/∂w actually measure in gradient descent?

Explanation: The source emphasizes this repeatedly — the derivative in gradient descent measures how the loss changes for a small change in the weight, not how the prediction changes. Gradient descent uses that information to move the weight in the loss-reducing direction.

2. In the worked example, ∂L/∂w₁ required reusing ∂L/∂zₒ, which had already been computed while finding ∂L/∂wₒ. What does this illustrate?

Explanation: This reuse of intermediate gradient terms while propagating error backward is the core efficiency mechanism of backpropagation — it's also exactly the idea behind caching forward-pass activations, covered as "MLP Memoization" in the next chapter.

3. A dataset has 2,000 rows and batch size is set to 500. How many iterations make up one epoch, and how many total iterations occur over 8 epochs?

Explanation: 2000 ÷ 500 = 4 iterations per epoch (matching the 1000-image/200-batch example's logic: total rows ÷ batch size). Over 8 epochs: 8 × 4 = 32 total iterations.

4. Which gradient descent variant makes exactly one weight update using the entire dataset per iteration?

Explanation: When batch size equals the full dataset size, 1 iteration processes the whole dataset and updates weights once — so 1 iteration = 1 epoch. That's the definition of Batch Gradient Descent.

5. A model's average epoch loss goes 0.80 → 0.42 → 0.19 → 0.18 → 0.179 → 0.1789 over six epochs. What does this pattern indicate?

Explanation: Fast initial error drop followed by flattening, where epoch-to-epoch change becomes tiny, is precisely the definition of convergence given in this chapter — the model has settled near a minimum of the loss.
