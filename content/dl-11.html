CNN Intuition & Layer Types

A Convolutional Neural Network (CNN) is a family of architectures purpose-built for data that has a known grid-like topology — data where the position of a value relative to its neighbors carries meaning. Time series data is a 1D grid: each reading sits next to the readings immediately before and after it in time. An image is a 2D grid: each pixel sits next to the pixels immediately above, below, and beside it in space. In both cases, "closeness" in the grid is informative — two adjacent pixels are far more likely to belong to the same object or edge than two pixels chosen at random from opposite corners of the picture. A plain, fully-connected network throws that structure away by treating every input value as independent and interchangeable; a CNN is built specifically to exploit it.

A CNN is composed of three fundamental building blocks, typically stacked and repeated:

Convolutional Layer

Slides small learnable filters over the input to detect local patterns, producing "feature maps." This is where the actual pattern-detection happens.

Pooling Layer

Down-samples feature maps — shrinking them while keeping the strongest signals — to cut memory cost and make detected features more location-independent.

Fully Connected (Dense) Layer

Comes at the end, after the grid has been flattened into a vector, and does the final job of combining the extracted features into a prediction — exactly like a normal ANN layer.

A picture, for the purposes of this discussion, is simply a 2D grid of intensity values — and the whole point of the sections below is to explain exactly how a CNN processes that grid, step by step, from raw pixels to a final prediction.

Why Not Just Use a Plain ANN on Images?

Technically, nothing stops you from feeding an image into an ordinary ANN — flatten the 2D grid of pixels into a single long 1D vector and feed it to a dense network, the same way it's done for a dataset like MNIST. It works, but it works badly, for three concrete, compounding reasons.

1. Explosive parameter count

Take a modest 40×40 grayscale image. Flattened, that's 40 × 40 = 1,600 input values. Now connect that flattened input to a single, fairly small hidden layer of just 100 units, fully connected — every one of the 1,600 inputs wired to every one of the 100 hidden neurons. That's:

$$ 1{,}600 \times 100 = 160{,}000 \text{ weights} $$

…for one hidden layer, on one small, low-resolution, black-and-white image. Real images are typically far larger and have 3 color channels, and real networks need many hidden layers — the parameter count for a fully-connected approach explodes combinatorially, driving up training time, memory footprint, and compute cost far beyond what's practical.

2. Overfitting — connecting every single pixel directly to every hidden neuron gives the network the freedom to memorize minute, idiosyncratic details of each training image (a stray pixel value, noise, a specific lighting quirk) rather than learning generalizable patterns. With that many free parameters relative to the structure being learned, the network has more than enough capacity to memorize the training set instead of understanding it — the textbook overfitting failure mode.
3. Loss of spatial arrangement — flattening a 2D grid into a 1D vector destroys the information about which pixels were near which other pixels. A pixel that was directly above another pixel and a pixel that was on the opposite side of the image become equally "close" once everything is squashed into one long list. But an image's meaning lives almost entirely in that spatial arrangement — an edge is a set of adjacent pixels with a sharp intensity change; an eye is a specific local arrangement of pixels. Throwing away adjacency information throws away the very structure the network needs to recognize.

The fix

A CNN never flattens the image up front. It keeps the 2D grid intact and instead scans small, shared filters across it — a design choice that directly attacks all three problems: far fewer parameters (a filter is reused across the whole image instead of getting a unique weight per pixel), less overfitting, and full preservation of local spatial structure.

From Edges to Objects: Why CNNs Go Deep

The earliest convolutional layer in a CNN — the one closest to the raw input — learns to detect the most primitive visual features that exist: edges, which are really just sharp changes in pixel intensity (a light region butting up against a dark region, for instance). As the data moves deeper into the network, each subsequent convolutional layer operates not on raw pixels but on the feature maps produced by the layer before it — so it isn't looking for edges anymore, it's looking for small, meaningful combinations of edges. A few edges arranged just so might form a curve; a few curves arranged just so might form a circle or a corner; further in, those shapes combine into parts of objects — an eye, a wheel, a leaf — and eventually into whole recognizable objects. This is the core intuition behind depth in a CNN: each layer builds increasingly complex, increasingly composite features out of the simpler features the previous layer already found, culminating in a rich, hierarchical representation of "what's in the image" by the time the signal reaches the final layers.

Popular CNN architectures. This edges-to-objects idea is the backbone of every well-known CNN design — they mainly differ in how deep they go, how they're wired, and what tricks they use to train reliably at that depth. The Convolution Operation

What is an image, to a CNN?

Strip away everything else, and an image is just a grid of pixels — a collection of numbers arranged in rows and columns, stored as an array. What differs is how many such 2D grids ("channels") stack together to represent color:

Grayscale (black & white) — a single channel: one 2D array, where each entry is a pixel's intensity, typically ranging 0 (black) to 255 (white).
Color — three channels: Red, Green, and Blue. Each channel is itself a grayscale-like 2D array of values from 0–255, and the three are stacked together — the final pixel color is a mix of how much red, green, and blue are present at that position. A color image of 228×228 pixels is therefore stored as 228 × 228 × 3 — width × height × channels.

The filter / kernel

To perform convolution, a CNN needs a filter (also called a kernel) — typically a small matrix, commonly 3×3. Where do the numbers inside that filter come from? Exactly the same place weights in a plain ANN come from: the filter's values are initialized randomly, and then updated during training via backpropagation, the loss gradient nudging each value toward whatever minimizes the network's error. A filter is not hand-designed by an engineer to look for "horizontal lines" or "vertical lines" specifically — it behaves precisely like the weight matrix of a normal ANN layer, except it's shared and reused across every spatial position of the image instead of being wired to just one input.

How convolution actually works

The filter is placed over a small window of the image — the same size as the filter itself — and the operation is:

  1. Element-wise multiply every value in the filter with the pixel value directly underneath it.
  2. Sum all of those products into a single number.
  3. That single number becomes one entry in the output — called the feature map.
  4. Slide the filter to the next window (one pixel over, by default) and repeat, until the filter has swept over the entire image.

This sliding, multiply-and-sum process is exactly what "convolving a filter onto the image" means.

A worked numeric example

Take a small 5×5 grayscale image patch and a 3×3 filter that has already been trained to respond to a horizontal intensity change:

Image window (top-left 3×3 of the 5×5 patch)
3  0  1
1  5  8
2  7  2
Filter (3×3)
1  0 -1
1  0 -1
1  0 -1

Element-wise multiply, position by position: (3×1)+(0×0)+(1×-1) + (1×1)+(5×0)+(8×-1) + (2×1)+(7×0)+(2×-1). Working through it: 3 + 0 − 1 + 1 + 0 − 8 + 2 + 0 − 2 = −5. That single value, −5, becomes one entry in the output feature map. The filter then slides one column to the right, repeats the same multiply-and-sum against the next 3×3 window, and produces the next feature-map entry — and so on until the whole image has been covered.

Feature map size formula

For an n×n image and an m×m filter, the resulting feature map size is:

$$ (n - m + 1) \times (n - m + 1) $$

This checks out against two concrete examples: a 6×6 image with a 3×3 filter gives 6 − 3 + 1 = 4, i.e. a 4×4 feature map. A 28×28 image with a 3×3 filter gives 28 − 3 + 1 = 26, i.e. a 26×26 feature map. Notice the feature map is always smaller than the input — a consequence revisited in the next page under Padding.

Extending to multi-channel (colored) images

A color image isn't a single 2D grid — it's 3 stacked grids (R, G, B). So the filter must also gain a matching depth: for a 6×6×3 image, the filter becomes 3×3×3 — one 3×3 slice of the filter for each of the 3 input channels. The convolution still happens the same way (element-wise multiply and sum), just across all three channel-slices at once, and the three per-channel sums are added together into one single number — meaning the output of one filter is still just a single 2D feature map, exactly as in the grayscale case, regardless of how many input channels there were:

$$ \text{image } n \times n \times c, \;\; \text{filter } m \times m \times c \;\; \Rightarrow \;\; \text{feature map } (n-m+1) \times (n-m+1) $$

The channel depth c of the filter must always match the channel depth of the input — but it disappears from the output shape, because the per-channel products are summed into one value per spatial position.

Applying multiple filters

In practice a convolutional layer never applies just one filter — it applies many, in parallel, to the same input. Each filter is convolved across the entire image independently and produces its own, separate 2D feature map; with N filters, you get N feature maps, which are then stacked together depth-wise into a single output volume. Conceptually, different filters end up specializing in detecting different kinds of local patterns — some might become sensitive to horizontal edges, others to vertical edges, others to particular color transitions or textures — but it's important to be precise about how that happens: nobody hand-designs "this filter looks for horizontal edges." The filters start as random numbers, and gradient descent shapes each one into whatever pattern-detector actually reduces the network's loss, which very often — but not by design — turns out to resemble classic edge detectors, especially in the earliest layers.

5 questions on CNN fundamentals & the convolution operation. Pick an answer for each, then check.

1. A 50×50 grayscale image is flattened and fed into a dense hidden layer of 200 units. How many weights connect the input to that one hidden layer?

Explanation: Flattened input size = 50×50 = 2,500. Fully connecting to 200 hidden units = 2,500 × 200 = 500,000 weights — the same explosive-parameter-count problem the 40×40→160,000 example illustrates, just scaled up.

2. Why does flattening an image into a 1D vector before feeding it to an ANN specifically hurt the network's ability to recognize objects?

Explanation: An image's meaning lives in which pixels are near which other pixels (edges, shapes). Flattening treats every pixel as an interchangeable, independent input, discarding that 2D neighborhood structure — which is exactly the "loss of spatial arrangement" problem CNNs are designed to avoid.

3. Where do the numeric values inside a convolutional filter come from, and how do they change during training?

Explanation: Filter values are learnable parameters, just like ANN weights — random init, then gradient-based updates via backprop. Any resemblance to a "horizontal edge detector" is an emergent result of loss minimization, not manual design.

4. A 32×32×3 color image is convolved with a single 5×5×3 filter (no padding, stride 1). What is the shape of the resulting output?

Explanation: Feature map size = (n−m+1)×(n−m+1) = (32−5+1) = 28, so 28×28. Even though the filter has depth 3 to match the input's 3 channels, the per-channel products are summed into one value per position — one filter always produces exactly one 2D feature map, regardless of input channel count.

5. A convolutional layer applies 64 different filters to the same input volume. What does the output of that layer look like?

Explanation: Each filter is convolved independently across the full input and produces its own feature map; with N filters you get N feature maps, stacked together into a single output volume of depth N — this is exactly how 228×228 images with 100 filters end up as 226×226×100 in the next page's pooling discussion.
