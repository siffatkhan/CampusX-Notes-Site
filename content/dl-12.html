12. CNN — Padding, Strides & Pooling

Why feature maps shrink · valid vs. same padding · strided convolution · max/min/average/global pooling

Padding

Padding

Plain convolution, as covered on the previous page, shrinks the image every time it's applied — an n×n image with an m×m filter produces an (n−m+1)×(n−m+1) output. Left unaddressed, that shrinkage causes two separate problems.

Problem 1 — progressive information loss

A feature map is already smaller than the image that produced it. Apply a second convolutional layer to that feature map, and it shrinks again — and again with a third layer. Stack several convolutional layers, as any real CNN does, and the spatial dimensions can shrink to almost nothing well before the network is deep enough to have learned useful high-level features, destroying information the network never got the chance to use.

Problem 2 — border pixels are under-used

As a filter slides across an image, a pixel near the center gets caught inside the filter's window many times over the course of the sweep, while a pixel sitting in a corner or along an edge only ever falls inside the window a handful of times. That means center pixels effectively contribute to far more output values than border pixels do — the network implicitly treats the edges of the image as less important, and information sitting near the border gets under-represented or lost.

The fix — padding. Add an extra border of rows and columns (top, bottom, left, and right) around the image before convolving. This border is generally filled with zeros. Padding fixes both problems at once: because the effective input is now larger, the output feature map can be made equal in size to the original (pre-padding) image instead of shrinking — solving problem 1; and because what used to be a border pixel is now surrounded by real neighbors on every side (the padding fills in what used to be "off the edge"), it gets caught inside the sliding filter roughly as often as a center pixel — solving problem 2.

Padded feature map size formula

Let p be the padding amount — how many rows/columns of zeros are added on each side. The formula becomes:

$$ (n + 2p - f + 1) \times (n + 2p - f + 1) $$

Here n is the original image size, f is the filter size, and p appears as 2p because padding is added on both sides of each dimension (e.g. both left and right). Choosing p so that the output size exactly equals the input size n is precisely what "same" padding (below) does.

Keras conventions: "valid" vs. "same"

valid — no padding at all (p = 0). The output shrinks according to the plain (n−m+1) formula. This is the default, "do nothing extra" option.
same — Keras automatically computes and adds just enough zero-padding so that the output feature map has the same width and height as the input. This is the option you reach for whenever you want to stack many convolutional layers without the spatial dimensions collapsing before the network is deep enough to be useful.
Strides

Strides

A stride is how many pixels the filter jumps between successive convolution steps, instead of always moving one pixel at a time. Take a 7×7 image and a 3×3 filter. With stride 1 — the default assumed everywhere on the previous page — the filter shifts one pixel right at a time across a row, and one pixel down when it wraps to the next row; this is written as stride (1,1). With stride 2, the filter instead jumps two pixels to the right each step, and two pixels down when moving to the next row — stride (2,2). Whenever the stride is greater than 1, the operation is called a strided convolution.

Stride alone
$$ \left\lfloor \frac{n - f}{s} \right\rfloor + 1 $$
Stride + padding combined
$$ \left\lfloor \frac{n + 2p - f}{s} \right\rfloor + 1 $$

Increasing the stride shrinks the feature map faster than stride 1 does — which means it's entirely possible for (n + 2p − f) / s to come out as a decimal (say, 4.5) rather than a whole number. When that happens, the sliding window simply runs out of room to fit one more full step, so the result is floored down to the nearest whole number — the network just discards that leftover fractional slice of the image on that pass, rather than trying to convolve a partial window.

Why use a stride greater than 1?

  • You want higher-level features, not low-level detail. Skipping pixels forces the filter to summarize more of the image per step, coarsening what it captures — useful when fine-grained low-level information isn't needed.
  • Speed. A larger stride means fewer positions to compute per layer, which directly reduces computation and makes training faster.

In practice, though, stride is a relatively minor tool in modern architecture design — it's used far less often than pooling (below) for down-sampling, since pooling generally achieves the same shrinkage more deliberately and with useful side-effects of its own.

Pooling

Pooling

Pooling is a technique for down-sampling a feature map — deliberately shrinking it while trying to retain its most important signal. It exists to solve two problems that plain convolution (even with strides) doesn't fully address.

Problem 1 — memory

A 228×228 image is a common input size in serious CNN architectures. Convolve it with 100 filters (no padding, stride 1, 3×3 filters) and each filter produces a 226×226 feature map — 100 of them stacked gives a 226×226×100 output volume. That's an enormous amount of data to hold in memory for just one convolutional layer, and real networks stack many such layers. Something has to shrink that volume down, or memory usage spirals out of control. Stride can help reduce this, but pooling is generally the better tool.

Problem 2 — translation variance

Convolution is inherently location-dependent — it detects a feature at whatever specific position that feature happens to appear in the image, and the resulting activation shows up at that same position in the feature map. For a task like classification, that's usually the opposite of what you want: "is there a cat in this picture" should have the same answer whether the cat is in the top-left corner or dead center. Pooling makes the learned features more location-independent by summarizing a whole neighborhood into one value, so a small shift in the input has little to no effect on the pooled output.

How pooling works

Pooling typically operates on a feature map after a non-linearity like ReLU has already been applied to it. To run pooling, you specify three things — exactly like specifying a convolution: window size (the region it looks at, e.g. 2×2), stride (how far the window moves each step), and pooling type. The window then slides across the feature map exactly like a mini-convolution — except instead of a weighted multiply-and-sum against a learned filter, it takes a simple, parameter-free aggregate (a max, a min, an average) of whatever values fall inside the window at each step.

The four pooling types

Max pooling — picks the largest (most dominant/strongest) activation in each window, eliminating weaker, low-level details and keeping only the loudest signal. This is by far the most commonly used pooling type in practice.
Min pooling — picks the smallest value in each window. Used far less often than max pooling, since the largest activation is usually the more informative signal for detecting "is this feature present."
Average pooling — takes the mean of all values in the window, producing a smoother summary rather than picking out one extreme value.
Global pooling — the extreme case: the window covers the entire feature map at once, collapsing it down to a single scalar value. Global max pooling returns the single largest value anywhere in the feature map; global average pooling returns the mean of every value in it. Global pooling is often used right before a classifier head, replacing a Flatten layer.

Advantages & disadvantages of pooling

Advantages
  • Reduces feature map size, directly cutting memory and compute cost
  • Introduces translation invariance — small shifts in the input barely change the pooled output
  • Max pooling specifically enhances the strongest features by discarding weaker surrounding activations
  • No parameters to learn — pooling is a fixed, deterministic operation, adding zero extra weights to train
Disadvantages

Pooling is a lossy operation — collapsing a whole window down to one number (a max, a min, an average) necessarily throws away everything else that was in that window. Some information is unavoidably lost every time pooling is applied, which is part of why some modern architectures (like ResNet-style designs) use it more sparingly, leaning more on strided convolutions or global pooling near the very end of the network instead of scattering pooling layers throughout.

Test Your Understanding

Hard

5 questions on padding, strides & pooling. Pick an answer for each, then check.

1. Padding an image with a border of zeros before convolving addresses which two problems at once?

Explanation: Padding keeps the feature map from shrinking layer after layer, and gives border pixels more neighbors to be caught inside the sliding filter's window — addressing both the shrinkage problem and the "center pixels matter more" problem. Memory and translation variance are what pooling addresses instead.

2. You want a convolutional layer's output to have exactly the same width and height as its input. Which Keras padding setting achieves this, and roughly how?

Explanation: "valid" means no padding (output shrinks); "same" pads with zeros just enough to make the output spatial size match the input. "valid" is the one that shrinks; "same" is the one that preserves size.

3. A 9×9 image is convolved with a 3×3 filter, no padding, stride 2. Using ⌊(n−f)/s⌋+1, what is the output size?

Explanation: (9−3)/2 + 1 = 6/2 + 1 = 3 + 1 = 4, giving a 4×4 feature map — a clean integer in this case, but the same formula is exactly where a decimal result would need to be floored down.

4. A 228×228 image convolved with 100 filters (3×3, valid padding, stride 1) produces a 226×226×100 output volume. Why is this specifically a problem pooling is meant to solve?

Explanation: This is precisely the "memory issue" pooling addresses — a 226×226×100 volume is a lot of numbers to store for one layer, and stacking more convolutional layers on top compounds the problem further unless something down-samples the feature maps.

5. What makes max pooling, specifically, "translation invariant" in a way that helps classification tasks?

Explanation: Because max pooling only reports the single largest value in a window, small shifts of the underlying feature within that window don't change the output — the window's max is robust to exactly where inside it the peak activation sits, which is what gives pooled features their location-independence.
