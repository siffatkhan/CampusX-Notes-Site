Day 7

Challenges in Machine Learning (ML)

# Challenge Detail
1Data CollectionSources: APIs, web scraping, databases. Challenge: collecting relevant and sufficient data.
2Insufficient / Labelled DataML models need enough examples to learn patterns. Labelled data is required for supervised learning.
3Unreasonable Effectiveness of DataWith huge datasets, even simple algorithms perform well. Quality matters less than quantity in some cases.
4Non-Representative DataData may not reflect the real-world scenario. Leads to sampling noise (random errors) and sampling bias (systematic errors).
5Poor Quality DataMissing values, duplicates, inconsistent data. Cleaning can take more time than model training.
6Irrelevant Features"Garbage in, garbage out." Feature engineering: create meaningful features, remove irrelevant ones.
7OverfittingModel memorizes training data but fails on new data. Solution: regularization, more data, cross-validation.
8UnderfittingModel too simple, fails to capture patterns. Solution: more complex model, better features.
9Software IntegrationML models must integrate with existing systems, APIs, or apps.
10Offline Learning / DeploymentSome ML models cannot update in real-time; need batch updates.
11Cost InvolvedComputational resources, storage, maintenance. MLOps: automates deployment, monitoring, scaling, retraining.

Day 9

ML Development Life Cycle (ML DLC)

  1. 1. Problem Framing

    Define clear ML objectives and scope.

  2. 2. Data Collection

    APIs, web scraping, databases, data warehouses.

  3. 3. Data Pre-processing

    Cleaning, integration, transformation, reduction.

  4. 4. Exploratory Data Analysis (EDA)

    Study input-output relationships. Uni-variate, bi-variate, multi-variate analysis. Detect outliers, handle imbalanced datasets.

  5. 5. Feature Engineering & Selection

    Features = input columns. Create new features by combining columns. Select most important features.

  6. 6. Model Training, Evaluation & Selection

    Try multiple algorithms. Evaluate using metrics (accuracy, precision, recall). Hyperparameter tuning to improve performance. Ensemble learning: combine multiple models for better results.

  7. 7. Model Deployment

    Deploy on servers (Heroku, AWS, etc.).

  8. 8. Testing

    A/B testing to compare model versions.

  9. 9. Optimization & Maintenance

    Model & data backups, automation, load balancing. Retraining to prevent model decay.

Day 10

Data-Related Job Roles

1. Data Engineer

Collect and prepare data, build pipelines.

Skills: databases, ETL, backend systems.

2. Data Analyst

Summarize and visualize data, support decisions.

Skills: SQL, Excel, visualization tools.

3. Data Scientist

Combines engineering + statistics + ML modeling. Full-stack data professional.

4. ML Engineer

Deploy ML models to production. Focus on scaling, optimization, reliability.

5. MLOps Engineer

Automate ML lifecycle: deployment, monitoring, retraining.

  • ML Engineer / MLOps Engineer — highest earning potential, strong demand, future-proof.
  • Data Scientist — very high salary, versatile, stable demand.

Test Your Understanding

Hard

5 questions on Day 7–10. Pick an answer for each, then check.

1. A model scores 99% training accuracy but only 60% test accuracy. A colleague also mentions that on a survey collected only from one city, the model performs poorly nationwide. Which two challenges from the notes are illustrated respectively?

Explanation: A huge gap between training and test accuracy is the definition of overfitting (model memorizes training data but fails on new data). Data from only one city that doesn't reflect the full population is a case of sampling bias under non-representative data.

2. Where does Feature Engineering & Selection sit in the ML Development Life Cycle relative to EDA and Model Training?

Explanation: The ML DLC order is: Problem Framing → Data Collection → Data Pre-processing → EDA → Feature Engineering & Selection → Model Training, Evaluation & Selection → Deployment → Testing → Optimization & Maintenance.

3. A startup needs someone who can automate deployment, monitoring, scaling, and retraining of ML models in production. Which role from Day 10 fits best, and which Day 7 challenge does that role primarily address?

Explanation: The MLOps Engineer role is defined exactly as automating the ML lifecycle (deployment, monitoring, retraining), which directly addresses the "Cost Involved" (MLOps automates deployment/monitoring/scaling/retraining) and "Offline Learning / Deployment" challenges from Day 7.

4. A BI team wants complex historical analytics across five years of aggregated sales, not day-to-day transactional lookups. Per Day 10's comparison, what should they query?

Explanation: Data warehouses store historical, aggregated data and are built for complex analytics used by data analysts/BI teams — exactly this use case. Databases are optimized for frequent, simple, current/transactional queries by application developers.

5. "With huge datasets, even simple algorithms perform well; quality matters less than quantity in some cases." Which Day 7 challenge/observation does this describe, and how does it relate to challenge #2?

Explanation: This is challenge #3, "Unreasonable Effectiveness of Data." It sits in tension with #2 (models need enough labeled examples): #2 says insufficient data is a blocker, while #3 says once you have huge volumes, even simple algorithms can do well — scale of data can offset algorithmic sophistication, but you still need the data to exist in the first place.
