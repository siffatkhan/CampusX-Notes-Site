9. Encoding Categorical Vars

Ordinal / Label Encoding · One Hot Encoding

Day 26

Encoding Categorical Variables: Ordinal / Label Encoding

Categorical data is part of feature transformation. It holds values as strings, and you must convert it into numbers before feeding it to an ML model. Categorical data comes in two main types: nominal and ordinal. The correct encoding method depends on this distinction.

Nominal Categorical Data

Has categories with no natural order or relationship between them. The categories are independent of each other.

Examples: Color → Red, Blue, Green · City → Lahore, Karachi, Islamabad

Saying one category is greater or smaller than another has no meaning here. Do not use ordinal or label based numbering on this kind of data. It introduces false relationships.

Ordinal Categorical Data

Has categories with a meaningful order or ranking. The order carries information, so your encoding must preserve it.

Examples: Grades → A, B, C · Reviews → Good, Average, Bad · Education → High School, Bachelor, Master

Ordinal Encoding

Use this for ordinal categorical input features. You assign each category a numerical value based on its rank or order.

Example: Bad → 0, Average → 1, Good → 2

from sklearn.preprocessing import OrdinalEncoder
oe = OrdinalEncoder(categories=[["Bad", "Average", "Good"]])

Important: define the order correctly. A wrong order misleads the model.

Label Encoding

Similar to ordinal encoding, but you mainly use it for output labels, not input features. It converts class labels into numeric form.

Example: Spam → 1, Not Spam → 0

from sklearn.preprocessing import LabelEncoder
le = LabelEncoder()
y_encoded = le.fit_transform(y)

Ordinal Encoding vs Label Encoding

Use Ordinal Encoding for input features with a known order. Use Label Encoding for output labels or target variables. Using label encoding on nominal input features is a common mistake, since it introduces false ordering.

Day 27

Encoding Categorical Variables: One Hot Encoding

Use One Hot Encoding to handle nominal categorical data, where categories have no natural order. It converts each category into a separate binary column, forming a vector representation of the original feature. This is the most common encoding technique in machine learning. ML algorithms work with numerical data, not strings. OHE avoids assigning artificial order to categories, which would mislead a model.

Example: a Color column with values Red, Blue, Green becomes three columns: Color_Red, Color_Blue, Color_Green. Each row gets a 1 for its category and 0 for the others. As the number of categories grows, the number of generated columns grows too.

You turned a string column into a vector.

High Cardinality Issue

When a feature has many unique categories, OHE creates too many columns. This increases memory usage, training time, and the risk of overfitting. This is known as the curse of dimensionality.

In ML, a common guideline says input columns should not relate to each other or depend on one another.

Dummy Variable Trap and Multicollinearity

The dummy variable trap occurs when you use all one hot encoded columns together. Since the sum of all dummy columns equals 1, one column becomes redundant and creates perfect multicollinearity.

Solution: drop one dummy column. You lose no information, because rows with all zeros implicitly represent the dropped category.

Example: if Red, Blue, Green exist, drop Green. All zeros → Green.

Handling Most Frequent Categories

When a feature has many categories, keep only the most frequent ones and group the rest into a single category called "Other". This reduces dimensionality and noise.

Effect on model: rare categories often carry little predictive power. Grouping them improves generalization. You lose some fine detail, but overall model stability improves.

from sklearn.preprocessing import OneHotEncoder
ohe = OneHotEncoder(handle_unknown="ignore", drop="first")

This converts categories into binary vectors, drops one column to avoid multicollinearity, and ignores unseen categories during testing.

5 questions on Day 26–27. Pick an answer for each, then check.

1. A junior data scientist applies LabelEncoder to a nominal "City" input feature (Lahore=0, Karachi=1, Islamabad=2). What is the core problem?

Explanation: Using label encoding on nominal input features is a common mistake. It introduces false ordering. Cities have no inherent rank, so 0 < 1 < 2 falsely tells the model that Islamabad > Karachi > Lahore.

2. You one-hot encode a "Color" column (Red, Blue, Green) into 3 columns and feed all 3 into a Linear Regression alongside an intercept term. What problem does this create?

Explanation: The dummy variable trap occurs when you use all one-hot encoded columns together. Since the sum of all dummy columns equals 1, one column becomes redundant and creates perfect multicollinearity. Fix: drop one column (e.g. drop="first").

3. After dropping the "Green" dummy column (keeping only Color_Red and Color_Blue), a row has Color_Red=0 and Color_Blue=0. What does this row's actual color have to be?

Explanation: No information is lost here. Rows with all zeros implicitly represent the dropped category. If Red, Blue, Green exist and you drop Green, all zeros means Green. You can fully recover the dropped category from an all-zero row.

4. A "Country" column has 180 unique values. Which consequence does one-hot encoding it directly risk?

Explanation: When a feature has many unique categories, OHE creates too many columns. This increases memory use, training time, and the risk of overfitting. This is the curse of dimensionality. The fix is grouping rare categories into "Other".

5. At test time, OneHotEncoder(handle_unknown="ignore") encounters a category it never saw during fit. What happens?

Explanation: OneHotEncoder(handle_unknown="ignore", drop="first") ignores unseen categories during testing. An unseen category produces zeros in all of that feature's dummy columns instead of raising an error.
