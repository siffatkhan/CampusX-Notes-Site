Earlier topics (Days 24–44) were feature transformation. Today's focus is construction and splitting.

Feature Construction

Create new features from existing features using logic and domain knowledge. No fixed formula — it depends on your understanding of the data and the problem.

Example — Titanic dataset: columns SibSp (number of siblings or spouses) and Parch (number of parents or children).

New feature: family_size = SibSp + Parch + 1 (add 1 to include the passenger). 
X['family_size'] = X['SibSp'] + X['Parch'] + 1

Why useful: single passengers behave differently from large families; the model captures group behavior better; it reduces noise from separate small columns.

Feature Splitting

Break one feature into multiple meaningful parts. Used when a column contains combined information. Feature splitting extracts hidden structured information from raw text columns.

Example — Titanic dataset: column df['Name']. A Name contains a Title, a First name, and a Last name.

Extracting the title: use a split operation to separate the string by comma and period.

Goal: create a new column such as Mr, Miss, Mrs, Dr.

Test Your Understanding

Hard

5 questions on Day 45. Pick an answer for each, then check.

1. A Titanic row has SibSp = 2 and Parch = 1. What is the constructed family_size feature?

Explanation: family_size = SibSp + Parch + 1 = 2 + 1 + 1 = 4. The +1 accounts for the passenger themself, not just their relatives.

2. You take the "Name" column ("Braund, Mr. Owen Harris") and extract "Mr" into a new Title column. Which category of feature engineering is this?

Explanation: Breaking one column that contains combined information (Name → Title + First + Last) into meaningful parts is exactly the definition of Feature Splitting, which the notes classify under Feature Construction — distinct from transformation (scaling/encoding/missing/outliers), selection, or PCA-style extraction.

3. Which of these is NOT classified under "Feature Transformation" per the notes' taxonomy?

Explanation: The notes list Feature Transformation as: missing value handling, categorical encoding, outlier handling, feature scaling. Feature splitting is listed separately, under Feature Construction.

4. Why is family_size potentially more useful to a model than keeping SibSp and Parch as two separate raw columns?

Explanation: Per the notes: "Single passengers behave differently from large families, model captures group behavior better, reduces noise from separate small columns." This is a domain-knowledge-driven construction, not a mathematical requirement, and has nothing to do with encoding or outliers.

5. Feature Construction is described as having "no fixed formula." What does this imply about how you should approach it?

Explanation: The notes say directly: "Create new features from existing features using logic and domain knowledge. No fixed formula. Depends on understanding of data and problem." This is unrelated to whether scaling or PCA has been applied.
