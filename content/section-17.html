Why more features aren't always better · Sparsity · Dimensionality Reduction

Day 46

Curse of Dimensionality

Note on Feature Selection: We cover this in detail later, after algorithms. You use it after building a model, to check whether adding or removing a feature changes the model.

Dimension means the number of features. Adding features improves a model only when they add useful information. Past a certain point, performance stops improving, or it drops. The reason: noise increases, not signal.

In image classification, only the pixels covering the object matter. Extra background pixels add complexity, not accuracy. More features do not mean more knowledge.

Where the Curse Appears

The curse of dimensionality shows up in high-dimensional data: images (many pixels), text data (many words), genomics (many genes).

The core problem is sparsity among columns. In high dimensions, most values are zero.

Example: 10,000 word features. Each document uses 100 words. 9,900 features are zero.

Because of this, data points end up far apart, and finding patterns gets hard.

Problems Caused

  • Sparsity increases
  • Distance measures lose meaning
  • Overfitting risk increases
  • Computation cost increases and training time increases
  • Storage increases and performance drops

Solution: Dimensionality Reduction

Reduce features while keeping important information. Two methods:

A. Feature Selection

Select important original features. Original features remain unchanged.

  • Forward Selection: start empty, add useful features
  • Backward Elimination: start full, remove useless features

B. Feature Extraction

Create new reduced features from old ones. Transform data into a lower dimension.

PCAMaximizes variance
LDAMaximizes class separation
t-SNEVisualizes data in 2D or 3D

1. A text classifier uses 10,000 word features, but a typical document only contains 100 distinct words. What core problem does this illustrate?

Explanation: This matches the worked example of sparsity given earlier: "10,000 word features. Each document uses 100 words. 9,900 features are zero." The problem in high dimensions is that most values are zero, not missingness, imbalance, or correlation between features.

2. You keep adding more features to a model and accuracy improves at first, then plateaus, then starts to decrease. What is the notes' explanation for the decrease?

Explanation: Per the notes: "Adding features improves model only if they add useful information. After a limit, performance stops improving or decreases. Reason: noise increases, not signal." The other options are unrelated concepts from other sections.

3. You want to reduce dimensionality but a domain expert insists the model must remain fully interpretable in terms of the original named columns (e.g. "salary," "age"). Which family of technique satisfies this constraint?

Explanation: Feature Selection keeps "important original features... original features remain unchanged," preserving interpretability. Feature Extraction techniques (PCA, LDA, t-SNE) instead create new transformed features that are combinations of the originals, sacrificing direct interpretability.

4. Which technique is specifically described as maximizing class separation, rather than maximizing overall variance?

Explanation: The notes list: "PCA: Maximizes variance, LDA: Maximizes class separation, t-SNE: Used for 2D or 3D visualization." LDA is the one tied to class separation.

5. In an image classification task, why do extra background pixels typically hurt rather than help accuracy?

Explanation: The notes state directly: "In image classification, only the pixels covering the object matter. Extra background pixels add complexity, not accuracy. More features do not mean more knowledge." This is the running theme of the curse of dimensionality: irrelevant dimensions add noise, not signal.
