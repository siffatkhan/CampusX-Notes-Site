Simple Linear Regression

Simple Linear Regression is a supervised regression algorithm. It is easy to understand and foundational — most advanced regression algorithms build on it.

What is "linear data"?

  • When input increases, output changes at a constant rate.
  • The relationship looks like a straight line (or a flat hyperplane in higher dimensions).
  • Linear data exhibits a directly proportional relationship — a constant change in an input variable produces a constant change in the output variable.

Example: if 1 year of experience adds 10k salary, then 2 years adds 20k. That is linear behavior. Real data is never perfect, so points scatter around a line rather than sitting exactly on it. Goal: find the best-fit line that passes as closely as possible through all points.

What the model does

  • Looks at all points
  • Tries many candidate lines
  • Picks the line closest to all points — the best fit line

Types of Linear Regression

  • Simple → one input (experience → salary)
  • Multiple → many inputs (experience, CGPA → salary)
  • Polynomial → curved relationship
  • Regularization → prevents overfitting

Equation of a Line

$$ y = mx + b $$

m → slope, b → intercept. m and b are parameters; x is the input.

Understanding slope (m) — slope tells how much output changes when input changes; it is the weightage of x over y. Example: m = 10 → x = 1 gives y +10; x = 2 gives y +20. Higher slope → stronger effect of x on y. Lower slope → weaker effect.
Understanding intercept (b) — intercept is the value of y when x = 0. Example: b = 5000. Even with 0 years experience, predicted salary = 5000. This is the base value of the line.

Common Misconceptions About Linear Regression (Q&A)

1. What is Linear Regression? A supervised ML algorithm that predicts a continuous numerical value — e.g. House Size (X) → House Price (Y). The goal is to learn the relationship between input features and output.

2. Does Linear Regression draw one line or many?

❌ Misconception: one line for every training example. ✅ Correct: it learns only one best-fit line (or one hyperplane with multiple features).

The algorithm finds one line that best fits all points — it does not draw a separate line per house.

3. What does the model learn? An equation. For one feature: \( \hat{y} = mx + b \), where x = input feature, ŷ = predicted value, m = slope (weight), b = intercept (bias). Example: ŷ = 0.2x. This equation is the trained model.

4. What happens during prediction? Learned equation ŷ = 0.2x. New house, size = 1700 → ŷ = 0.2 × 1700 = 340. The model simply substitutes the input into the equation — no retraining, no new line.

5. Where does the predicted value lie? Every predicted value lies on the regression line. Model ŷ = 0.2x, input 1700 → prediction 340. The point (1700, 340) sits on the line.

6. Where does the actual value lie? Suppose the real price is 360. The actual value is not required to be on the line — only the prediction lies on the line.

7. What is error? Error is computed per individual data point. Formula: Error = Actual − Predicted. Example: Actual 360, Prediction 340 → Error = 20. Every sample has its own error.

8. Why don't we add errors directly? Errors 50, −50, 20 add up to 20 — this looks small even though the model made two huge mistakes, because positive and negative errors cancel out. That's why we square them instead: 50² = 2500, (−50)² = 2500, 20² = 400 — now every error is positive.

The Cost Function

Most important concept: the cost function is not calculated for one sample — it is calculated over all training samples (or a batch). A large cost means the line fits the training data poorly; a small cost means it fits well. Gradient descent's only job is to keep changing m and b until this cost becomes as small as possible. The meaning of the cost matters more than its exact value — a cost of 100 alone doesn't tell you whether the model is good; you interpret it by comparing to previous iterations or to other models on the same problem.

How Linear Regression Learns — Step by Step

  1. Step 1: Start with a random line. Example ŷ = 0.1x.
  2. Step 2: Predict every training sample (e.g. actual 200/300/400 → predicted 180/260/380).
  3. Step 3: Calculate every error (20, 40, 20).
  4. Step 4: Square every error (400, 1600, 400).
  5. Step 5: Calculate one cost value from those squared errors.
  6. Step 6: Gradient Descent changes slope and intercept to reduce the cost.
  7. Step 7: Repeat thousands of times until the cost becomes very small. Final equation ŷ = 0.2x — training is finished.

What Happens During Testing?

The line is already learned — nothing changes. Test house, size = 1700 → prediction 340. Suppose actual price is 360 → error 20. Repeat for every test sample, then compute MSE, RMSE, MAE, R². These metrics measure how good the trained model is on unseen data. The model is not updated using the test set.

Final Summary — The 6 Sentences to Remember

  1. Linear regression learns one best-fit line from the training data.
  2. Every prediction is obtained by substituting the input into the learned equation.
  3. Predicted values always lie on the regression line.
  4. Actual values may be above or below the line, and their difference from the prediction is the error (residual).
  5. Each sample has its own error, but the cost function combines the errors of all training samples into one value that the model minimizes during training.
  6. After training, the learned line is fixed. The test set is only used to evaluate the model — it does not change the line.

We optimize cost on the training data or test data? Only on the training data.

Simple Linear Regression (Mathematical Intuition)

You try to draw a straight line that best fits the data: \( Y = mX + b \), where m = slope (how steep the line is) and b = intercept (where the line cuts the Y-axis). Goal: predicted value close to actual value, and a line that fits most points well.

Closed Form Solution (OLS)

Closed form means: you directly compute m and b using a formula — no iteration, no guessing. Plug values into the formula, get the exact answer. This is OLS (Ordinary Least Squares). Used when data is small and dimensions are low (like 1 feature).

Gradient Descent (Non-Closed Form)

No direct formula. Start with random values (e.g. m = 0, b = 0) and improve step by step, repeating until error becomes small. At each step: calculate error using MSE, check direction (increase/decrease m?), move in the direction where error decreases. Used when data is large or has many features (high dimension).

Mathematical Intuition of m (Slope)

$$ m = \frac{\sum_{i=1}^{n}(x_i - \bar{x})(y_i - \bar{y})}{\sum_{i=1}^{n}(x_i - \bar{x})^2} $$

Numerator → how x and y move together (covariance-style term). Denominator → spread of x, i.e. how much the values of X are scattered from their average (variance-style term). If x increases and y increases → m is positive. If x increases and y decreases → m is negative.

Low spread — values close together, small variation. Example: X = [2, 3, 4].
High spread — values far apart, large variation. Example: X = [1, 10, 100].

Finding b (Intercept)

$$ b = \bar{y} - m\bar{x} $$

Once m is known: take the mean of y and x, then subtract the effect of the slope.

Loss / Cost Function

You need a way to measure error: \( e = y_{actual} - y_{predicted} \). The cost function is the overall error of the model — the Mean Squared Error:

$$ MSE = \frac{1}{n}\sum_{i=1}^{n}(y_i - \hat{y}_i)^2 $$

Why Square, Not Absolute?

We square instead of taking the absolute value so opposite-sign distances don't cancel each other out, and — critically — because |x| is not differentiable at 0, while gradient descent needs a smooth, differentiable function to find a direction to move in.

If we use square: large errors become very large, the model focuses on big mistakes, and the function is smooth → easy math.
If we use absolute: all errors treated equally, harder to optimize mathematically (non-differentiable corner at 0).

So: MSE is easier for optimization and works well with OLS.

Your Code Explanation — Manual Linear Regression (MeraLR) 
class MeraLR:

    def __init__(self):
        self.m = None
        self.b = None

    def fit(self, X_train, y_train):

        num = 0
        den = 0

        # Loop through all data points
        for i in range(X_train.shape[0]):

            # numerator: covariance part
            num = num + ((X_train[i] - X_train.mean()) * (y_train[i] -
y_train.mean()))

            # denominator: variance part
            den = den + ((X_train[i] - X_train.mean()) * (X_train[i] -
X_train.mean()))

        # slope
        self.m = num / den

        # intercept
        self.b = y_train.mean() - (self.m * X_train.mean())

        print(self.m)
        print(self.b)

    def predict(self, X_test):
        return self.m * X_test + self.b

fit() — computes m manually using the covariance / variance formula. Step by step: loop over all points, compute numerator and denominator, divide to get slope, then compute b using the mean formula.

predict() — applies the learned equation y = mx + b to a new input to get a prediction.

Key Takeaways

  • Linear Regression = fit best straight line
  • OLS = direct formula method
  • Gradient Descent = iterative method
  • m = relationship between x and y
  • b = starting point of the line
  • MSE = error measurement
  • Squaring error makes the model care about large mistakes

Regression Metrics

Setup: Input CGPA, Output Salary. The model gives predictions — now the question is: "Is this model good or bad?" You need a number to judge it. Without metrics you only see a line and cannot compare models. With metrics, you get a score, can compare models, and can improve them.

Error — difference for one data point. \( y - \hat{y} \). Example: real salary 50k, predicted 40k → error 10k. Raw difference.
Loss function — error for one point after applying a transforming formula: \( |y-\hat{y}| \) or \( (y-\hat{y})^2 \). Example: take absolute → |10| = 10; square it → 100. Why transform? Raw error cancels out (+/−); you want the magnitude of the mistake.
Cost function — the average loss over the entire dataset, which the model aims to minimize during training.

Mean Absolute Error (MAE)

$$ MAE = \frac{1}{n}\sum_{i=1}^{n}|y_i - \hat{y}_i| $$

What happens: for each point, take the distance between real and predicted, ignore the sign, add all distances, divide by total points. Intuition: "On average, how wrong am I?" If MAE = 5k, predictions are off by 5k on average.

Advantages
  • Same unit as output
  • Easy to understand
  • Robust to outliers — outliers do not dominate

Example — errors 2, 3, 4, 100: MAE = (2+3+4+100)/4 = 27.25. The outlier (100) affects the result, but not insanely.

Disadvantages

Not differentiable at 0 — the graph of |x| has a sharp corner there. Gradient descent needs smooth curves; the slope is undefined at 0, which makes optimization harder.

Mean Squared Error (MSE)

$$ MSE = \frac{1}{n}\sum_{i=1}^{n}(y_i - \hat{y}_i)^2 $$

Meaning: squares the error and averages it — large errors become very large. Intuition: "Punish large mistakes more."

Example — errors 2, 3, 4, 100: squared → 4, 9, 16, 10000 — huge impact from the 100. One outlier dominates everything.

Advantages
  • Differentiable
  • Easy for optimization
  • Used in most algorithms

Why square helps: removes the negative sign, makes the function smooth, easy to optimize via gradient descent.

Disadvantages
  • Unit becomes squared — hard to interpret back
  • Not robust to outliers — big errors become extremely big and dominate the result

Rule: more outliers → use MAE. Clean data → use MSE.

Root Mean Squared Error (RMSE)

$$ RMSE = \sqrt{MSE} = \sqrt{\frac{1}{n}\sum_{i=1}^{n}(y_i - \hat{y}_i)^2} $$

Why the square root? MSE's unit is squared — e.g. salary becomes (rupees)², which is meaningless. RMSE brings it back to the original unit. Intuition: same as MSE but easier to interpret. If RMSE = 5k, error is around 5k.

Advantages
  • Same unit as output
  • Penalizes large errors
  • Common in deep learning
Disadvantages

Still sensitive to outliers, still not robust — squaring still happens inside, so outliers still dominate.

R² Score (Coefficient of Determination — Goodness of Fit)

Baseline idea: imagine you ignore the model and predict "everyone's salary = average salary" — the mean model. Now compare your regression line vs. the mean line. R² measures: "How much better is my regression model than just predicting the mean?"

$$ R^2 = 1 - \frac{SS_{res}}{SS_{mean}} = 1 - \frac{\sum_{i=1}^{n}(y_i - \hat{y}_i)^2}{\sum_{i=1}^{n}(y_i - \bar{y})^2} $$

The closer we get to perfection, the more R² moves toward 1 — the numerator (SSres) approaches zero as the regression line covers all points. The closer we get to just predicting the mean, the more R² moves toward 0.

CaseConditionMeaning
R² = 1 (perfect)SSres = 0The regression model makes no error, so the numerator is zero and 1 − 0 = 1.
R² = 0 (same as mean)SSres = SSmeanThe model is equal to the mean model — the input features add nothing.
R² < 0 (worse than mean)SSres > SSmeanThe model is garbage — it makes more error than just predicting the mean. Can happen when the data is non-linear but you apply a linear model to it.

Real interpretation: R² = 0.80 means 80% of the variation is explained, 20% is unknown. If CGPA → Salary gives R² = 0.80, CGPA explains 80% of the variance in salary; the remaining 20% could be anything not captured mathematically. Important: it does NOT mean accuracy — it means explanation power.

Advantages — easy to interpret, independent of unit, good for model comparison.
Disadvantage — adding an irrelevant column (e.g. temperature to a salary model) introduces more variance; instead of decreasing, R² can sometimes increase because of that irrelevant input.

The Problem with R²

Every time you add a new feature — even a useless one — R² can only stay the same or increase, never decrease. Why? The model gets more flexibility and can fit noise. So R² alone can mislead you into thinking a model with more features is better, when it's really just overfitting to noise.

Adjusted R² Score

$$ \text{Adjusted } R^2 = 1 - \frac{(1-R^2)(n-1)}{n-k-1} $$

k = number of features (columns), n = number of rows, R² = the normal R² score. It is designed to remove the flaw that R² has when irrelevant columns are added. Adding an irrelevant column increases k, which lowers the denominator (n − k − 1), which increases the fraction being subtracted from 1 — so Adjusted R² comes out lower than plain R². It works the opposite way too: adding a genuinely relevant column pushes Adjusted R² higher than plain R². It becomes a reliable metric when dealing with many input features or multiple linear regression.

Intuition: "You only get rewarded if the new feature is useful." Useless feature → Adjusted R² goes down. Useful feature → Adjusted R² goes up.

Final Mental Model

  • MAE → average mistake
  • MSE → punish big mistakes
  • RMSE → readable MSE
  • R² → how much the model explains
  • Adjusted R² → real performance accounting for the number of features used

Multiple Linear Regression (Geometric Intuition)

Multiple Linear Regression extends simple linear regression. In simple linear regression we have only one input feature: \( y = mx + b \). In multiple linear regression we have more than one input feature:

$$ y = b_0 + b_1x_1 + b_2x_2 + \cdots + b_nx_n $$
Understanding the terms
  • y → target value (output)
  • x₁, x₂, …, xₙ → input features
  • b₀ → intercept (bias)
  • b₁, b₂, …, bₙ → coefficients (weights)
Meaning of coefficients
  • b₁, b₂, … show the importance of each feature — a higher value means a stronger effect on the output, and tells how much y changes when that feature changes.
  • b₀ (intercept) — the value of y when all inputs are zero; the starting point of the prediction.

Geometric Interpretation

  • 2D (one feature) → a line
  • 3D (two features) → a plane
  • 4D or more → a hyperplane

So: linear regression fits a line; multiple regression fits a plane or hyperplane.

Why It Matters

Real-world problems rarely depend on one variable — multiple regression captures the combined effect of many features. Example: house price depends on size, location, and number of rooms together.

Dataset Generation (Scikit-learn)

You can generate synthetic data using scikit-learn's make_regression function. It creates linear datasets, supports multiple features, and is useful for practice and testing models — set the number of features, then generate X (inputs) and y (output).

Multiple Linear Regression (Mathematical Formulation)

The goal is the same as before — minimize the sum of squared errors — but now with n input features and n+1 unknown parameters (b₀ … bₙ), it is far more convenient to work in matrix form rather than expand n separate partial derivatives by hand.

Illustrative aid — the source page for this derivation was an embedded image that didn't extract as text. The step-by-step below is reconstructed to reach the same closed-form result the notes state directly on Day 57 (\( w = (X^TX)^{-1}X^Ty \)) and use in the Day 55 code — not a verbatim transcription of the original page.

1. The Design Matrix (the "bias trick")

Prepend a column of 1s to the feature matrix X so the intercept b₀ can be treated as just another coefficient multiplying a constant "feature" of 1. This is exactly what np.insert(X_train, 0, 1, axis=1) does in the code on Day 55.

$$ Y = X\beta + \varepsilon $$

Where X is the (n × (k+1)) design matrix (first column all 1s), β = [b₀, b₁, …, b_k]ᵀ is the vector of intercept + coefficients, Y is the vector of actual targets, and ε is the vector of residual errors.

2. Cost Function in Matrix Form

The same "sum of squared errors" cost, written compactly as a dot product of the residual vector with itself:

$$ J(\beta) = \frac{1}{n}(Y - X\beta)^T(Y - X\beta) $$

3. Minimizing — the Normal Equation

Because J(β) is convex (a bowl-shaped quadratic in β), its minimum is exactly where the gradient with respect to β is the zero vector. Differentiate and set to zero:

$$ \nabla_\beta J(\beta) = -2X^TY + 2X^TX\beta = 0 $$

Rearranging:

$$ X^TX\beta = X^TY $$

Solving for β by left-multiplying both sides by \( (X^TX)^{-1} \) gives the closed-form OLS solution (the "Normal Equation") — the exact same formula quoted on Day 57 as \( w = (X^TX)^{-1}X^Ty \):

$$ \beta = (X^TX)^{-1}X^TY $$

β₀ (the first entry) is the intercept; β₁ … β_k are the coefficients — exactly what betas[0] and betas[1:] pull apart in the Day 55 code.

This matrix invertibility, \( (X^TX)^{-1} \), is exactly what breaks down when features are duplicated or perfectly correlated — see "No multicollinearity" in Day 56 and the "non-invertible matrix" failure mode covered in Day 57.

Multiple Linear Regression (Code)

A from-scratch implementation that computes the Normal Equation directly, mirroring the derivation from Day 54.

import numpy as np

class MeraLR:
    def __init__(self):
        self.coef_ = None
        self.intercept_ = None

    def fit(self, X_train, Y_train):
        X_train = np.insert(X_train, 0, 1, axis=1)
        print(X_train)
        # calculate the coeffs
        betas = np.linalg.inv(np.dot(X_train.T, X_train)).dot(X_train.T).dot(Y_train)
        self.intercept_ = betas[0]
        self.coef_ = betas[1:]
        # print(betas)

    def predicted(self, X_test):
        y_pred = np.dot(X_test, self.coef_) + self.intercept_
        # Each row -> multiply with slope coefs -> sum all -> add intercept, for each row
        return y_pred


lr = MeraLR()

lr.fit(X_train, y_train)

y_predict = lr.predicted(X_test)
print(y_predict)

r2_score(y_test, y_predict)

fit() — inserts a column of 1s at position 0 so the intercept is folded into the same matrix multiplication as the coefficients, computes β = (XᵀX)⁻¹XᵀY via np.linalg.inv, then splits the result: first element → intercept, remaining elements → coefficients.
predicted() — for each row, multiplies feature values by their learned slope coefficients, sums them, and adds the intercept: \( \hat{y} = X\beta_{1:} + \beta_0 \).
Day 56

Assumptions of Linear Regression

Linear regression's coefficients and its statistical guarantees are only trustworthy when the following five assumptions roughly hold. Violating one doesn't necessarily make the model useless, but it undermines the reliability of the coefficients, p-values, or predictions in specific ways.

# Assumption What It Means How to Detect
1 Linear relationship There should be a linear relationship between input and output — that's the entire premise of fitting a straight line/hyperplane. Scatter plots of each feature vs. target; residual vs. fitted plots.
2 No multicollinearity Input columns should be independent of one another — no strong correlation between features. Variance Inflation Factor (VIF) — a value of 5 or more indicates multicollinearity; also a correlation heatmap via corr().
3 Normality of residuals The difference between actual and predicted value (the error/residual) should follow a normal distribution when plotted. Histogram / Q-Q plot of residuals.
4 Homoscedasticity "Homo" = same, "scedasticity" = spread. Residuals must have equal (constant) spread across all fitted values — not fan out or shrink. Plot residuals vs. fitted values — spread should look like a flat, even band, not a cone.
5 No autocorrelation of errors Residuals should not be correlated with each other (e.g. one error predicting the next) — a common violation in time-series/sequential data. Plot residuals in sequence order; check for patterns.

Why These Matter in Practice

  • Violating linearity means the model systematically under- or over-predicts in some regions — a curved/polynomial relationship forced into a straight line.
  • Violating no multicollinearity makes individual coefficients unstable and hard to interpret — two correlated features can "steal" importance from each other, and in the extreme case (perfectly duplicated features) the Normal Equation's \( X^TX \) becomes non-invertible.
  • Violating homoscedasticity doesn't bias the coefficients themselves but makes their confidence intervals/standard errors unreliable.
  • Violating no autocorrelation is especially common in time-series data, where consecutive errors are related — this also inflates the false sense of precision in standard errors.
Day 57

Gradient Descent from Scratch

Gradient descent is an optimization technique that takes a differentiable function and finds its minima. It is the general algorithm used in linear regression, logistic regression, and is the backbone of deep learning.

OLS vs Gradient Descent

OLS (Ordinary Least Squares) Gradient Descent
MethodDirect formula, no iteration: \( w = (X^TX)^{-1}X^Ty \). Computes weights in one step using matrix inversion.Iterative optimization: \( w = w - \alpha\nabla J \). Start with random weights, update step by step.
What happensMultiply XᵀX → take its inverse → multiply with Xᵀy → get exact best weights.Loop: (1) predict ŷ, (2) compute error, (3) compute gradient, (4) update weights — repeat until error reduces.
ProsExact solution; no learning rate; no epochs; same result every time.Works with huge datasets; no matrix inversion; scales well; works with regularization.
ConsMatrix inversion costs O(n³) — very slow for large feature counts, high memory usage; fails if the matrix is not invertible (singular).Needs a learning rate; needs epochs; can converge slowly; can get stuck if poorly tuned.
Best forSmall datasets, few features.Large datasets, high-dimensional data, when data doesn't fit in memory.

Core difference in one line: OLS solves directly using math. GD learns step by step using error.

Why OLS Can Fail: Non-Invertible Matrices

If a matrix has no inverse, it's called non-invertible (singular). The most common reason: duplicate or perfectly dependent features. Example — a "Size" and an "Area in sq ft" column that contain exactly the same values (1000/1000, 1200/1200, 1500/1500 …). The second feature adds nothing new; because of this redundancy, XᵀX cannot be inverted, and the Normal Equation cannot be computed.

The Update Rule

Naively subtracting the raw slope causes drastic jumps, so we scale it by a learning rate η (typically ~0.01):

$$ b_{new} = b_{old} - \eta \cdot \text{slope} \qquad\qquad w_{new} = w_{old} - \alpha\frac{\partial J}{\partial w} $$

A higher learning rate causes jumps to the opposite side, skipping the solution; a lower learning rate converges very slowly.

Case 1 — ∂J/∂w = 5, α = 0.1, w_old = 8
w_new = 8 − (0.1)(5) = 8 − 0.5 = 7.5 → positive gradient → w decreases
Case 2 — ∂J/∂w = −5, α = 0.1, w_old = 2
w_new = 2 − (0.1)(−5) = 2 + 0.5 = 2.5 → negative gradient → w increases

At the minimum: ∂J/∂w = 0 → w_new = w_old (no change).

The Intuition to Remember

Imagine you're blindfolded on a hill and can only feel the ground beneath your feet. If the ground tilts upward to your right (positive slope, which makes the new w smaller), you know downhill is left, so you decrease w. If the ground tilts upward to your left (negative slope, which adds to the new w value), you know downhill is right, so you increase w. If the ground feels flat (gradient = 0), you're at the bottom of the valley — the cost is minimum. Near a local minimum, the derivative gets smaller and smaller, so the update step also shrinks automatically — you can reach the minimum without manually decaying the learning rate, because the derivative is doing that work for you.

Convex vs Non-Convex Functions

Convex — a single bowl shape, one global minimum. No matter where you start, gradient descent always slides down to the same lowest point — no risk of getting stuck. Linear regression's MSE cost is convex — a big reason MSE is popular: gradient descent is guaranteed to converge to the true minimum.
Non-convex — multiple bumps and dips (multiple local minima), not just one. Where you start matters — gradient descent might slide into a local minimum that looks like the bottom locally but isn't the true global minimum. Neural network cost functions are almost always non-convex, which is why deep learning training is trickier — you can get stuck in a local minimum, a saddle point, or a plateau.

Key mathematical difference: a function J(w) is convex if, for any two points w₁, w₂ on the curve, the line segment (chord) connecting them never goes below the curve:

$$ J(\theta w_1 + (1-\theta) w_2) \le \theta J(w_1) + (1-\theta) J(w_2), \quad \theta \in [0,1] $$

θ is a mixing knob between 0 and 1 — it tells you how far you're walking from w₁ to w₂ along the straight line \( \theta w_1 + (1-\theta) w_2 \): θ = 0 → standing exactly at w₂; θ = 1 → standing exactly at w₁; θ = 0.5 → exactly halfway between them. The test in plain words: pick two points on the curve, draw a straight chord connecting them. Convex → the chord stays above or on the curve everywhere between them. Non-convex → the chord dips below the curve somewhere.

Worked example: for the convex curve J(w) = w², pick w₁ = −2 and w₂ = 3. At the midpoint (θ = 0.5), the actual curve sits at 0.25 while the chord sits at 6.5 — curve ≤ chord, holding everywhere. For the non-convex curve J(w) = w⁴ − 4w², pick w₁ = −1.8 and w₂ = 1.8 (both in the two dips) — the chord is flat around −2.46, but the actual curve pokes up to 0 in the middle, sitting above the chord. That's the violation: curve > chord means the inequality fails — exactly what non-convex means.

ConvexNon-convex
MinimaOne (global)Many (local + global)
Starting pointDoesn't matterMatters a lot
GuaranteeAlways finds the minimumMay get stuck in a local minimum
ExampleLinear / logistic regressionNeural networks

That's why techniques like momentum, learning-rate scheduling, and random restarts exist — they help gradient descent escape bad local minima in non-convex landscapes.

Deriving the Gradient — Step by Step

  1. We make a prediction: \( \hat{y} = wx + b \)
  2. We calculate the loss: \( L = (\hat{y} - y)^2 \)
  3. We compute the derivative \( \partial L/\partial w \) — this answers "if I change w a tiny bit, how much will the loss change?"
  4. We update the weight: \( w_{new} = w_{old} - \alpha \dfrac{\partial L}{\partial w} \), where α is the learning rate.

Differentiating the MSE cost with respect to b and m directly gives the two slope formulas used by the update rule:

$$ \frac{\partial J}{\partial b} = \frac{-2}{n}\sum_{i=1}^{n}(y_i - mx_i - b) $$ $$ \frac{\partial J}{\partial m} = \frac{-2}{n}\sum_{i=1}^{n}(y_i - mx_i - b)x_i $$

Direction is now a combination of two different variables, m and b — that's why it's called a gradient and not simply a derivative. Each algorithm has a different loss function, so the differentiation changes accordingly, but the mechanics (b, learning rate) stay the same.

Putting It Together — Steps & Worked Example

  1. Initialize random values for m and b.
  2. Set epochs = 100, learning rate (lr) = 0.1.
  3. For i in epochs: b = b − lr × slope; m = m − lr × slope.
b = -100
m = 78.35
lr = 0.1
epochs = 10

for i in range(epochs):
    loss_slope = -2 * np.sum(y - m*X.ravel() - b)
    b = b - (lr * loss_slope)

y_pred = m * X + b
plt.plot(X, y_pred)
plt.scatter(X, y)

Linear Regression: "I want to find the best line through data." Gradient Descent: "I will slowly adjust the line until it fits best." Linear regression defines what we want (the best-fit line); gradient descent is one way to find that best-fit line by iteratively reducing error.

Learning rate impact
  • Small lr → many iterations/time to converge
  • Optimum lr (e.g. 0.1) → optimum steps to find the minima
  • Large lr (e.g. 0.5) → skips the actual target, bouncing back and forth

To check whether the chosen learning rate is optimal, plot the cost function per iteration and check that it is decreasing. Practical approach: try a range — start with 0.001, then 0.01, then 0.1, then 1 — until you find a reasonable value.

Loss-function & data effects on GD
  • Non-convex loss functions (common in deep learning) can create a saddle point — a flat plateau that takes much longer to cross; with too few epochs you may never reach the solution.
  • When input features are on similar scales, the cost function's contour plot is more circular, and gradient descent descends much faster — it's always better to scale data before running gradient descent on linear regression.

Three Types of Gradient Descent

They differ in how much data they look at before updating the weights.

1. Batch Gradient Descent (BGD) — uses the entire training dataset to compute the gradient before making a single update. Example: 10,000 house-price examples → Batch GD calculates the average gradient across all 10,000 rows, then updates w once.
  • Very stable, smooth path to the minimum
  • Slow — one update requires a full pass over the data
  • Can't handle datasets too big to fit in memory
2. Stochastic Gradient Descent (SGD) — uses just ONE random training example per update. Example: same 10,000 rows — SGD picks row #4521, computes the gradient from just that row, updates w; picks another random row, updates again — 10,000 times per epoch.
  • Very fast updates, works well with huge/streaming data
  • Noisy, zig-zaggy path — doesn't move smoothly downhill
  • The noise can actually help escape shallow local minima (useful in non-convex problems like neural nets)
3. Mini-Batch Gradient Descent — uses a small batch (e.g. 32, 64, 128 examples) per update, a middle ground. Example: same 10,000 rows split into batches of 64 → ~156 updates per epoch instead of 1 (batch) or 10,000 (SGD).
  • Faster than batch, smoother than SGD
  • This is what's actually used in almost all real deep learning training
  • Batch size (32/64/128/256…) is a tunable hyperparameter

Quick Reference — Batch vs SGD vs Mini-Batch

Type Data per Update Path Shape Speed per Update Best For
Batch GDEntire datasetSmooth, directSlowSmall datasets, convex problems
SGD1 exampleVery noisy zig-zagVery fastHuge/streaming data, escaping local minima
Mini-batch GDSmall batch (32–256)Slightly noisyFastStandard choice — used in almost all deep learning

Simple way to remember it: the more examples you average over before updating, the smoother (but slower) your path downhill. One extreme is "look at everything, then take one careful step" (Batch). The other is "look at one thing, take a step, look at another thing, take a step" (SGD). Mini-batch is the practical compromise everyone actually uses.

Day 58

Batch Gradient Descent

In batch gradient descent, we use the total data (all rows) to update/calculate the slope each step. It is slow and has computational drawbacks for large data — that motivates stochastic and mini-batch variants. Batch GD is rare in practice; it's used when the cost function is convex but the dataset is manageable in size. Stochastic GD is used far more widely.

Applying Gradient Descent to Multiple Linear Regression

Mathematical formulation: \( y = b_0 + b_1x_1 + b_2x_2 \). We start with random values, e.g. b₀ = 0 and slopes b₁ = 1, b₂ = 1, then update each:

$$ b_0 = b_0 - \eta \cdot \text{slope}_{b_0} \qquad b_1 = b_1 - \eta \cdot \text{slope}_{b_1} \qquad b_2 = b_2 - \eta \cdot \text{slope}_{b_2} \\ $$

Each slope is found by differentiating the MSE loss function with respect to that particular parameter — the MSE is expanded and then partial-differentiated term by term.

What "Update Once Per Full Pass" Actually Means

"Calculates across all 10,000 rows, then updates once" means:

  1. Loop through all 10,000 houses
  2. For each one, compute how far off the prediction was
  3. Average all 10,000 of those errors into one number
  4. Use that one number to move w a single time
  5. Repeat — go through all 10,000 rows again for the next update

Trace it with numbers:

Pass 1

w = 3 (starting value). House 1 (size = 1000): prediction = 3 × 1000 = 3000, actual price = 2000 → large error. Same for all 10,000 houses → average gradient computed, say it comes out to +8. Update: w_new = 3 − 0.01(8) = 2.92.

Pass 2

w is now 2.92 (the model's value — not stored in the rows). House 1 is the exact same row — size 1000, price 2000. But now prediction = 2.92 × 1000 = 2920, a better prediction purely because w changed. Repeat for all 10,000 houses → new average gradient, say +5. Update: w_new = 2.92 − 0.01(5) = 2.87.

The clean way to say it: the data stays frozen. The model's parameter w evolves. Each pass, you feed the same 10,000 rows through the model, but the model itself is a little smarter (has a better w) than the previous pass — so the predictions, errors, and resulting gradient differ each time, even though the input data never moved.

Batch GD — Compact Numeric Example

# Data
X = [[1, 2],
     [3, 4],
     [5, 6]]

y = [5, 11, 17]

w = [1, 1]
b = 0

# Step 1: Prediction (use ALL samples)
y_hat = Xw + b
y_hat = [3, 7, 11]

# Step 2: Error (ALL samples)
error = y - y_hat
      = [2, 4, 6]

# Step 3: Gradient (core step)
# grad_J = (-2/n) * X.T @ (y - y_hat)
# Transpose:
X.T = [[1, 3, 5],
       [2, 4, 6]]
# Multiply:
X.T . error = [44, 56]

# Final gradient:
gradient = [-29.33, -37.33]
$$ \nabla J = \frac{-2}{n} X^T(y - \hat{y}) $$

Key Insight (Most Important)

Each weight uses ALL samples together — w₁'s gradient contribution is (1×2) + (3×4) + (5×6) across samples s1, s2, s3. No sample is skipped.

Why it's slow on large data: if there are 1M samples, w₁'s gradient = (x₁×e₁) + (x₂×e₂) + … + (x₁₀₀₀₀₀₀×e₁₀₀₀₀₀₀) — huge multiplications per step, repeated for every feature and every epoch.

One-line intuition: Batch GD sees ALL errors → takes ONE update.

Day 59

Stochastic Gradient Descent

Problem with batch GD: say you have 1,000 rows, 5 columns (so 6 coefficients including the intercept), and 50 epochs — every single epoch requires a full pass over all 1,000 rows before the weights move even once. That cost compounds badly as data grows.

Batch vs Stochastic — The Setup

Current weight (w) = 2.0, learning rate (α) = 0.1.

  • In Batch GD: you do all the work of looking at every row just to move the weight from 2.0 to 2.033 — you have to look at all rows before the weight moves even a tiny bit.
  • In Stochastic GD: you look at Row B, see the error was −1, and update the weight immediately to 2.1. Then you move to Row C and update again.

The analogy: Batch is "polite" — it waits for everyone to speak before making a decision. Stochastic is "impulsive" — it reacts to every single person it meets. This is why Batch GD is so much slower once you have millions of rows.

Why SGD is used
  • Fast and requires fewer epochs; gives faster convergence
  • Not necessary to load all data into RAM
  • Randomly selects a row and updates — that's why it's called "stochastic": it's random, so it won't be perfectly stable
  • Used for big data because it converges faster
  • Used for non-convex functions — surfaces with multiple local minima and one global minimum: in batch GD you can get permanently stuck in a local minimum, but in stochastic GD the randomness of picking different rows each step can knock you back out of a shallow local minimum
The tradeoff

The problem with stochastic GD is that even near the true solution (the global minimum), it still shows randomness — bouncing around — even though you'd want stability there. That's what motivates the learning schedule concept: gradually decreasing the learning rate over time so updates get smaller and more stable as training progresses, letting SGD settle near the minimum instead of bouncing around it indefinitely.

Day 60

Mini Batch Gradient Descent

Mini-batch GD groups rows into batches — it sits in between Batch and Stochastic GD. Example: 100 rows, one batch of 10 rows → 10 total batches. In each epoch we now perform a number of updates equal to the number of batches, instead of one update (Batch) or one update per row (Stochastic).

Code — MBGDRegressor

import random

class MBGDRegressor:

    def __init__(self, batch_size, learning_rate=0.01, epochs=100):

        self.coef_ = None
        self.intercept_ = None
        self.lr = learning_rate
        self.epochs = epochs
        self.batch_size = batch_size

    def fit(self, X_train, y_train):
        # init your coefs
        self.intercept_ = 0
        self.coef_ = np.ones(X_train.shape[1])

        for i in range(self.epochs):

            for j in range(int(X_train.shape[0] / self.batch_size)):

                idx = random.sample(range(X_train.shape[0]), self.batch_size)

                y_hat = np.dot(X_train[idx], self.coef_) + self.intercept_
                # print("Shape of y_hat", y_hat.shape)
                intercept_der = -2 * np.mean(y_train[idx] - y_hat)
                self.intercept_ = self.intercept_ - (self.lr * intercept_der)

                coef_der = -2 * np.dot((y_train[idx] - y_hat), X_train[idx])
                self.coef_ = self.coef_ - (self.lr * coef_der)

        print(self.intercept_, self.coef_)

    def predict(self, X_test):
        return np.dot(X_test, self.coef_) + self.intercept_


mbr = MBGDRegressor(batch_size=int(X_train.shape[0] / 50), learning_rate=0.01, epochs=100)

mbr.fit(X_train, y_train)

Note the batch size is derived as X_train.shape[0] / 50 — i.e. the caller chooses "50 batches per epoch" and lets the regressor compute the resulting rows-per-batch. Inside fit(), each inner loop iteration draws a random sample of batch_size row indices (without a fixed order across epochs), predicts on just that subset, computes the mean gradient over the subset, and updates the intercept and coefficients — exactly the "group of rows" compromise between Batch (all rows) and Stochastic (one row) gradient descent.

5 questions on Day 50–60. Pick an answer for each, then check.

1. You have 1 million rows, 200 features, and one of your features is a perfect duplicate of another (e.g. "size_sqft" and "size_sqft_copy"). You need an exact, one-shot solution. Which approach — and why does it specifically fail here?

Explanation: Duplicate/perfectly dependent features make XᵀX singular, so OLS's matrix inversion breaks (as covered in Day 57's "why does this happen" walkthrough). Gradient Descent never inverts a matrix, so it's unaffected by this specific failure mode — and at 1M rows / 200 features, GD's iterative approach also avoids OLS's O(n³) inversion cost. (D is wrong — GD tolerates the redundant feature without needing it removed first.)

2. You add 10 randomly-generated, meaningless columns to your regression's feature set. R² increases from 0.62 to 0.71. What's the most defensible conclusion?

Explanation: Day 52 explicitly covers this: adding any feature — even a useless one — gives the model more flexibility to fit noise, so R² can only stay flat or increase, never decrease. Adjusted R² exists precisely to correct this: its (n−k−1) denominator shrinks as k grows, penalizing additions that don't earn their keep — for random noise columns, Adjusted R² would very likely drop even as R² rises.

3. Your dataset is 50 million rows, doesn't fit in RAM, and you're training a neural-network-style non-convex loss where you're worried about getting trapped in a shallow local minimum. Which gradient descent variant best matches BOTH constraints, and why?

Explanation: Batch GD requires the whole dataset for every single update (fails the memory constraint) and its smooth path is exactly what lets it get stuck in a local minimum on non-convex surfaces (Day 57/59). SGD and mini-batch GD only need a row or small batch per update — feasible for 50M rows — and their randomness is explicitly called out as a mechanism for escaping shallow local minima, unlike batch's deterministic descent. OLS is not even applicable to non-convex/neural-style losses.

4. A model's residuals, when plotted against the predicted values, form a clear cone shape — small spread for low predictions, wide spread for high predictions. Which assumption is violated, and what does that specifically compromise?

Explanation: A cone/fan shape in a residual-vs-fitted plot is the textbook signature of heteroscedasticity — unequal spread across fitted values, violating the homoscedasticity assumption from Day 56. Multicollinearity is detected via VIF/correlation heatmaps on inputs, not this plot; normality is checked via a histogram/Q-Q plot of residuals, not a cone shape; autocorrelation is checked by residuals in sequence order.

5. You're running gradient descent on a scaled, single-feature linear regression and get R² = −0.3 on the test set. What does this specifically tell you?

Explanation: Day 52 spells this out directly: R² < 0 happens when SS_res > SS_mean, meaning the fitted line performs worse than the trivial "predict the mean" baseline — often a sign of applying a linear model to a non-linear relationship (or, in a gradient descent context, a poorly-tuned/diverged fit). It is not a computation error, and R² is routinely computed on held-out test data to evaluate generalization — that's the entire point of the train/test metric step in the Day 50 pipeline.
