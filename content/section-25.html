Classification

Softmax Regression (Multinomial Logistic Regression)

Binary logistic regression answers a yes/no question: it computes one linear score \(z = w^\top x + b\), squashes it through the sigmoid, and reads the result as "probability of the positive class." That trick only works for two classes because a single number \(z\) only has one axis to move along — toward class 1 or toward class 0. What happens when you have K classes — say, classifying an email as work, personal, or spam?

The fix: instead of one linear score, compute one linear score per class. Each class \(k\) gets its own weight vector \(w_k\) and bias \(b_k\), producing its own raw score \(z_k = w_k^\top x + b_k\). Now you have K numbers — one "how much does this look like class k" score per class — and you need a way to turn K arbitrary real numbers into K probabilities that sum to 1. That's exactly what the softmax function does.

$$ \text{softmax}(z_i) = \frac{e^{z_i}}{\sum_{j=1}^{K} e^{z_j}} $$

Read this piece by piece: exponentiating every score \(e^{z_i}\) makes everything positive (no negative probabilities) and amplifies differences (a score that's a bit higher than the rest becomes disproportionately larger after exponentiating — this is what makes softmax "winner-take-most" rather than a flat average). Dividing by the sum of all the exponentials normalizes the whole vector so it sums to exactly 1, turning it into a valid probability distribution over the K classes.

Sigmoid is softmax's special case

With exactly K=2 classes, softmax reduces algebraically to the sigmoid function applied to the difference of the two scores, \(z_1 - z_0\). Binary logistic regression isn't a different algorithm from softmax regression — it's the K=2 case, parameterized more efficiently (one score instead of two, since the two scores' difference is all that matters).

One-hot encoding the targets

Binary logistic regression's targets are single numbers, 0 or 1. Softmax regression's targets need to be vectors, because the model's output is a vector of K probabilities. A label like "class 2 out of 3" is one-hot encoded into \([0, 0, 1]\) — a vector of zeros with a single 1 in the position of the true class. This lets you compare the model's predicted probability vector directly against the true "probability" vector (which is 1.0 on the correct class and 0.0 everywhere else) using the same subtraction/comparison machinery throughout training.

Categorical cross-entropy — the loss function

Binary logistic regression trains by minimizing binary cross-entropy (log loss). Softmax regression's loss is the direct multi-class generalization, categorical cross-entropy:

$$ J(w) = -\sum_{i=1}^{n} \sum_{k=1}^{K} y_{i,k} \, \log(\hat{p}_{i,k}) $$

\(y_{i,k}\) is 1 if sample \(i\)'s true class is \(k\) and 0 otherwise (the one-hot vector), and \(\hat{p}_{i,k}\) is the model's predicted softmax probability that sample \(i\) belongs to class \(k\). Because \(y_{i,k}\) zeroes out every term except the true class, this sum collapses per-sample to just \(-\log(\hat{p}_{i,\text{true class}})\) — in plain English: penalize the model by how far its predicted probability on the correct class was from 1.0. Confidently correct (\(\hat{p}\) near 1) → loss near 0. Confidently wrong (\(\hat{p}\) near 0 on the true class) → loss shoots toward infinity.

Code — multinomial logistic regression with scikit-learn

from sklearn.linear_model import LogisticRegression
from sklearn.preprocessing import StandardScaler
from sklearn.pipeline import make_pipeline

# multi_class='multinomial' trains one true softmax model —
# all K score functions are learned jointly against categorical
# cross-entropy, rather than the older "one-vs-rest" workaround
# (train K separate binary classifiers, each asking "is it class k or not?")
model = make_pipeline(
    StandardScaler(),
    LogisticRegression(
        multi_class='multinomial',
        solver='lbfgs',     # required for true multinomial loss
        max_iter=1000
    )
)

model.fit(X_train, y_train)

probs = model.predict_proba(X_test)   # shape (n_samples, n_classes), rows sum to 1
preds = model.predict(X_test)         # argmax of probs, per row

print(probs[0])   # e.g. [0.05, 0.90, 0.05] -> predicted class 1
Note. Recent scikit-learn versions infer multinomial vs one-vs-rest automatically based on the solver and data, and have deprecated the explicit multi_class argument in favor of always using softmax when the solver supports it. The concept — one joint softmax over K classes — is what matters; check your installed version's docs for the exact current API.

Polynomial Features in Logistic Regression (Non-Linear Decision Boundaries)

Logistic regression is called a "linear model" because its decision boundary — the set of points where \(P(y=1)=0.5\) — is always a straight line (or flat hyperplane) in the space of the features you feed it. Feed it just \(x_1\) and \(x_2\) and it can only ever draw a straight dividing line between classes. That sounds like a hard limitation, but section 20 already showed the workaround for linear regression: engineer new, non-linear features from the ones you have, and let the "linear" model draw a straight line through the transformed feature space — which corresponds to a curved boundary back in the original space.

Concretely, PolynomialFeatures turns \([x_1, x_2]\) into something like \([x_1, x_2, x_1^2, x_1 x_2, x_2^2]\). Logistic regression then learns a decision boundary that's linear in these five features — but a line equation like \(w_1 x_1 + w_2 x_2 + w_3 x_1^2 + w_4 x_1 x_2 + w_5 x_2^2 + b = 0\), when plotted back in the original \((x_1, x_2)\) plane, is a conic section: it can be a circle, an ellipse, a parabola, or a hyperbola. That's enough to separate the classic case where one class forms a blob surrounded by a ring of the other class — something no straight line could ever do.

The same trick, twice. This is precisely the same move Section 28's kernel trick makes for SVMs and Section 20 made for linear regression: don't change the algorithm, change the features it sees. "Linear model" always means linear in its inputs — and you control what those inputs are.

Code — circular decision boundary with a Pipeline

from sklearn.preprocessing import PolynomialFeatures, StandardScaler
from sklearn.linear_model import LogisticRegression
from sklearn.pipeline import make_pipeline
from sklearn.datasets import make_circles

# classic "impossible for a straight line" dataset:
# one class is a disc, the other is a ring around it
X, y = make_circles(n_samples=500, noise=0.05, factor=0.4, random_state=42)

model = make_pipeline(
    PolynomialFeatures(degree=2, include_bias=False),  # adds x1^2, x1*x2, x2^2
    StandardScaler(),
    LogisticRegression()
)

model.fit(X, y)
print(model.score(X, y))   # near-perfect accuracy — the ring is now separable

# plain LogisticRegression() with no polynomial features would cap out
# around 50% accuracy here, since no straight line separates a disc from a ring
Trade-off to watch: higher degree values let the boundary get arbitrarily wiggly — and arbitrarily overfit, exactly as in Section 20's polynomial regression and Section 21's bias-variance tradeoff. Degree 2 or 3 handles most real curved boundaries; combine with regularization (the C parameter, next section) to keep it in check.

Logistic Regression Hyperparameters

Scikit-learn's LogisticRegression has more knobs than it looks like at first — it bundles regularization, the choice of penalty, and the optimizer itself into one constructor. Here's what actually matters in practice.

C — inverse regularization strength

Section 22 wrote regularized cost functions as "loss + \(\lambda \times\) penalty," where bigger \(\lambda\) means stronger regularization. Scikit-learn's logistic regression flips this convention: it uses \(C = 1/\lambda\). That means:

Small C (e.g. 0.01) → large effective \(\lambda\) → strong regularization → coefficients pushed hard toward zero → simpler, smoother boundary, higher bias.
Large C (e.g. 100) → small effective \(\lambda\) → weak regularization → the model is freer to fit training data closely → higher variance, risk of overfitting.

Mnemonic: C is a confidence knob — high C tells the optimizer "I trust the training data, fit it tightly"; low C tells it "be skeptical, stay conservative."

penalty — which regularizer

Same three options as Section 22's Ridge/Lasso/Elastic Net, applied to the log-loss instead of squared error: 'l2' (ridge-style, shrinks smoothly, default), 'l1' (lasso-style, can zero out coefficients — useful with many features, some irrelevant), 'elasticnet' (blend, needs an l1_ratio), and None (no regularization at all).

solver — the optimization algorithm, and which penalties it supports

Unlike linear regression's OLS, logistic regression's log-loss has no closed-form solution — it's always solved iteratively. Not every solver supports every penalty, which is the single most common source of a confusing sklearn error message here.

SolverSupportsWhen to use
lbfgsl2, NoneGood general-purpose default; handles multinomial softmax natively; fast on small/medium datasets
liblinearl1, l2Small datasets, especially with l1; does not support true multinomial softmax (falls back to one-vs-rest)
sagal1, l2, elasticnet, NoneLarge datasets, and the only solver that supports elasticnet; converges slower per-step but scales well

max_iter — give the optimizer room to converge

Since there's no closed form, sklearn iterates until the loss stops improving meaningfully or it hits max_iter steps (default 100). A "ConvergenceWarning" means it hit the cap before converging — the fix is usually to raise max_iter (e.g. to 1000+), scale your features (unscaled features slow convergence dramatically), or both.

class_weight='balanced' — for imbalanced classes

By default, every training example contributes equally to the loss. If 99% of your data is class 0 and 1% is class 1, the optimizer can get a very low average loss just by leaning heavily toward predicting class 0 always — it barely "notices" the minority class. Setting class_weight='balanced' automatically reweights each class's contribution to the loss inversely proportional to its frequency, so mistakes on the rare class cost proportionally more. This doesn't change the data, only how much each misclassification is penalized during training — pairs naturally with the precision/recall/F1 tools from Section 24, since accuracy alone is exactly the metric imbalance fools.

Code — a realistic, tuned setup

from sklearn.linear_model import LogisticRegression
from sklearn.model_selection import GridSearchCV

param_grid = {
    'C': [0.01, 0.1, 1, 10, 100],
    'penalty': ['l1', 'l2'],
}

grid = GridSearchCV(
    LogisticRegression(
        solver='saga',            # supports both l1 and l2
        max_iter=5000,            # give it room to converge
        class_weight='balanced'   # dataset has a rare positive class
    ),
    param_grid,
    scoring='f1',                 # imbalanced data -> don't optimize plain accuracy
    cv=5
)
grid.fit(X_train, y_train)

print(grid.best_params_)
best_model = grid.best_estimator_

Test Your Understanding

Hard

5 questions on Softmax Regression, polynomial features, and hyperparameters. Pick an answer for each, then check.

1. Why does softmax exponentiate the raw class scores before normalizing, instead of just normalizing the raw scores directly (dividing each by their sum)?

Explanation: Raw linear scores \(z_k\) can be any real number, including negative — dividing negative or mixed-sign numbers by their sum doesn't yield a valid probability distribution. \(e^{z}\) is always positive for any real z, and because exponential growth is convex, a score that's modestly higher than its rivals becomes disproportionately larger after exponentiating, giving softmax its "winner-take-most" character.

2. With exactly K=2 classes, how does softmax regression relate to standard binary logistic regression?

Explanation: softmax(z_1)/softmax(z_0) algebra reduces to a sigmoid function of (z_1 - z_0). Binary logistic regression is a more compact parameterization (one score instead of two) of exactly the same underlying model.

3. A dataset has one class forming a tight cluster completely surrounded by a ring of the other class. Plain logistic regression on the raw 2D features fits terribly. What's the most direct fix that keeps logistic regression as the model?

Explanation: This is the concentric-rings problem — no straight line separates a disc from a surrounding ring. Neither more iterations, a different solver, nor class weighting change the shape of the achievable boundary; only feeding the model non-linear features (like x1^2, x2^2) lets its linear boundary in the transformed space correspond to a circular boundary in the original space.

4. You set C=0.001 on a LogisticRegression model. What should you expect?

Explanation: sklearn's C is the inverse of the regularization strength lambda. A tiny C like 0.001 corresponds to a huge effective lambda — strong regularization, coefficients squeezed toward zero, a simpler and higher-bias but lower-variance model.

5. You want L1 regularization combined with an elastic-net-style blend on a large dataset. Which solver must you use?

Explanation: Of sklearn's solvers, only saga supports the elasticnet penalty (a blend of l1 and l2). lbfgs only supports l2/None, and liblinear only supports l1/l2 — neither can do the elasticnet blend.
