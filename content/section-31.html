Ensemble

Introduction — Bootstrap AGGregatING

Voting (previous page) combines different algorithms trained on the same data. Bagging flips that: it trains the same algorithm, over and over, on different random samples of the training data — then aggregates. "Bagging" is short for Bootstrap AGGregatING.

What is Bootstrap Sampling?

"Bootstrap sample" means: from your training set of N rows, randomly draw N rows with replacement. "With replacement" means after picking a row, you put it back in the pool before picking the next one — so the same row can be picked multiple times, and some rows won't be picked at all.

Example: dataset rows [A, B, C, D, E] (N=5). One bootstrap sample might be [A, A, C, D, D] — A and D each appear twice, B and E don't appear at all. Draw another bootstrap sample from the same original 5 rows and you might get [B, C, C, C, E] — a completely different mix. Each bootstrap sample is a slightly different "view" of the same underlying dataset.

The Bagging Procedure

  1. Step 1: From the original training set, draw a bootstrap sample (N rows, with replacement).
  2. Step 2: Train a base model (e.g. a Decision Tree) on that bootstrap sample.
  3. Step 3: Repeat steps 1–2 many times (e.g. 100 or 500 times) — each round draws a fresh bootstrap sample and trains a fresh model on it.
  4. Step 4 — Aggregate: for a new input, ask every trained model for its prediction, then combine them — majority vote for classification, average for regression.

The "Ask Many Slightly-Different Experts" Analogy

Imagine diagnosing a patient by asking 100 doctors — but instead of showing all 100 doctors the patient's entire medical history, you show each doctor a random subset of the patient's past test results (with some results repeated, some left out). Each doctor forms their own opinion from their own partial view. No single doctor sees the exact same data as another, so no single doctor's blind spot is shared by all the others. Averaging their diagnoses smooths out any one doctor's overreaction to a particular quirky test result. That's exactly what bagging does with models instead of doctors, and bootstrapped samples instead of partial test results.

Why Bagging Specifically Reduces Variance

Recall the Bias-Variance Tradeoff: a model's total expected error breaks into bias (error from wrong assumptions — underfitting) and variance (error from being overly sensitive to the specific training sample it happened to see — overfitting). A single unpruned Decision Tree has low bias (it can represent almost any decision boundary) but high variance — swap a handful of training rows and the tree it learns can look completely different.

Averaging (or voting among) many independently-trained high-variance models cancels out their individual, uncorrelated fluctuations — much like averaging many noisy thermometer readings gets you closer to the true temperature than trusting one reading. Mathematically, if you average \(m\) models each with variance \(\sigma^2\) and their errors were fully independent, the variance of the average would shrink to \(\sigma^2/m\). Bootstrapped training sets aren't fully independent (they're drawn from the same original data, so they overlap), so the reduction isn't quite that dramatic in practice — but the direction is real and strong: bagging trades a little bit of correlation-limited variance reduction for a lot of stability, while barely touching bias. That's why bagging shines specifically with high-variance, low-bias base learners.

Classification

Bagging Classifiers

For classification, each bootstrapped model casts one vote for a class label, and the ensemble's prediction is the majority vote across all models — the same aggregation rule as hard voting, except here every "voter" is the same algorithm trained on a different resample, rather than different algorithms trained on the same data.

Code — BaggingClassifier

from sklearn.ensemble import BaggingClassifier
from sklearn.tree import DecisionTreeClassifier
from sklearn.model_selection import train_test_split

X_train, X_test, y_train, y_test = train_test_split(X, y, test_size=0.2, random_state=1)

bag_clf = BaggingClassifier(
    estimator=DecisionTreeClassifier(),  # base learner — unpruned tree, high variance
    n_estimators=500,       # how many bootstrapped models to train
    max_samples=1.0,        # fraction (or count) of rows drawn per bootstrap sample — 1.0 = N rows
    bootstrap=True,         # sample rows WITH replacement (this is what makes it "bagging")
    n_jobs=-1,               # train the 500 trees in parallel across CPU cores
    random_state=1
)
bag_clf.fit(X_train, y_train)
print("Bagged accuracy:", bag_clf.score(X_test, y_test))

# compare against a single tree to see the variance-reduction effect
single_tree = DecisionTreeClassifier()
single_tree.fit(X_train, y_train)
print("Single tree accuracy:", single_tree.score(X_test, y_test))
ParameterMeaning
n_estimatorsHow many base models to train and aggregate. More estimators → smoother, more stable ensemble, but diminishing returns and more compute. Bagging does not overfit as you increase this — it just plateaus.
max_samplesHow many rows each bootstrap draw pulls (as a fraction of N or an absolute count). Default 1.0 (N rows, with replacement — so ~63% unique rows per sample, see the Random Forest page's OOB section for why). Lower values increase per-model diversity (more variance reduction) but each model sees less data (can raise bias slightly).
bootstrapWhether sampling is done with replacement. True = real bagging. Setting it False turns this into "pasting" — sampling without replacement — which loses the with-replacement diversity bagging depends on.
Regression

Bagging Regressors

For regression, there's no class to vote on, so aggregation is simply averaging the numeric predictions produced by every bootstrapped model — identical in spirit to VotingRegressor's averaging rule from the previous page.

Code — BaggingRegressor

from sklearn.ensemble import BaggingRegressor
from sklearn.tree import DecisionTreeRegressor

bag_reg = BaggingRegressor(
    estimator=DecisionTreeRegressor(),
    n_estimators=200,
    max_samples=0.8,     # each tree sees 80% (with replacement) of the training rows
    bootstrap=True,
    n_jobs=-1,
    random_state=1
)
bag_reg.fit(X_train, y_train)

y_pred = bag_reg.predict(X_test)   # = average of all 200 trees' predictions

from sklearn.metrics import mean_squared_error
print("Bagged RMSE:", mean_squared_error(y_test, y_pred, squared=False))

Key Takeaways

  • Bagging = Bootstrap sampling + training many models + Aggregating their predictions.
  • Works with any base learner, but shines with high-variance learners — unpruned Decision Trees are the textbook example.
  • Classification aggregates by majority vote; Regression aggregates by averaging.
  • Primarily targets variance reduction, not bias reduction — it won't fix an underfitting model.
  • Training is fully parallel — every bootstrapped model is independent, unlike boosting (next-but-one page).
  • Bagging applied specifically to Decision Trees, plus one more trick (random feature subsampling), is exactly what Random Forest is — covered next.

Test Your Understanding

Hard

5 questions on Bagging. Pick an answer for each, then check.

1. What specifically makes bootstrap sampling "with replacement" important for bagging's effectiveness?

Explanation: Sampling with replacement is what makes each bootstrap draw a genuinely different mix of rows (some repeated, some missing) even though all draws come from the same original dataset — that diversity across samples is what makes the resulting models different enough from each other for aggregation to help. Without replacement, and with max_samples=1.0, every "sample" would just be the original dataset itself.

2. Why does the text recommend high-variance, low-bias base learners (like unpruned Decision Trees) for bagging, rather than a high-bias learner like a heavily-regularized Linear Regression?

Explanation: Averaging/voting cancels out the noisy, sample-dependent part of a model's error (variance) but does nothing to correct a systematically wrong assumption (bias) — if every bootstrapped model shares the same underlying bias, averaging them still leaves that bias. So bagging pays off most when the base learner has plenty of variance to shed and little inherent bias, which describes unpruned trees well.

3. In BaggingClassifier, what does setting bootstrap=False actually change about the algorithm?

Explanation: bootstrap=True is literally what makes bagging "bagging" — sampling rows with replacement. Turning it off switches to sampling without replacement (a technique sometimes called pasting), which changes the diversity characteristics of the ensemble; it doesn't touch the voting rule or parallelism settings.

4. You train a BaggingRegressor with n_estimators=10 and get validation RMSE of 4.2. You retrain with n_estimators=500 (everything else identical) and get RMSE 3.9, then n_estimators=5000 gives RMSE 3.88. What does this pattern illustrate?

Explanation: Because bagged models are trained independently, adding more of them does not cause overfitting the way adding more boosting rounds can — but the variance reduction from averaging follows diminishing returns (the correlated portion of the variance never goes away, no matter how many models you add), which is exactly the plateau shown by RMSE 4.2 → 3.9 → 3.88.

5. Which best describes the relationship between Bagging and Random Forest (the next page)?

Explanation: Random Forest = BaggingClassifier/Regressor with Decision Trees as the base learner, plus one extra source of randomness: at each split, only a random subset of features is considered. Both remain fully parallel/independent in how their trees are trained — sequential training is boosting's defining trait, not Random Forest's.
