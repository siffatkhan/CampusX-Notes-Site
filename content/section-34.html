34. Bagging vs Boosting

Parallel independence vs sequential correction · variance vs bias · a side-by-side comparison

Extended notes — this topic isn't covered in the CampusX playlist notes this site is based on. Written from scratch to continue the curriculum, in the same style as the rest of the site.
Concept

The Core Structural Difference

You've now seen one full example of each family: Bagging/Random Forest (parallel) and AdaBoost (sequential). Both are "ensembles of many models," but the two families disagree on a single, fundamental question — do the base models know about each other?

Bagging — parallel

Three trees trained at once, independently, on different bootstrap samples — none aware of the others.

Boosting — sequential

Each model trained only after seeing where the previous one failed — a strict chain.

Illustrative aid — generated for this site.

Bagging: independent models, bootstrapped rows, combined by simple averaging/voting. Boosting: dependent models, each one correcting the previous ensemble's specific errors, combined by a weighted sum where better models earn more say. That single design choice cascades into almost every other difference between the two families.

Concept

What Each Is Best At

Bagging reduces VARIANCE

Bagging shines when your base learner is already low-bias but high-variance and unstable — the textbook example is a deep, fully-grown decision tree, which changes a lot if you perturb the training data slightly. Averaging many independent, noisy-but-unbiased estimates cancels out their individual noise (this is exactly the ρσ² + (1-ρ)σ²/n math from the Random Forest page), while barely touching bias. Bagging can't fix a base learner that's fundamentally too simple to capture the pattern — averaging ten straight lines still gives you a straight line.

Boosting reduces BIAS

Boosting shines when your base learner is high-bias but low-variance — a stump, or any deliberately simple model that consistently misses the same kind of pattern. By training each new model specifically to correct what's still being missed, boosting can turn a whole sequence of weak, biased learners into a single strong, low-bias one. The cost: boosting is more prone to overfitting if you run it for too many rounds or with too high a learning rate, and it's more sensitive to noisy data and outliers — since it keeps chasing whatever is still hard to fit, a mislabeled point can absorb disproportionate attention round after round.

A useful rule of thumb

Ask "is my base model overfitting (high variance) or underfitting (high bias)?" A single deep tree overfits — bag it. A single stump underfits badly — boost it. Using the wrong family doesn't just fail to help; bagging a stump barely improves it (averaging weak, similar, high-bias stumps is still high-bias), and boosting an already-deep, low-bias tree mostly just adds overfitting risk without much bias left to remove.

Side-by-Side Comparison

AspectBaggingBoosting
Training styleParallel — models trained independently on bootstrap samplesSequential — each model trained after, and dependent on, the previous ones
Error component reducedVarianceBias (also some variance in practice)
Sensitivity to outliers/noiseLow — one bad sample rarely dominates any single tree, and its effect is averaged awayHigher — hard/mislabeled points get progressively more weight/focus round after round
Parallelizability / speedFully parallelizable — all base models can train simultaneouslyInherently sequential — round t needs round t−1's result, harder to parallelize across rounds
Typical base learnersDeep/unpruned trees — low bias, high varianceShallow trees / stumps — high bias, low variance
Overfitting riskLow — adding more base models rarely hurts, it just plateausHigher — too many rounds / too high a learning rate can overfit; needs tuning or early stopping
Example algorithmsBagging, Random ForestAdaBoost, Gradient Boosting, XGBoost, LightGBM, CatBoost

Both families work for classification and regression — the parallel-vs-sequential design choice, not the task type, is what defines them. The next two pages go deeper into the boosting side: Gradient Boosting generalizes AdaBoost's idea from "reweight samples" to "fit residuals" using calculus, and XGBoost turns that into a highly engineered, regularized, production-grade implementation.

Test Your Understanding

Hard

5 questions on Bagging vs Boosting. Pick an answer for each, then check.

1. You have a single decision stump (depth 1) that badly underfits your data. Which ensemble approach is most likely to meaningfully fix this, and why?

Explanation: Underfitting = high bias. Bagging attacks variance, not bias — averaging many similarly-biased stumps stays biased. Boosting attacks bias directly by sequentially correcting residual errors, which is exactly what's needed here.

2. Your dataset has several mislabeled rows you haven't cleaned yet, and you need to train a robust model quickly. Which is the more cautious choice, and why?

Explanation: Boosting's reweighting loop keeps increasing attention on consistently-wrong points — including mislabeled ones — round after round. Bagging's independent trees have no such reinforcing mechanism, making it comparatively more robust when noisy/mislabeled data is present.

3. You have a 64-core machine and want to minimize wall-clock training time. All else equal, which ensemble family exploits that hardware better, and why?

Explanation: Bagging's defining property is that its base models have no dependency on each other, so they're embarrassingly parallel. Boosting's round t strictly requires round t−1's output, which fundamentally limits parallelizing across rounds (though modern implementations like XGBoost do parallelize the work within building a single tree).

4. Which statement correctly describes overfitting risk as you add more base models, for each family?

Explanation: Averaging more independent bootstrap models keeps reducing variance and then plateaus — it doesn't meaningfully re-increase overfitting. Boosting keeps trying to reduce remaining training error every round, and if left unchecked (too many rounds, too high a learning rate) it will eventually start fitting noise.

5. Which pairing of (base learner property) → (recommended ensemble family) is correct?

Explanation: Match the ensemble's strength to the base learner's weakness: bagging cancels variance, so pair it with a low-bias/high-variance learner (deep tree); boosting reduces bias, so pair it with a high-bias/low-variance learner (stump). This is the rule-of-thumb from this page's "What Each Is Best At" section.
