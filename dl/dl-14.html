14. Recurrent Neural Networks (RNN)

Why feedforward nets fail on sequences · the recurrent hidden state · unrolling through time · backpropagation through time · why RNNs forget

RNN

Why Plain Feedforward Networks Fail on Sequences

Every network you've seen so far in this track — the MLP, the CNN — is a feedforward network. Information travels in one direction only: input → hidden layers → output, start to finish, in a straight line. Critically, once one prediction is made, the network throws everything away and starts completely fresh for the next input. It has no memory of anything it processed before.

That's a fine assumption for tabular data or images, where each row or each image genuinely is independent of the others. But it breaks down the moment order carries meaning. Consider feeding the words of a sentence into a plain ANN one at a time: it has no built-in way to remember that the word it just saw was "not," so it cannot connect that to the word "good" arriving right after — "not good" and "good," in isolation, look unrelated to a network with no memory. On top of that, ANNs expect a fixed-size input vector, but sentences vary in length (5 words vs. 20 words) — forcing ANNs onto text means resorting to hacks like zero-padding every sentence out to some maximum length, which wastes computation on meaningless padding, turns a sequence problem into an awkward fixed-size prediction problem, and still totally disregards the sequence — the same set of words shuffled into a different order would look identical to the network, even though the meaning (and therefore the "sequence" of information) is completely lost.

The core distinction

MLP and CNN are feed-forward networks — information moves from start to end linearly, and every prediction is computed from scratch. In an RNN, information in the hidden layer loops back on itself, timestep after timestep, so each new prediction is informed by everything the network has already seen in that sequence. That loop is the single architectural idea that makes RNNs fundamentally different.

This is why RNNs exist specifically for time-series, sequential, and ordered data — anything where "what came before" changes the meaning of "what comes now": stock prices over time, sensor readings, audio, and above all, text. RNNs are a type of sequential model, and they're mostly used in NLP because they're so well suited to textual data, where word order is the entire point.

RNN

The Recurrent Hidden State — the Network's Memory

At every timestep \(t\), an RNN does something an ANN never does: it takes two inputs — the current input \(x_t\) and the previous hidden state \(h_{t-1}\) — combines them, and produces a new hidden state \(h_t\). That \(h_t\) is a running summary of "everything relevant seen so far," and it gets carried forward to the next timestep as part of its input. This is exactly the "loop back" from the box above, written out mathematically:

$$ h_t = \tanh\big(W_{hh}\,h_{t-1} + W_{xh}\,x_t + b\big) $$

Optionally, at any timestep the network can also emit an output \(y_t\), computed from the current hidden state:

$$ y_t = f\big(W_{hy}\,h_t + b_y\big) $$

Notice something important: \(W_{hh}\), \(W_{xh}\), and \(b\) don't change from timestep to timestep — the same weights are reused at every single position in the sequence. This is precisely why it's called a recurrent network: the hidden layer recurs — reoccurs — again and again, fed new input each time, but always through the identical set of weights. At the very first timestep, there is no "previous" hidden state to feed in yet, so by convention \(h_0\) is initialized to a vector of zeros, purely to keep the computation consistent across the very first step and every step after it.

Worked walkthrough — processing "I am fine"

Feed the sentence in one word at a time. At each step the RNN cell combines the current word with whatever it's remembered so far, and updates its memory:

Timestep Input word What the cell does Resulting memory
t = 1"I"Combines "I" with the blank starting memory \(h_0 = 0\)Updates to \(h_1\)
t = 2"am"Combines "am" with \(h_1\) (which already "contains" a trace of "I")Updates to \(h_2\)
t = 3"fine"Combines "fine" with \(h_2\) (which carries traces of both "I" and "am")Updates to \(h_3\)

By the time the RNN reaches "fine," \(h_3\) is a compressed summary of the whole phrase so far — not just the last word in isolation. That's the entire trick: memory accumulates one word at a time instead of being recomputed from nothing.

How data is actually shaped for an RNN. A single sequence is fed as (timesteps, input_features) — e.g. (3, 5) for a 3-word sentence where each word is a 5-dimensional vector. Keras's SimpleRNN layer expects a whole batch at once, shaped (batch_size, timesteps, input_features) — e.g. (3, 4, 5) means "3 sentences/documents, each 4 words long, each word a 5-dim vector," all processed together.

Unrolling the RNN Through Time

A single RNN cell is easiest to understand if you "unroll" it — draw a fresh copy of the same cell for every timestep, connected by the hidden state passing from one to the next. Every one of these copies is the same cell, sharing the exact same weights; drawing it unrolled is purely a way to visualize how information flows forward through time.

Illustrative aid — generated for this site to visualize the architecture.

Read this diagram left to right, exactly as time passes: each box is the identical RNN cell, taking its own word (\(x_t\), fed in from below) plus the memory handed to it from the previous cell (\(h_{t-1}\), arriving from the left). It blends the two together into a new memory (\(h_t\)) which is passed rightward to the next cell, and — depending on the task — can also produce an output (\(y_t\), shown dashed since not every RNN needs an output at every single step).

Five RNN Architecture Shapes

Not every sequence task wants an output at every timestep. Whether you feed one input or many, and whether you want one output or many, defines a distinct RNN "shape":

Shape Pattern Example
One-to-Oneimage → classNot really a recurrent problem — no sequence involved at all.
One-to-Manyimage → sequencePhoto → "A dog is running." — image captioning.
Many-to-Onesequence → single label"I love this phone." → Positive — sentiment analysis.
Many-to-Many (variable length)sequence → sequence, different lengths"I love AI" → "J'aime l'IA" — machine translation.
Many-to-Many (same length)sequence → sequence, aligned position-by-positionJohn / lives / in / Paris → Name / Verb / Prep / Location — Named Entity Recognition, POS tagging.

The "variable length" many-to-many case — input and output sequences of different lengths, like translation — is genuinely hard, and gets its own dedicated architecture two pages from now (Encoder-Decoder).

Backpropagation Through Time (BPTT)

Training an ordinary MLP means backpropagating the error through its layers. Training an RNN means backpropagating the error through its layers and through time — because the unrolled diagram above is, for the purposes of the gradient computation, just a very deep feedforward network, where "depth" is however many timesteps long the sequence is. This is called Backpropagation Through Time.

Concretely: the error computed at the final timestep has to flow backward through every single previous cell, all the way back to \(t=1\), because every hidden state \(h_t\) depends on \(h_{t-1}\), which depends on \(h_{t-2}\), and so on. At every one of those steps back, the gradient gets multiplied again by the same recurring weight matrix \(W_{hh}\). A 20-word sentence isn't backpropagated through 20 timesteps' worth of independent weights — it's the same weight matrix multiplied into the gradient chain 20 times over.

Repeatedly multiplying by the same matrix, over and over, is exactly the kind of operation that either shrinks a number toward zero or blows it up toward infinity, depending on whether that matrix's values are smaller or larger than 1. That's why RNNs are so much more prone to vanishing and exploding gradients than a normal feedforward network of similar size — normal backprop multiplies through a handful of distinct layers; BPTT multiplies through potentially hundreds of repeated copies of the same weights.

RNN

RNN's Two Core Limitations

RNNs are conceptually the right tool for sequential data, but in practice, plain ("vanilla") RNNs are rarely used directly, because they suffer from two closely-related problems — both a direct consequence of BPTT above.

1. Vanishing / exploding gradients

Because BPTT multiplies the same weight matrix into the gradient at every timestep, long sequences push that product toward one of two extremes. If the repeated multiplication shrinks the gradient toward zero, this is the vanishing gradient problem — early timesteps barely get updated at all, since almost no error signal survives the trip backward to reach them. If it instead grows without bound, this is the exploding gradient problem — the long-term dependency's gradient becomes so large it dominates and destabilizes the whole update, a "stagnated gradient" that swamps everything else.

Cures for vanishing gradients: ReLU-family activations instead of tanh/sigmoid, better weight initialization (e.g. initializing close to an identity matrix), skip-connection RNN variants, or simply moving to LSTM.
Cures for exploding gradients: gradient clipping (capping the gradient's magnitude before the update is applied), a more conservative/controlled learning rate, or again, LSTM.

2. Only short-term memory

The practical consequence of vanishing gradients is that an RNN's hidden state is dominated by recent timesteps and effectively forgets information from many steps back — it has only short-term memory (STM). Imagine a sentence: "I grew up in France, went to school there, worked there for a decade... and I speak fluent ___." The word the model needs ("French") depends on context from way back at the start of the sentence — but by the time the RNN reaches the blank, that early context has been diluted almost to nothing by dozens of intervening updates. This is exactly the long-range dependency problem: the further back the relevant information sits, the less of it survives.

Both problems point at the same root cause: a plain RNN has no dedicated mechanism for preserving information over long stretches — everything is squeezed through the same tiny hidden state, overwritten a little more at every timestep. Fixing this properly requires a structural change to the cell itself, giving it an explicit long-term memory channel alongside its short-term one. That's exactly what LSTM — the subject of the next page — was built to do.

Test Your Understanding

Hard

5 questions on RNNs. Pick an answer for each, then check.

1. What is the single architectural feature that separates an RNN from an MLP/CNN?

Explanation: MLPs/CNNs are strictly feed-forward — no memory of prior inputs. An RNN's hidden state loops back into itself at the next timestep, giving it memory of everything processed so far in the sequence.

2. At timestep t, what two things does an RNN cell combine to produce the new hidden state h_t?

Explanation: h_t = tanh(W_hh · h_(t-1) + W_xh · x_t + b) — the current input and the previous hidden state are combined through shared weights to produce the new memory.

3. In an unrolled RNN diagram, why do all the timestep "boxes" share the exact same weights?

Explanation: Unrolling is a visualization device. There is only one RNN cell and one set of weights; the same weights are applied again and again as the sequence progresses — that repetition is also exactly what causes BPTT's vanishing/exploding gradient issue.

4. Why does Backpropagation Through Time (BPTT) make vanishing/exploding gradients worse than in a typical feedforward network?

Explanation: Because every timestep reuses the same W_hh, backpropagating through T timesteps multiplies the gradient by that same matrix T times — repeated multiplication shrinks or blows up the value far more severely than the handful of distinct layer-to-layer multiplications in a normal feedforward net.

5. A vanilla RNN reads a 40-word paragraph and needs a detail mentioned in word 2 to correctly predict word 40. What typically happens, and why?

Explanation: This is the RNN's defining weakness: it has only short-term memory. Over many timesteps, early information gets diluted almost to nothing — the long-range dependency problem, a direct consequence of vanishing gradients, and exactly what motivates LSTM.
