15. LSTM & GRU

Giving RNNs a long-term memory · the forget/input/output gates · the LSTM cell · GRU, the simpler cousin

LSTM

Why LSTM — Giving the Network a Second, Longer Memory

The previous page ended on RNN's core weakness: it only has short-term memory (STM) — everything gets squeezed through one hidden state that's overwritten a little more at every timestep, so old information fades out. Long Short-Term Memory (LSTM) networks were built specifically to fix this. (For a deeper visual walkthrough than these notes, Christopher Olah's classic post Understanding LSTM Networks is the canonical reference this material draws from.)

The core idea, in one line: RNN has just STM, while LSTM adds a genuine LTM (long-term memory) cell alongside it. LSTM keeps two separate running values instead of one — a cell state \(C_t\) (the long-term memory) and a hidden state \(h_t\) (the short-term memory, same role as a plain RNN's \(h_t\)) — and it adds machinery whose entire job is to manage communication between those two memories: what long-term information to keep, what to add, and what to actually expose as output right now.

Think of the cell state as a conveyor belt running along the top of the whole sequence: information can ride on it from the very first timestep to the very last, largely untouched, unless something deliberately decides to remove or add to it. That's a fundamentally different design from a plain RNN, where every timestep fully recomputes the memory from scratch — here, the default behavior is to preserve, and change only happens through explicit, learned gates.

Inputs and outputs of one LSTM cell, at timestep t. Inputs: the previous cell state \(C_{t-1}\) (long-term memory), the previous hidden state \(h_{t-1}\) (short-term memory), and the current input \(x_t\). Outputs: an updated cell state \(C_t\) and an updated hidden state \(h_t\). Both \(C_t\) and \(h_t\) are vectors of the same dimension — a rule that holds throughout the cell — while \(x_t\) can be a different dimension entirely.
LSTM

The Three Gates

Every gate in an LSTM is, mechanically, nothing exotic — it's just a small neural network layer (a set of nodes, weights, and a bias) with a sigmoid activation. Sigmoid squashes every value to somewhere between 0 and 1, and that output is used as a "how much to let through" dial: 0 means block everything, 1 means let everything through, and anything in between lets through that fraction. The three gates only differ in what they read and where their 0–1 output gets applied.

Forget Gate — "should I keep remembering this old information?"

Looks at the current input \(x_t\) and the previous hidden state \(h_{t-1}\), and decides what to throw away from the long-term cell state. It outputs a vector \(f_t\) (same shape as \(C_{t-1}\)), and the actual "forgetting" happens by pointwise-multiplying: \(C_{t-1} \odot f_t\). Wherever \(f_t\) is close to 0, that piece of the old cell state gets wiped out; wherever it's close to 1, that piece survives untouched.

Input Gate — "how much of this new information is worth remembering?"

Works in two stages. First, a tanh layer looks at \(x_t\) and \(h_{t-1}\) and proposes a candidate cell state \(\tilde C_t\) — potentially important new information that could be added to the long-term memory. Second, a sigmoid layer computes the input gate value \(i_t\), which decides how much of that candidate is actually worth keeping. The filtered result, \(i_t \odot \tilde C_t\), is added onto the already-forgotten cell state to produce the new cell state.

Output Gate — "what part of the memory should I expose right now?"

Computes an output value \(o_t\) from \(x_t\) and \(h_{t-1}\), same as the other two gates. This is combined with the freshly updated cell state \(C_t\), which is first squashed through tanh (to bound it between −1 and 1), then filtered pointwise by \(o_t\). The result is the new hidden state \(h_t\) — the short-term memory / output that gets passed to the next timestep, and optionally used as this timestep's prediction.

$$ f_t = \sigma(W_f[h_{t-1}, x_t] + b_f) \qquad C_t = f_t \odot C_{t-1} + i_t \odot \tilde C_t $$ $$ i_t = \sigma(W_i[h_{t-1}, x_t] + b_i), \quad \tilde C_t = \tanh(W_C[h_{t-1}, x_t] + b_C) $$ $$ o_t = \sigma(W_o[h_{t-1}, x_t] + b_o) \qquad h_t = o_t \odot \tanh(C_t) $$

\([h_{t-1}, x_t]\) means the two vectors concatenated together and fed into that gate's own fully-connected layer; \(\odot\) is the pointwise (element-by-element) product — two vectors of identical shape multiplied position-by-position, producing another vector of that same shape. \(\sigma\) is sigmoid.

A concrete size example. Suppose the hidden/cell state is 3-dimensional and the input \(x_t\) is 4-dimensional. Each gate first concatenates \([h_{t-1}, x_t]\) into a 7-dimensional vector, then runs it through a fully-connected layer with 3 nodes (one output value per cell-state dimension) — that's \(7 \times 3 = 21\) weights, plus 3 biases (one per node), producing the 3-dimensional gate vector (\(f_t\), \(i_t\), or \(o_t\)). Every gate — and the candidate \(\tilde C_t\) — is sized this same way, always matching the cell/hidden state's dimensionality.

Anatomy of One LSTM Cell

Illustrative aid — generated for this site to visualize the architecture.

Read the top horizontal line as the long-term memory conveyor belt: \(C_{t-1}\) enters on the left, gets partly erased by the forget gate's multiply, gets new information added by the input gate's addition, and leaves as \(C_t\) on the right. The bottom line is the short-term hidden state, flowing the same way. All three gates sit below, each reading the incoming \(h_{t-1}\) and \(x_t\) to decide how much they should influence the cell state or the final output — the output gate is what taps the freshly-updated \(C_t\) (through a tanh squash) to actually produce \(h_t\).

LSTM

The Cost of All This — Training Time

All of this extra machinery — three gates, each its own small neural network layer, plus the candidate cell state computation — is what solves the long-range dependency problem. But it isn't free: the LSTM's architecture is considerably more complex than a plain RNN cell, meaning more parameters to learn and more computation per timestep. In practice, this means LSTM's training time is a lot longer than a comparably-sized plain RNN. That extra cost is exactly the gap GRU was designed to close.

GRU

GRU — LSTM's Simpler Cousin

If LSTM already solves the vanishing-gradient / long-range-dependency problem, why invent yet another architecture? Because LSTM's complexity has a real cost — slow training — and the Gated Recurrent Unit (GRU) was designed to keep most of LSTM's benefit while trimming the architecture down to something simpler and faster to train.

GRU makes two structural simplifications. First, instead of three gates, it has only two: a Reset Gate and an Update Gate — conceptually merging LSTM's separate forget-gate and input-gate jobs into one combined update-gate decision. Second, GRU drops the separate cell state entirely: there is no distinct long-term-memory channel — long-term and short-term context are both carried in a single hidden state \(h_t\). Fewer gates and one fewer memory channel together mean meaningfully fewer parameters, which is exactly why GRU trains faster.

Reset Gate rₜ

Looks at the current input and the previous hidden state, and decides how much of the past hidden state to "reset" (forget) when forming this timestep's candidate — i.e. how relevant the old memory still is for what's being computed right now.

Update Gate zₜ

Decides the final blend: how much of the new candidate hidden state to mix in versus how much of the old hidden state to simply carry forward unchanged. This single gate is doing the combined job LSTM splits across its forget and input gates.

$$ r_t = \sigma(W_r[h_{t-1}, x_t]) \qquad \tilde h_t = \tanh(W_h[r_t \odot h_{t-1},\, x_t]) $$ $$ z_t = \sigma(W_z[h_{t-1}, x_t]) \qquad h_t = (1-z_t)\odot h_{t-1} + z_t \odot \tilde h_t $$

Read the last line carefully — it's the heart of GRU: the new hidden state is a weighted mix between the old hidden state \(h_{t-1}\) and the candidate hidden state \(\tilde h_t\), with the update gate \(z_t\) controlling the mix. When \(z_t \to 0\), the cell essentially ignores the new candidate and just keeps carrying the old memory forward — a direct, low-effort route for long-term information to survive, similar in spirit to LSTM's conveyor belt, but achieved with one gate and one state instead of three gates and two states.

Because of its lighter weight and faster training, GRU is commonly reached for in tasks like text generation, where training speed and a smaller parameter count are especially valuable.

Bi-RNN

A Quick Aside — Bidirectional RNN

Everything so far reads a sequence strictly left to right — each output depends only on past input. But sometimes a word's meaning depends on words that come after it. Take Named Entity Recognition on the sentence "I love Amazon": at the point of reading "Amazon," a purely left-to-right model can't tell whether this refers to the river or the company — that only becomes clear from a later phrase like "...it's a great website," which reveals the future context needed to correctly label the past word.

A Bidirectional RNN fixes this by running two separate RNNs over the same sequence — one reading forward (left to right), one reading backward (right to left) — and concatenating their outputs at each position. The same idea applies equally to LSTM and GRU cells, giving BiLSTM and bidirectional GRU; BiLSTM is the one used most often in practice.

Applications: Named Entity Recognition, POS tagging, machine translation, sentiment analysis, and time-series forecasting (e.g. stock price prediction), wherever full-sequence context genuinely helps.
Drawbacks: extra architectural complexity (two RNNs instead of one), and it fundamentally requires the entire sequence up front — it cannot be used in real-time/streaming settings where future input isn't available yet.

Test Your Understanding

Hard

5 questions on LSTM & GRU. Pick an answer for each, then check.

1. What is the fundamental structural addition LSTM makes over a plain RNN?

Explanation: RNN has only short-term memory (the hidden state). LSTM adds a cell state — the long-term memory "conveyor belt" — and three gates that manage what gets removed, added, and exposed from it.

2. A gate's sigmoid output is close to 0 for a particular vector position. What does that mean?

Explanation: Sigmoid gate outputs act as a 0–1 "how much to let through" dial. Close to 0 blocks that value (multiplying by ~0 zeroes it out); close to 1 lets it through essentially unchanged.

3. In the LSTM equations, which gate's output is used to filter the candidate cell state before it's added into the cell state?

Explanation: Cₜ = fₜ ⊙ Cₜ₋₁ + iₜ ⊙ C̃ₜ. The forget gate filters what survives from the old cell state; the input gate filters how much of the new candidate actually gets added.

4. What are GRU's two structural simplifications relative to LSTM?

Explanation: GRU merges LSTM's forget+input gates into a single update gate (plus a reset gate), and merges the cell state and hidden state into one — fewer parameters, faster training.

5. Why does a Bidirectional RNN help with "I love Amazon... it's a great website" but a plain left-to-right RNN struggles?

Explanation: The disambiguating context ("website") comes after "Amazon." A unidirectional RNN has no access to future tokens at the point it processes "Amazon"; the backward-reading RNN in a BiRNN does, and its output is concatenated with the forward pass.
