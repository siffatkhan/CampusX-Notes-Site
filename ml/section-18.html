Day 47

Principal Component Analysis (PCA) — Geometric Intuition

PCA is an unsupervised machine learning technique, having just input, no output. PCA can transform higher-dimensional data into lower-dimensional data while keeping the core essence of the data.

PCA Benefits

  • Data size reduction, resulting in faster execution of algorithms
  • Visualization in the needed dimension

Feature Selection vs Feature Extraction — the intuition

Feature selection is keeping only those columns that are important for predicting outputs. If we don't know which column is more necessary, we should project the data onto a scatter plot and check the spread/distance: whichever projection has a lengthier spread — bigger variance — we select those columns.

If we come across a set of columns that has roughly equal variance, we use a feature extraction technique instead. For example: rooms and washrooms are both important for predicting the price of a home, so we can't just remove one column — instead we make a new column, house_size, that predicts the price.

The number of principal components is always less than n, the number of original features in the data.

Why variance, not mean?

Formula: \( (x - \bar{x})^2 / n \). Spread is not variance, but spread is directly proportional to variance. We must maximize variance so as not to disturb the relationship between data points when transforming higher-dimensional data to lower dimension.

EXTRA — Mean, Variance, Covariance, and Eigenvectors, built up from scratch
1. Mean (center of data)

Mean is the average of values.

$$ \text{mean} = \frac{x_1 + x_2 + \dots + x_n}{n} $$

Example: data [2, 4, 6] → mean = (2 + 4 + 6) / 3 = 4.

Intuition: mean is the center point of your data. Think of placing weights on a rod — mean is the balance point.

2. Variance (spread of data)

Variance tells how far values are from the mean.

$$ \text{variance} = \text{average of } (x_i - \text{mean})^2 $$

Example: data [2, 4, 6], mean = 4. Deviations: (2−4)² = 4, (4−4)² = 0, (6−4)² = 4. Variance = (4 + 0 + 4) / 3 = 2.67.

Intuition: low variance → data is tight. High variance → data is spread out.

3. Standard Deviation (SD)

SD = square root of variance.

$$ SD = \sqrt{\text{variance}} $$

Example: SD = √2.67 ≈ 1.63.

Why SD? Variance is squared, so its units become weird. SD brings it back to the original scale — it's the average distance from the mean.

4. From 1D to 2D (important jump)

Now data has 2 features, e.g. Height and Weight. Each point = (x, y). Now we care about spread in x, spread in y, and the relationship between x and y. This leads to covariance.

5. Covariance (relationship between features)

Covariance measures how two variables move together.

$$ \text{cov}(x,y) = \text{average of } (x_i - \text{mean}_x)(y_i - \text{mean}_y) $$

Intuition: positive → both increase together. Negative → one increases, the other decreases. Zero → no relation.

6. Covariance Matrix

For 2D:

$$ \begin{bmatrix} \text{var}(x) & \text{cov}(x,y) \\ \text{cov}(y,x) & \text{var}(y) \end{bmatrix} $$

This matrix summarizes spread and direction.

7. Eigenvectors and Eigenvalues

Now comes the core idea. Given the covariance matrix, we extract eigenvectors (directions) and eigenvalues (importance of those directions).

7.1 Eigenvectors (directions). An eigenvector is the direction in which data varies most — the direction where data points spread out the most. Think: the data cloud is tilted, and the eigenvector tells you "this is the main direction of spread."

7.2 Eigenvalues (magnitude). An eigenvalue tells you how much variance exists along that direction. Large eigenvalue → important direction. Small eigenvalue → less important.

Simple analogy

Imagine a stretched ellipse: the long axis is the major direction → high variance → big eigenvalue. The short axis is the minor direction → low variance → small eigenvalue. Eigenvectors = axes directions, eigenvalues = axis lengths.

8. Visual intuition

Data is like a tilted cloud. Normal axes (x-axis, y-axis) don't align with it. Eigenvectors rotate the axes to align with the data.

9. Now connect everything to PCA

PCA's goal: reduce dimensions (columns) but keep maximum information. It uses scikit-learn internally, but the concept is pure math.

Step-by-step PCA flow:

  1. Mean center data — subtract the mean from every point, so data is centered at the origin
  2. Compute covariance matrix — captures spread and relationships
  3. Compute eigenvectors and eigenvalues from the covariance matrix — eigenvectors → directions of max variance, eigenvalues → how much variance
  4. Sort eigenvalues (descending), pick top k — e.g. 2D → reduce to 1D → pick the largest eigenvalue's direction
  5. Project data onto the selected eigenvectors — this gives reduced dimensions with maximum preserved information
10. Final connection (everything together)
  • Mean → centers data
  • Variance → measures spread
  • Covariance → shows relationships
  • Covariance matrix → full structure
  • Eigenvectors → best directions
  • Eigenvalues → importance of directions
  • PCA → selects top directions and projects data
11. One-line intuition

PCA finds the direction where your data spreads the most and keeps that, ignoring the rest.

12. Real-world intuition

Think of shadows: a 3D object casts a 2D shadow. You choose the angle that preserves the most shape. That angle = eigenvector; its importance = eigenvalue.

Day 48

Principal Component Analysis (PCA) — Problem Formulation & Code

PCA has to find such a unit vector for which the projected value is maximum — we have to maximize variance.

1. Problem PCA Solves

You have high-dimensional data with many features. Problems include redundant features, noise, slow models, and hard visualization. The goal is to reduce dimensions and keep maximum information. The core idea is to find new axes where data variance is maximum.

2. Key Intuition

PCA performs a rotation of axes, not deletion of data. Old axes represent original features; new axes represent directions of maximum variance. You project data onto these new axes.

PCA finds new axes — called principal components — that point in the directions of maximum variance in your data. Think of it as turning your coordinate system so that the first axis captures the most variation, the second captures the next most, and so on.

3. Variance (Why important)

Variance means how spread out data is. High variance means more information, low variance means less useful information. PCA keeps directions with highest variance and drops directions with low variance.

4. Covariance (Relationship between features)

Variance works on one feature; covariance works on two features. Positive means both increase together, negative means one increases and the other decreases, zero means no relation. PCA uses this to understand how features move together.

5. Covariance Matrix

Shows relationships between all features. Example in 2D:

$$ \begin{bmatrix} \text{var}(x) & \text{cov}(x,y) \\ \text{cov}(y,x) & \text{var}(y) \end{bmatrix} $$

Diagonal values are variances, off-diagonal values are covariance, and the matrix is symmetric.

6. Correlation vs Covariance

Covariance is scale dependent and hard to compare. Correlation is scaled covariance and lies between −1 and 1. Both give the same direction insight. PCA usually uses the covariance matrix.

7. Linear Transformation (Core concept)

Transformation means changing data space. A matrix performs rotation, stretching, and compression. When you multiply a vector by a matrix, you get a transformed vector. The matrix acts as a transformation rule.

8. Eigenvectors and Eigenvalues

Eigenvectors are special directions where, after transformation, direction stays the same and only magnitude changes. Eigenvalues show how much stretching happens. Key equation:

$$ A v = \lambda v $$

A is the matrix, v is the eigenvector, λ is the eigenvalue.

9. Why Eigen Things Matter in PCA

Eigenvectors define directions of the new axes. Eigenvalues define the importance of each axis. A higher eigenvalue means more variance and more importance.

10. PCA Step-by-Step

  1. Mean centering. Subtract the mean from each feature to shift data to the origin and improve results.
  2. Compute covariance matrix using: np.cov(X.T)
  3. Perform eigen decomposition to find eigenvalues and eigenvectors.
  4. Sort eigenvalues in descending order and pick the top k.
  5. Select top eigenvectors. These become the principal components.
  6. Transform data using the projection: \( X_{new} = X \cdot V \), where V contains the selected eigenvectors.

11. Dimensionality Reduction

You reduce dimensions like 3D to 2D to 1D. The number of components depends on how much variance you want to retain.

12. Explained Variance

Shows how much information each component keeps.

$$ \text{explained\_variance} = \frac{\text{eigen\_value}}{\sum \text{eigen\_values}} $$

Used to decide the number of components.

13. Code Example (Minimal)

import numpy as np

X = np.array([[2, 3],
              [3, 4],
              [4, 5]])

X_meaned = X - np.mean(X, axis=0)

cov_matrix = np.cov(X_meaned.T)

eigen_values, eigen_vectors = np.linalg.eig(cov_matrix)

idx = np.argsort(eigen_values)[::-1]
eigen_vectors = eigen_vectors[:, idx]

V = eigen_vectors[:, :1]

X_reduced = np.dot(X_meaned, V)

print(X_reduced)

14. Important Points for Exams

  • PCA is unsupervised
  • PCA is linear
  • PCA is sensitive to scaling — use standardization
  • PCA works best when features are correlated

15. When to Use PCA

Use when you have too many features, features are correlated, visualization is needed, or speed optimization is needed.

Avoid when interpretability is critical or features are already few.

Day 49

Principal Component Analysis (PCA) — MNIST Example

A full worked example: PCA applied to the MNIST digit dataset, with a KNN classifier trained before and after dimensionality reduction. Dataset: column 0 = label (digit), columns 1–784 = pixel values (a 28×28 image flattened).

import pandas as pd
import matplotlib.pyplot as plt

# ===================== 1. LOAD DATA =====================
# Read MNIST CSV
df = pd.read_csv('/kaggle/input/datasets/animatronbot/mnist-digit-recognizer/train.csv')

# Dataset:
# column 0 = label (digit)
# columns 1-784 = pixel values (28x28 image flattened)


# ===================== 2. SPLIT INTO X AND Y =====================
# X = features (pixels)
X = df.iloc[:, 1:]

# Y = target (digit label)
Y = df.iloc[:, 0]


# ===================== 3. TRAIN-TEST SPLIT =====================
from sklearn.model_selection import train_test_split

x_train, x_test, y_train, y_test = train_test_split(
    X, Y,
    test_size=0.2,        # 20% test data
    random_state=42       # fixed shuffle -> same split every run
)

# random_state:
# fixes randomness -> reproducible results


# ===================== 4. KNN BEFORE SCALING =====================
from sklearn.neighbors import KNeighborsClassifier
from sklearn.metrics import accuracy_score

knn = KNeighborsClassifier()

# KNN stores training data (no real training phase)
knn.fit(x_train, y_train)

# Predict using nearest neighbors
y_pred = knn.predict(x_test)

# Check accuracy
print("Accuracy before scaling:", accuracy_score(y_test, y_pred))


# ===================== 5. FEATURE SCALING =====================
from sklearn.preprocessing import StandardScaler

scaler = StandardScaler()

# fit -> learn mean and std from training data
# transform -> apply scaling
x_train = scaler.fit_transform(x_train)
x_test = scaler.transform(x_test)

# scaling:
# converts data to mean=0, std=1
# prevents large-value features dominating distance


# ===================== 6. PCA (DIMENSION REDUCTION) =====================
from sklearn.decomposition import PCA

# reduce 784 features -> 100 important features
pca = PCA(n_components=100)

# fit -> learn principal components
# transform -> project data onto new axes
x_train_trf = pca.fit_transform(x_train)
x_test_trf = pca.transform(x_test)

# PCA:
# rotates data -> keeps directions with max variance
# reduces noise + computation


# ===================== 7. KNN AFTER PCA =====================
knn = KNeighborsClassifier()

knn.fit(x_train_trf, y_train)

y_pred = knn.predict(x_test_trf)

print("Accuracy after PCA:", accuracy_score(y_test, y_pred))


# ===================== 8. PCA INTERNALS =====================
# eigenvalues -> importance of each component
print("Explained variance:", pca.explained_variance_)

# eigenvectors -> directions of new axes
print("PCA components shape:", pca.components_.shape)
# shape = (100, 784)


# ===================== 9. VISUALIZE ONE IMAGE =====================
# take one sample and reshape to 28x28
image = df.iloc[0, 1:].values.reshape(28, 28)

plt.imshow(image, cmap='gray')
plt.title(f"Label: {df.iloc[0,0]}")
plt.show()


# ===================== FINAL FLOW =====================
# image -> flatten -> scale -> PCA -> KNN -> prediction

Walkthrough

  1. Load the MNIST CSV, split into pixel features (X) and digit label (Y)
  2. Train/test split with test_size=0.2 and a fixed random_state=42 for reproducibility
  3. Run KNN directly on the raw 784-pixel features and record baseline accuracy
  4. Standardize features with StandardScaler (mean=0, std=1) so large-value pixels don't dominate distance calculations
  5. Apply PCA(n_components=100) — reduce 784 features down to the 100 directions of maximum variance
  6. Re-run KNN on the 100-dimensional PCA-transformed data and compare accuracy
  7. Inspect PCA internals: pca.explained_variance_ (eigenvalues — importance per component) and pca.components_.shape which is (100, 784) — the eigenvectors, one 784-length direction per retained component

Final flow: image → flatten → scale → PCA → KNN → prediction.

5 questions on Day 47–49. Pick an answer for each, then check.

1. Two candidate features, "rooms" and "washrooms," both project with roughly equal spread/variance when predicting house price. Per the notes' geometric intuition, what should you do?

Explanation: The notes give exactly this example: "If we come across such set of columns which has equal variance then we use feature extraction technique. Like rooms and washrooms are both important... so we can't remove any column but instead we make a new column of house_size." Feature selection (dropping a column) is appropriate only when one column is clearly less important by variance.

2. You compute the covariance matrix of a 2D dataset and find the off-diagonal covariance is 0, but var(x) ≠ var(y). What does this imply about the principal components?

Explanation: Covariance = 0 means no linear relationship, so the data cloud isn't "tilted" — eigenvectors of a diagonal covariance matrix are the standard basis vectors themselves (x-axis, y-axis). The eigenvalues equal var(x) and var(y) directly, so whichever axis has the larger variance becomes PC1 (larger eigenvalue = more important direction), and the other becomes PC2.

3. In the MNIST code, StandardScaler is applied BEFORE PCA. If you skipped scaling and ran PCA directly on raw pixel values (0–255), what is the most likely consequence, per the notes' stated properties of PCA?

Explanation: Section 14's "Important Points for Exams" states plainly: "PCA is sensitive to scaling so use standardization." Since PCA maximizes variance, unscaled features with larger numeric ranges would dominate the variance calculation and distort the resulting principal components — this is exactly why the MNIST pipeline scales before applying PCA.

4. After running pca = PCA(n_components=100) and pca.fit_transform(x_train) on the 784-pixel MNIST data, what is the shape of pca.components_, and what does it represent?

Explanation: The code comment states directly: "eigenvectors -> directions of new axes... PCA components shape: shape = (100, 784)." Each of the 100 retained principal components is itself a direction (eigenvector) defined across all 784 original pixel dimensions — unrelated to the 10 digit classes, which PCA (unsupervised) never sees.

5. A dataset has only 3 features, all weakly correlated with each other, and the business requirement is that the final model must clearly explain predictions in terms of the original named features. Should you apply PCA here?

Explanation: The notes' "When to Use PCA" section says to avoid PCA "when interpretability is critical or features are already few," and that "PCA works best when features are correlated" — both conditions argue against it here. PCA being unsupervised (option D's premise) is true but is not why it should be avoided; it works on unlabeled data just fine.
