22. Regularization: Ridge, Lasso & Elastic Net

Ridge (L2) · Lasso (L1) · Elastic Net · why L1 zeroes out coefficients and L2 doesn't

Extended notes — this topic isn't covered in the CampusX playlist notes this site is based on. Written from scratch to continue the curriculum, in the same style as the rest of the site.

Ridge, Lasso, and Elastic Net are all Regression techniques — they're regularized versions of Linear Regression, aimed at the exact overfitting problem section 21 (Bias-Variance Tradeoff) introduced: a model with too many features, or features that are too flexible, memorizes noise in the training data instead of learning the real signal. Regularization fixes this by adding a penalty to the cost function that discourages large coefficients.

Regression

Ridge Regression — Geometric Intuition & Cost Function

Plain linear regression only cares about one thing: minimize the sum of squared residuals (RSS) on the training data. Nothing stops it from assigning a huge coefficient to a feature if that helps fit the training points even a little better — including fitting noise. Ridge regression adds a second term to the cost that penalizes large coefficients directly, so the model has to "pay" for every unit of coefficient size, not just for prediction error.

$$ J(w) = \underbrace{\sum_{i=1}^{n}(y_i - \hat{y}_i)^2}_{\text{RSS — fit the data}} \;+\; \underbrace{\lambda \sum_{j=1}^{d} w_j^2}_{\text{penalty — keep weights small}} $$

\( \lambda \) (sometimes written \( \alpha \) in sklearn) is a hyperparameter you choose: \( \lambda = 0 \) recovers plain OLS exactly; a very large \( \lambda \) crushes every coefficient toward zero, forcing the model to basically predict a constant. Somewhere in between is the sweet spot — enough freedom to fit real signal, not enough freedom to chase noise.

Geometric picture — a budget on coefficient size

Minimizing "RSS + \( \lambda \sum w_j^2 \)" is mathematically the same problem as minimizing RSS alone subject to \( \sum w_j^2 \leq t \) for some budget \( t \) tied to \( \lambda \). In 2D (two coefficients \(w_1, w_2\)), that constraint \( w_1^2+w_2^2 \le t \) is a disc centered at the origin. The unconstrained OLS solution sits somewhere outside that disc (since OLS ignores coefficient size); ridge's answer is the point inside or on the edge of the disc that gets you closest to the OLS solution in terms of RSS. Section 4 below builds on this exact picture to explain why ridge and lasso behave so differently.

Code — Ridge Regression with scikit-learn

from sklearn.linear_model import Ridge
from sklearn.preprocessing import StandardScaler
from sklearn.pipeline import make_pipeline

# feature scaling matters a lot for regularized models —
# the penalty term sums raw coefficient magnitudes, so features on
# larger scales would get unfairly punished (or unfairly protected)
model = make_pipeline(
    StandardScaler(),
    Ridge(alpha=1.0)   # alpha == lambda, the penalty strength
)

model.fit(X_train, y_train)
y_pred = model.predict(X_test)

# inspect how much each coefficient got shrunk vs plain LinearRegression
ridge_coefs = model.named_steps['ridge'].coef_
print(ridge_coefs)
Rule of thumb: increasing alpha always shrinks every coefficient's magnitude further toward zero — but with ridge, they approach zero and rarely hit it exactly. Keep that in mind for section 4.
Regression

Ridge Regression — Gradient Descent

Section 19 showed that plain linear regression's cost \( J(w) = \frac{1}{2n}\sum(y_i-\hat{y}_i)^2 \) has a closed-form solution via OLS — no iteration needed, just linear algebra. Ridge's cost adds the penalty term, and it's still a smooth, convex, differentiable function of \(w\) — which means gradient descent applies to it exactly the same way it applies to OLS. Let's derive the update rule.

Step 1 — write the cost with the penalty

$$ J(w) = \frac{1}{2n}\sum_{i=1}^{n}(y_i - \hat{y}_i)^2 + \lambda \sum_{j=1}^{d} w_j^2 \qquad \hat{y}_i = w^\top x_i $$

Step 2 — differentiate term by term

The RSS term's gradient is exactly what it was for plain linear regression — the penalty term is new, and its derivative is easy since \( \frac{d}{dw_j}w_j^2 = 2w_j \):

$$ \frac{\partial J}{\partial w_j} = -\frac{1}{n}\sum_{i=1}^{n} x_{ij}(y_i - \hat{y}_i) \;+\; 2\lambda w_j $$

Step 3 — the update rule

$$ w_j \leftarrow w_j - \eta \left[ -\frac{1}{n}\sum_{i=1}^{n} x_{ij}(y_i-\hat{y}_i) + 2\lambda w_j \right] $$

Rearranged, this is more revealing:

$$ w_j \leftarrow \underbrace{(1 - 2\eta\lambda)}_{\text{shrink factor} \;<\;1}\, w_j \;+\; \underbrace{\frac{\eta}{n}\sum_{i=1}^{n} x_{ij}(y_i-\hat{y}_i)}_{\text{the usual OLS gradient step}} $$
This is exactly "weight decay." Every gradient step first multiplies the current weight by a factor slightly less than 1 (shrinking it toward zero), then applies the ordinary OLS-style gradient update. This is precisely the term deep learning borrows for L2 regularization — the "decay" is this multiplicative shrinkage happening on every single step, on top of whatever the loss gradient wants to do.

Regression

Lasso Regression — Cost Function & Code

Lasso (Least Absolute Shrinkage and Selection Operator) swaps ridge's squared penalty for an absolute value penalty — L1 instead of L2:

$$ J(w) = \sum_{i=1}^{n}(y_i - \hat{y}_i)^2 \;+\; \lambda \sum_{j=1}^{d} |w_j| $$

That one change — squares to absolute values — looks small on paper but produces a strikingly different kind of model, which section 4 covers in depth. In short: Lasso doesn't just shrink coefficients, it can push them to exactly zero, effectively removing features from the model. That makes Lasso useful as an automatic feature-selection tool, not just an overfitting guard.

Note. \( |w_j| \) is not differentiable at \( w_j=0 \) (the same corner problem MAE has, seen in section 19), so plain gradient descent doesn't cleanly apply. In practice, scikit-learn's Lasso is solved with coordinate descent — optimizing one coefficient at a time while holding the others fixed — rather than a closed form or vanilla GD.

Code — Lasso Regression with scikit-learn

from sklearn.linear_model import Lasso
from sklearn.preprocessing import StandardScaler
from sklearn.pipeline import make_pipeline

model = make_pipeline(
    StandardScaler(),
    Lasso(alpha=0.1)   # alpha == lambda
)
model.fit(X_train, y_train)

lasso_coefs = model.named_steps['lasso'].coef_

# count how many features got zeroed out entirely
n_dropped = (lasso_coefs == 0).sum()
print(f"Lasso zeroed out {n_dropped} of {len(lasso_coefs)} features")
Concept

Why Lasso Creates Sparsity

This is the single most important intuition on this page: why does swapping \( \sum w_j^2 \) for \( \sum|w_j| \) make coefficients hit exactly zero? The cleanest way to see it is geometrically, using the constrained-optimization view from section 1.

Ridge's constraint region — \( w_1^2+w_2^2 \le t \) is a disc: perfectly round, no corners, no edges — every boundary point is equally "sharp" (or rather, equally smooth).
Lasso's constraint region — \( |w_1|+|w_2| \le t \) is a diamond (a square rotated 45°): four sharp corners, and those corners sit exactly on the axes — the points where one coefficient is zero.

Now overlay the RSS cost. Plot the plain-OLS solution as a point, and around it draw the RSS's contour lines — since RSS is a quadratic bowl, its contours are concentric ellipses centered on the OLS point, growing outward as cost increases. The regularized solution is whichever point on the boundary of the constraint region first touches the smallest (lowest-cost) ellipse as it expands outward from the OLS point.

Illustrative aid — generated for this site.

The circle has no corners, so as the ellipse expands from the OLS point, it almost always first grazes the circle at some smooth, generic point — one where both coordinates are nonzero. Coefficients get smaller, but landing exactly on an axis (one coefficient exactly 0) would be a geometric coincidence.

The diamond is different: its corners stick out further toward the OLS point relative to its flat edges (for a fixed "budget" \(t\)), so an expanding ellipse is disproportionately likely to hit a corner first — and every corner of the diamond lies exactly on an axis, meaning one of the coordinates is exactly zero. That corner-hugging behavior is what makes Lasso a sparse, feature-selecting method: whichever coefficients correspond to weak or redundant features get snapped to exactly 0, not just shrunk small.

The one-sentence version

Circles are round everywhere, so the optimum lands anywhere on the boundary; diamonds have corners on the axes, so the optimum disproportionately lands on those corners — and a corner means a coefficient of exactly zero. In higher dimensions this generalizes: L2's constraint region (a hypersphere) has no flat faces or vertices, while L1's (a cross-polytope) has vertices sitting exactly on the axes, so the same corner-snapping logic applies with many features at once.

Regression

Elastic Net Regression

Ridge shrinks everything smoothly but keeps every feature; Lasso can zero features out but has two well-known weaknesses: with a group of highly correlated features, it tends to arbitrarily pick just one of them and zero out the rest (instead of spreading credit across the group), and when there are more features than samples (\(d > n\)) it can select at most \(n\) features. Elastic Net's fix is simple: use both penalties at once.

$$ J(w) = \sum_{i=1}^{n}(y_i - \hat{y}_i)^2 \;+\; \lambda \left[ \, r \sum_{j=1}^{d} |w_j| \;+\; (1-r) \sum_{j=1}^{d} w_j^2 \, \right] $$

\( \lambda \) still controls overall regularization strength, and a new mixing ratio \( r \in [0,1] \) (sklearn calls it l1_ratio) controls the blend: \( r=1 \) is pure Lasso, \( r=0 \) is pure Ridge, and anything in between gets a constraint region that's a rounded-off diamond — it keeps corners (so it can still zero out coefficients) but the corners are softened by the circular term (so correlated features get shrunk together as a group instead of one being arbitrarily kept and the rest zeroed).

Code — Elastic Net with scikit-learn

from sklearn.linear_model import ElasticNet
from sklearn.preprocessing import StandardScaler
from sklearn.pipeline import make_pipeline

model = make_pipeline(
    StandardScaler(),
    ElasticNet(alpha=0.1, l1_ratio=0.5)  # 50/50 blend of L1 and L2
)
model.fit(X_train, y_train)

# l1_ratio=1.0  -> pure Lasso
# l1_ratio=0.0  -> pure Ridge
# l1_ratio=0.5  -> balanced mix, good default when features are correlated

Test Your Understanding

Hard

5 questions on Ridge, Lasso & Elastic Net. Pick an answer for each, then check.

1. Geometrically, why does Lasso tend to zero out coefficients while Ridge doesn't?

Explanation: The diamond's vertices sit exactly on the axes (one coordinate = 0), and vertices are the points an expanding ellipse is most likely to touch first because they protrude further toward the interior for the same constraint "budget." The circle has no such protrusions — every boundary point is equally likely.

2. In the ridge gradient descent update \( w_j \leftarrow (1-2\eta\lambda)w_j + \frac{\eta}{n}\sum x_{ij}(y_i-\hat{y}_i) \), what happens if you set \( \lambda = 0 \)?

Explanation: \( (1-2\eta \cdot 0) = 1 \), so the weight decay term disappears entirely and the update is just the ordinary OLS gradient descent step — confirming ridge with \(\lambda=0\) is plain linear regression, as the cost function also shows directly.

3. Why does scikit-learn's Lasso use coordinate descent rather than plain gradient descent?

Explanation: The absolute value function has a sharp corner at 0 (same issue as MAE in section 19) — no single well-defined gradient exists there. Coordinate descent sidesteps this by optimizing one coefficient at a time using a closed-form soft-thresholding update, avoiding the need for a gradient of the full multivariate penalty.

4. A dataset has 5 features that are all highly correlated with each other. Compared to Lasso, why might Elastic Net be preferred here?

Explanation: Pure L1 is known to behave erratically with correlated groups, picking one somewhat arbitrarily. Mixing in the L2 term rounds off the diamond's corners just enough that correlated features get shrunk together as a group rather than one being singled out.

5. What does increasing \( \lambda \) (alpha) do to a ridge model's bias and variance, per the bias-variance tradeoff from section 21?

Explanation: Regularization is a direct bias-variance dial: shrinking coefficients makes the model less flexible (higher bias, worse fit to training data) but less sensitive to the particular noise in the training sample (lower variance across different training sets) — exactly the tradeoff section 21 described, just now with a knob to control it.
