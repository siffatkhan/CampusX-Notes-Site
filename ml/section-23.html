Day 70

Logistic Regression (Perceptron Trick)

Why Not Linear Regression for Classification?

Problem 1: Output Range Mismatch

Classification needs a class label, usually 0 or 1. Linear regression produces \( \hat{y} = wx + b \), which outputs any real number: 1.6, -0.2, 5.3, -10, and so on. There's no natural way to interpret "class = 1.6" or "class = -0.2." These values don't correspond to a class.

Problem 2: Why a Simple Threshold Fails

The obvious fix: pick a threshold. For example, if \( \hat{y} \geq 0.5 \), predict class 1, otherwise predict class 0. This works for simple, well-separated data, but it breaks down with outliers. Here's the mechanism:

  • Linear regression minimizes squared error: \( \sum (\hat{y}^{(i)} - y^{(i)})^2 \)
  • Squaring punishes large errors disproportionately. An outlier far from the rest of the data contributes a huge squared error
  • To reduce that huge error, the regression line tilts toward the outlier, dragging the decision boundary with it
  • Result: a single distant point shifts the boundary dramatically, misclassifying points that were previously separated correctly

The model isn't only "occasionally wrong." It's structurally unstable to outliers, because of what it's optimizing for.

Problem 3: Wrong Optimization Objective

Squared error is designed for continuous prediction problems ("how far off was my number?"), not classification ("did I pick the right class?"). It doesn't correspond to a meaningful notion of classification confidence.

Why Logistic Regression Fixes This

Fix 1: The Sigmoid Function Bounds the Output

Instead of outputting \( \hat{y} = wx+b \) directly, logistic regression passes that value (\(z\)) through the sigmoid function:

$$ \sigma(z) = \frac{1}{1 + e^{-z}} $$

No matter what \(z\) is, even \(z=-1000\) or \(z=+1000\), the output is squeezed into the range (0, 1):

$$ z \to -\infty \implies \sigma(z) \to 0 \qquad z \to +\infty \implies \sigma(z) \to 1 \qquad z = 0 \implies \sigma(z) = 0.5 $$

This output now represents a probability: "there's an 87% chance this is class 1."

Fix 2: A Loss Function Built for Classification

Logistic regression doesn't use squared error. It uses log loss (cross-entropy):

$$ J(w,b) = -\frac{1}{m}\sum_{i=1}^{m}\left[y^{(i)}\log(\hat{y}^{(i)}) + (1-y^{(i)})\log(1-\hat{y}^{(i)})\right] $$

This penalizes confident wrong predictions heavily. Predicting 0.99 when the true label is 0 draws a severe penalty. It stays far less sensitive to distant points than squared error does, because the penalty depends on probability confidence, not raw distance.

We don't usually use MSE for logistic regression. After you apply the sigmoid function, the MSE cost becomes non-convex, which makes gradient descent harder and slower to optimize. Binary cross-entropy (log loss) works better: it produces a convex optimization problem and penalizes incorrect, high-confidence predictions more effectively.
Deep dive: the Perceptron Trick

Assumes the data is linearly separable. Two approaches exist for finding the separating line. The perceptron trick is one of them.

What is the perceptron trick? You start with random values of a, b, c, the line's coefficients. You run a loop, generally 1000 times, or until convergence. In each iteration, you choose a random point. If that point is classified correctly, you do nothing. Otherwise, you move the line. This gives a solution easily, but not necessarily the best possible one.

Identifying +ve and -ve regions. The line equation is \( Ax + By + C = 0 \), where C is the y-intercept. You move the line in 2D by changing a, b, c:

  • Changing c → the line moves in parallel
  • Changing a → the line rotates around an axis
  • Changing b → the line rotates around some point

(Desmos is an online calculator for playing with a, b, c values interactively.)

Update rule. Append 1 to the end of a point's coordinates: (1, 3) becomes (1, 3, 1). Add or subtract it from the line's coefficient vector: line \( 2x+3y+5=0 \) has coefficients \( (2,3,5) \). To move the line toward the negative region, you add the point vector. To move it toward the positive region, you subtract it. If a -ve point falls in a +ve region, you add its augmented coordinates and subtract from the line coefficients. The same logic applies in reverse for a +ve point misclassified as -ve.

$$ w_{\text{new}} = w_{\text{old}} - \eta \cdot x_i \qquad \eta = \text{learning rate (e.g. } 0.01\text{)} $$

Rewrite the line as \( w_0 + w_1 x_1 + w_2 x_2 = 0 \) (where \(w_0=c,\ w_1=a,\ w_2=b\)). You classify a point using the summation \( \sum w_i x_i \): if the result is positive, the prediction is 1, otherwise 0.

Algorithm sketch. You decide the epoch count (generally 100) and the learning rate (generally 0.01):

for i in range(epochs):
    # randomly select a training point
    idx = random.randint(0, len(X) - 1)
    xi, yi = X[idx], y[idx]

    z = np.dot(w, xi)          # summation of w_i * x_i
    y_hat = 1 if z >= 0 else 0

    if y_hat != yi:
        # misclassified -> move the line towards this point
        if yi == 1:
            w = w + learning_rate * xi
        else:
            w = w - learning_rate * xi
    # if correctly classified, do nothing this round
Day 71

Logistic Regression (Perceptron Trick Code)

A from-scratch implementation of the perceptron trick described on Day 70: random initialization, a fixed number of epochs, a random point sampled each round, and a coefficient update whenever that point is misclassified.

Illustrative aid: the source notes hold this implementation as a screenshot that didn't extract as text. This is a reconstruction of that same code from the Day 70 algorithm description, not a verbatim transcription.
import numpy as np

def perceptron(X, y, epochs=100, lr=0.01):
    # add a bias column of 1s -> augmented coordinates (x1, x2, 1)
    X = np.insert(X, X.shape[1], 1, axis=1)

    # random initial weights: w0 = c, w1 = a, w2 = b
    weights = np.ones(X.shape[1])

    for i in range(epochs):
        # pick one random student/point per epoch
        j = np.random.randint(0, X.shape[0])
        xi = X[j]

        # summation of w_i * x_i -> step function
        z = np.dot(xi, weights)
        y_hat = step(z)

        # perceptron trick update rule
        weights = weights + lr * (y[j] - y_hat) * xi

    return weights

def step(z):
    return 1 if z >= 0 else 0

Note: \( (y_j - \hat{y}) \) is 0 when the point is already classified correctly, so the weight update does nothing that round. This matches the Day 70 rule: "if classified rightly, do nothing, otherwise move the line."
Day 72

Logistic Regression (Sigmoid Function)

In the earlier perceptron trick algorithm, only misclassified points pulled the line. Now, correctly classified points also push the line, so an equilibrium forms between the pushes and pulls.

These pushes and pulls also depend on the distance of the point from the line. Misclassified points further away pull with more magnitude, and points near the line pull weakly. The same goes for correctly classified points pushing.

The sigmoid function scales every value into the range 0 to 1. This turns a raw distance-from-the-line into a smooth, distance-aware push/pull magnitude, instead of a hard misclassified/correct switch.
$$ \sigma(x) = \frac{1}{1 + e^{-x}} $$

Higher k makes the transition between 0 and 1 sharper, closer to a hard step function like the perceptron's step rule. Lower k gives a gentler, more probability-like curve.

Maximum Likelihood → Cross-Entropy

In maximum likelihood estimation, you select the model whose product of probabilities (over all data points) is highest. The summation of the negative log of that maximum likelihood is what we call cross-entropy. Instead of maximizing a product of probabilities, you minimize the negative-log-sum. The best model is the one with the lowest cross-entropy.

Loss Function of Logistic Regression

$$ J(w,b) = -\frac{1}{m}\sum_{i=1}^{m}\left[y^{(i)}\log(\hat{y}^{(i)}) + (1-y^{(i)})\log(1-\hat{y}^{(i)})\right] $$

This is the same binary cross-entropy / log loss introduced above. It's the negative-log-likelihood formulation described above, averaged over all m training examples. Look closely at what happens per example: only one of the two terms is ever "active," because \(y^{(i)}\) is either 0 or 1.

Per-example view: why it punishes confident wrong answers so hard

If the true label \(y^{(i)}=1\), the loss for that single example collapses to \( -\log(\hat{y}^{(i)}) \), because the \((1-y)\log(1-\hat{y})\) term vanishes when \((1-y)=0\). If \(y^{(i)}=0\), it collapses to \( -\log(1-\hat{y}^{(i)}) \) instead. Either way, you take \( -\log \) of "the probability the model assigned to the correct class."

True labelModel's predicted \(\hat{y}\)Prob. assigned to correct classLoss \(-\log(\cdot)\)
10.99 (confident & correct)0.99≈ 0.01, tiny
10.51 (barely correct)0.51≈ 0.67, moderate
10.01 (confident & wrong)0.01≈ 4.6, huge

That last row is the whole point. Because \(-\log(x)\) shoots toward infinity as \(x \to 0\), a model that's confidently wrong gets penalized far more than one that's barely wrong. That's the behavior you want from a classifier's training signal.

Related: controlling overfitting. More features combined with less data also causes overfitting. Fixes: add more data, do feature selection, or reduce the size of parameters through regularization. See the next page for exactly how.

Gradient Descent for Logistic Regression

Extended notes: this subsection continues past where the source playlist notes end.

The perceptron trick above updates weights one misclassified point at a time, forever, with no real notion of a "cost being minimized." Logistic regression's log loss gives you something better: a smooth, differentiable cost function. This means the same gradient descent machinery from linear regression (batch, stochastic, mini-batch, all of it) applies here too. Only the gradient formula changes.

Deriving the gradient

Start from the log loss for one example, \( \hat{y}=\sigma(z) \), \( z=w^\top x + b \). The chain rule needs three pieces: \( \frac{\partial J}{\partial \hat y} \), \( \frac{\partial \hat y}{\partial z} \) (the sigmoid's own derivative, a clean \( \sigma(z)(1-\sigma(z)) \)), and \( \frac{\partial z}{\partial w} = x \). Multiply them together:

$$ \frac{\partial J}{\partial w} = (\hat{y} - y)\, x $$

Almost everything cancels. The messy log terms and the sigmoid's derivative collapse into (predicted − actual) × input. This is the exact same shape as linear regression's gradient (\( (\hat y - y)x \) there too), even though the loss function and the meaning of \( \hat y \) are completely different. That's not a coincidence. It's a general property of pairing a sigmoid/softmax output with a cross-entropy loss.

The update rule

$$ w := w - \alpha \cdot \frac{1}{m}X^\top(\hat{y} - y) \qquad b := b - \alpha \cdot \frac{1}{m}\sum_{i=1}^m(\hat{y}^{(i)} - y^{(i)}) $$

Same idea as OLS gradient descent: compute predictions with the current weights, find the error, nudge weights opposite to the gradient, repeat. Because the shape matches linear regression exactly, batch, stochastic, and mini-batch gradient descent all carry over unchanged. SGD picks one random row per update, mini-batch picks a small group, batch uses everything. Only now \(\hat y\) comes from a sigmoid instead of a raw linear function.

import numpy as np

def sigmoid(z):
    return 1 / (1 + np.exp(-z))

def logistic_gd(X, y, lr=0.1, epochs=1000):
    X = np.insert(X, 0, 1, axis=1)     # bias trick, same as linear regression
    w = np.zeros(X.shape[1])
    m = X.shape[0]

    for _ in range(epochs):
        z = np.dot(X, w)
        y_hat = sigmoid(z)
        gradient = np.dot(X.T, (y_hat - y)) / m
        w = w - lr * gradient

    return w   # w[0] is the bias/intercept, w[1:] are the coefficients

Hard

5 questions on Days 70–72. Pick an answer for each, then check.

1. A dataset with one extreme outlier is fit with plain linear regression + 0.5 threshold for classification. Per the notes, why does this specifically go wrong?

Explanation: The mechanism is specific: squaring the error amplifies distant points, the regression line tilts to reduce that huge squared error, and the decision boundary shifts with it. That's a structural instability, not a one-off mistake.

2. Why is MSE avoided as the cost function for logistic regression, even though it works fine for linear regression?

Explanation: Composing MSE with the nonlinear sigmoid produces a non-convex loss surface with local minima, which gradient descent struggles with. Binary cross-entropy stays convex and is the preferred alternative.

3. In the perceptron trick's update rule, a positive-class point (y=1) is misclassified. Which direction does the weight vector move, per "New coef = old coef − η × coordinates" combined with the sign convention for +ve points?

Explanation: A misclassified +ve point needs to move into the +ve region, so the update adds (moves toward) its coordinates: \(w_{new} = w_{old} + \eta x_i\). This is equivalent to \((y-\hat y)=1-0=1\) in the Day 71 code's \(w + \eta(y-\hat y)x\) rule.

4. Using the sigmoid widget on this page, what happens as you drag the steepness slider k toward its maximum value?

Explanation: As k grows, \( \sigma(kx) \) transitions from 0 to 1 more abruptly around x=0. In the limit it converges to the perceptron's hard step function, while staying bounded in (0,1).

5. Per Day 72, what is cross-entropy in relation to maximum likelihood estimation?

Explanation: The notes define cross-entropy exactly this way: the summation of the negative log of the maximum likelihood. Instead of maximizing a product of probabilities, you minimize the negative-log-sum. The best model minimizes cross-entropy.
