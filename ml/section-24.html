24. Classification Metrics

Confusion matrix · Precision, Recall & F1 · ROC curve & AUC

Extended notes — this topic isn't covered in the CampusX playlist notes this site is based on. Written from scratch to continue the curriculum, in the same style as the rest of the site.

Logistic Regression (sections 22–23) gives you a classifier — but "does it work?" needs its own vocabulary. Unlike regression, where MAE/RMSE/R² all roughly agree on what "good" means, classification has several genuinely different notions of "correct," and picking the wrong one to optimize for can quietly build a useless model.

Evaluation

Confusion Matrix, Accuracy & Type I / Type II Errors

A binary classifier can be wrong in two distinct ways, and right in two distinct ways. The confusion matrix just lays out all four possibilities in a grid, comparing what the model predicted against what actually happened:

Predicted Positive
Predicted Negative
Actual Positive
True Positive (TP)
Correctly caught it
False Negative (FN)
Missed it — Type II error
Actual Negative
False Positive (FP)
False alarm — Type I error
True Negative (TN)
Correctly cleared it

Accuracy — and why it lies to you

$$ \text{Accuracy} = \frac{TP + TN}{TP + TN + FP + FN} $$

Accuracy answers "what fraction did I get right overall?" — fine when classes are roughly balanced, dangerously misleading when they aren't.

Concrete example — fraud detection. Suppose 95% of transactions are legitimate and 5% are fraud. A "model" that outputs not fraud for every single transaction, without looking at the data at all, scores 95% accuracy — while catching literally zero fraud cases. High accuracy here reflects the class imbalance in the data, not any skill the model has. This is exactly why classification tasks with rare positive classes (fraud, disease, defects) need precision/recall instead — see the next section.

Type I vs Type II Errors

Type I Error — False Positive

You raised an alarm that shouldn't have gone off. Analogy: a fire alarm blaring because someone made toast — nothing is actually on fire, but everyone evacuates for nothing.

Spam filter version: a real, important email gets shoved into the spam folder.

Type II Error — False Negative

You stayed silent when you shouldn't have. Analogy: a smoke detector with a dead battery during an actual fire — the danger is real, and nothing warns anyone.

Medical version: a cancer screening test says "healthy" for a patient who actually has cancer — arguably the costlier mistake of the two in this domain.

Which error type is worse always depends on the domain — that's the entire reason precision and recall exist as separate, sometimes-opposing metrics rather than one blended number.

Evaluation

Precision, Recall & F1 Score

Precision

$$ \text{Precision} = \frac{TP}{TP+FP} $$

Plain English: "Of everything I flagged as positive, how much of it was actually positive?" It's a measure of how much you can trust a positive prediction.

Recall

$$ \text{Recall} = \frac{TP}{TP+FN} $$

Plain English: "Of all the actual positives out there, how many did I actually catch?" It's a measure of how thoroughly you're finding the positives, regardless of false alarms along the way.

The one-line mnemonic: precision is about your positive predictions ("were you right when you said yes?"); recall is about the actual positives ("did you find all of them?"). Precision's denominator is everything you flagged; recall's denominator is everything that was truly positive.

The tradeoff — and who cares about which

Precision and recall pull in opposite directions. Flag everything as positive and recall hits 100% (you never miss a true positive) — but precision craters, since most of your "positive" flags are wrong. Flag nothing unless you're extremely sure, and precision goes up — but recall craters, since you're letting real positives slip through unflagged. This is the same push-pull as the classification threshold in the ROC section below.

Spam detection wants precision. A false positive (real email marked spam) can mean someone misses a job offer or an important message — that's a costly, visible mistake. A false negative (spam that slips through) is just mildly annoying. Bias the model toward "only flag spam when very confident."
Cancer screening wants recall. A false negative (missed cancer) can be fatal. A false positive (unnecessary follow-up test) is inconvenient and costly, but rarely life-threatening. Bias the model toward "flag anything even remotely suspicious," and let a doctor filter the false alarms downstream.

F1 Score — the harmonic mean, on purpose

$$ F_1 = 2 \cdot \frac{\text{Precision} \cdot \text{Recall}}{\text{Precision} + \text{Recall}} $$

F1 is the harmonic mean of precision and recall, not the ordinary (arithmetic) average — and that choice is deliberate. The harmonic mean is dragged down hard by whichever of the two numbers is smaller, so a model can't hide a terrible score in one metric behind a great score in the other.

Worked example. Model A: precision = 1.0, recall = 0.01 (it only ever flags one thing, but it's right). Arithmetic mean: (1.0 + 0.01)/2 = 0.505 — looks like a decent, middling model. Harmonic mean (F1): \( 2 \times \frac{1.0 \times 0.01}{1.0+0.01} \approx \) 0.02 — correctly exposes that this model is nearly useless, since it essentially never finds the positives it's supposed to find. The arithmetic mean rewards being extreme in one metric; the harmonic mean punishes it.

Use F1 when you want one balanced number and don't have a strong domain reason to favor precision or recall specifically; use precision or recall directly when the domain does give you that reason (as above).

Evaluation

ROC Curve & AUC

Every metric so far assumes a fixed classification threshold — usually 0.5: "if the predicted probability \( \ge 0.5 \), call it positive." But that 0.5 cutoff is arbitrary. The ROC (Receiver Operating Characteristic) curve asks a broader question: across every possible threshold, how good is this model at separating the two classes?

True Positive Rate (TPR) — this is just Recall again: of all actual positives, what fraction did the model catch at this threshold?
False Positive Rate (FPR) — of all actual negatives, what fraction did the model wrongly flag as positive at this threshold? \( FPR = \frac{FP}{FP+TN} \)

Sweep the threshold from 1 down to 0. At threshold 1, nothing is ever flagged positive — TPR = 0, FPR = 0 (the origin). At threshold 0, everything is flagged positive — TPR = 1, FPR = 1 (the top-right corner). Every point traced out in between is one (FPR, TPR) pair for one threshold value — plot all of them, and you get the ROC curve.

Drag the slider down: more points get flagged positive, so both TPR and FPR climb and the red dot slides up-right along the curve, toward (1,1). Drag it up: fewer positive flags, both rates drop toward (0,0). The dashed diagonal is what a coin-flip classifier with zero real signal would trace out.

Reading AUC

AUC = 0.5 On the diagonal — the model's ranking of scores carries no real information about the actual class. Equivalent to guessing.
0.5 < AUC < 1.0 The typical real-world case — the model does better than random at ranking positives above negatives, but imperfectly.
AUC = 1.0 Perfect separation — every positive scores higher than every negative, for some ordering of scores. No threshold ever confuses the two classes.

AUC has a clean probabilistic reading too: it's the probability that a randomly chosen positive example gets a higher predicted score than a randomly chosen negative example.

Why AUC is threshold-independent (and accuracy/F1 aren't)

Accuracy and F1 are each a single number computed at one fixed threshold — change the threshold and they change, sometimes drastically, even though the underlying model (its ranking of who's more likely positive) hasn't changed at all. AUC integrates over every threshold at once, so it measures something more fundamental: how well-separated the model's score distributions are for the two classes, independent of wherever you eventually decide to draw the line. That makes it the right metric for comparing two models' raw discriminative power, and a poor metric for judging "is this specific deployed threshold good enough" — for that, go back to precision/recall/F1 at the threshold you actually plan to use.

Test Your Understanding

Hard

5 questions on Classification Metrics. Pick an answer for each, then check.

1. A dataset is 98% negative, 2% positive. A model predicts "negative" for every single input. What's the biggest problem with reporting its accuracy as the headline metric?

Explanation: Predicting the majority class for everything scores accuracy equal to the majority class's share of the data (98% here) while providing zero actual predictive value for the minority class — the exact trap this section's fraud example illustrates.

2. A spam filter is tuned to almost never mark real email as spam, even if that means some spam gets through. This design choice prioritizes which metric, and which error type does it accept more of?

Explanation: "Almost never wrongly flag a real email" is exactly precision (TP/(TP+FP)) — minimizing false positives, i.e. Type I errors on the spam class. The tradeoff is accepting more false negatives (Type II) — spam that slips through — as described in the spam-vs-cancer comparison.

3. Model A: precision = 0.9, recall = 0.9. Model B: precision = 0.99, recall = 0.3. Which has the higher F1 score, and why does F1 favor it?

Explanation: Model A's F1 ≈ 0.9; Model B's F1 = 2(0.99×0.3)/(0.99+0.3) ≈ 0.46. The harmonic mean is dominated by the smaller of the two values, so Model B's weak 0.3 recall drags its F1 down hard — exactly the worked example in this section, just with different numbers.

4. Using the ROC widget on this page, as you drag the threshold slider from 1.0 down toward 0.0, what happens?

Explanation: Lowering the threshold flags more points positive, which can only increase or hold steady both TPR and FPR — so the marked point slides up the fixed curve toward (1,1). The curve's shape (and AUC) is a property of the model's score distributions, not of any one threshold — only the marked point on it moves.

5. Why is AUC described as "threshold-independent" while accuracy and F1 are not?

Explanation: AUC is the area under the entire curve traced across all thresholds — a property of how well-separated the model's score distributions are. Accuracy and F1 collapse everything into one number tied to whatever threshold you pick, so they shift if that threshold shifts even when the underlying model hasn't changed.
