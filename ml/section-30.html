30. Ensemble Learning: Voting

Wisdom of crowds · the ensemble family (voting, bagging, boosting, stacking) · Hard vs Soft Voting · VotingClassifier & VotingRegressor

Extended notes — this topic isn't covered in the CampusX playlist notes this site is based on. Written from scratch to continue the curriculum, in the same style as the rest of the site.
Concept

Introduction to Ensemble Learning

Every algorithm you've studied so far — Linear Regression, Decision Trees, KNN, SVM, Logistic Regression — trains one model and asks it to make every prediction alone. Ensemble Learning asks a different question: what if, instead of trusting one model, you trained several models and combined their opinions? In practice, the combination is very often better than the single best model in the group.

The "Wisdom of Crowds" Analogy

Ask one random person to guess the weight of an ox at a county fair, and their guess could be wildly off. Ask 800 random people — farmers, butchers, tourists who've never seen livestock — and average their guesses, and the average lands astonishingly close to the true weight. This is the famous 1907 story that gave the idea its name. It works because individual errors are mostly random and uncorrelated — one person overestimates, another underestimates, and when you average across many independent guesses, the errors cancel out and what's left is closer to the truth.

The same logic applies to ML models. A single Decision Tree might overfit to quirks in the training data. A single KNN might be thrown off by noisy neighbors. But if you train many different models and combine their predictions, the individual mistakes — as long as they aren't all making the same mistake — tend to average out, leaving a combined prediction that is more stable and often more accurate than any single member.

Why combine weak/diverse models?

  • A single strong model can still have blind spots — regions of the input space it consistently gets wrong.
  • Several diverse models rarely share the exact same blind spots, so combining them covers more ground.
  • Diversity matters more than raw individual strength — three models that are 60% accurate but wrong in different places can outperform one model that's 70% accurate on its own.
  • Averaging/voting reduces the variance contributed by any single model's quirks (formalized in the Bagging and Random Forest pages next).

What "ensemble" is — and isn't

  • Ensemble is a meta-technique — a strategy for combining models, not an algorithm that learns patterns from raw features itself.
  • It sits orthogonal to the Supervised / Unsupervised / Reinforcement split from Day 1 — an ensemble is usually built out of supervised base learners, but "ensemble" itself is not a fourth learning paradigm.
  • It's also orthogonal to Classification vs Regression — the same ensemble ideas apply to both, just with a different way of aggregating (vote vs average).

Overview — The Ensemble Family

There isn't just one way to combine models. Over the next several pages of this course you'll meet four major families, each combining models in a structurally different way:

Classification & Regression

Voting Ensemble

A Voting Ensemble is the simplest possible ensemble: pick a handful of different algorithms — say a Logistic Regression, a KNN, and a Decision Tree — train each one on the same training data, and combine their predictions with a fixed rule. No sequencing, no resampling — just "ask several different experts and combine their answers."

Hard Voting (Classification)

Each classifier outputs a class label. The ensemble's prediction is simply the majority class — whichever label the most models voted for.

Example: 3 classifiers predicting spam / not-spam for one email vote Spam, Spam, Not-Spam. Majority is Spam (2 out of 3) → the ensemble predicts Spam. Ties are typically broken by class order or by falling back to predicted probabilities.

Soft Voting (Classification)

Each classifier outputs predicted probabilities per class (e.g. via predict_proba), not just a hard label. The ensemble averages the probabilities across models, then picks the class with the highest average probability.

Example: Model A says [0.55, 0.45], Model B says [0.51, 0.49], Model C says [0.20, 0.80] for classes [Not-Spam, Spam]. Averaged: [0.42, 0.58] → predicts Spam. Notice hard voting would have said Not-Spam, Not-Spam, Spam → majority Not-Spam — a different answer. Soft voting used the strength of each model's conviction, not just its final label.

When is Soft Voting better?

Soft voting usually outperforms hard voting if the individual classifiers' probability estimates are reasonably calibrated — meaning a predicted probability of 0.8 really does correspond to being right about 80% of the time. It lets confidently-correct models outweigh barely-confident ones instead of treating every vote as equal. The catch: some models (e.g. SVMs without extra calibration) produce probability-like scores that aren't well calibrated, in which case soft voting can be misled by an overconfident-but-wrong model. Hard voting is more robust when you don't trust the probability estimates.

Code — VotingClassifier

from sklearn.ensemble import VotingClassifier
from sklearn.linear_model import LogisticRegression
from sklearn.neighbors import KNeighborsClassifier
from sklearn.tree import DecisionTreeClassifier
from sklearn.model_selection import train_test_split, cross_val_score

X_train, X_test, y_train, y_test = train_test_split(X, y, test_size=0.2, random_state=1)

clf1 = LogisticRegression()
clf2 = KNeighborsClassifier(n_neighbors=5)
clf3 = DecisionTreeClassifier(max_depth=5)

# HARD VOTING — majority class wins
voting_hard = VotingClassifier(
    estimators=[('lr', clf1), ('knn', clf2), ('dt', clf3)],
    voting='hard'
)
voting_hard.fit(X_train, y_train)
print("Hard voting accuracy:", voting_hard.score(X_test, y_test))

# SOFT VOTING — average predicted probabilities, then argmax
# every base estimator MUST support predict_proba
voting_soft = VotingClassifier(
    estimators=[('lr', clf1), ('knn', clf2), ('dt', clf3)],
    voting='soft',
    weights=[2, 1, 1]   # optional — trust lr twice as much as the others
)
voting_soft.fit(X_train, y_train)
print("Soft voting accuracy:", voting_soft.score(X_test, y_test))

# sanity check — compare against each individual model
for name, clf in voting_hard.named_estimators_.items():
    score = cross_val_score(clf, X_train, y_train, cv=5).mean()
    print(name, "standalone CV accuracy:", round(score, 3))

VotingRegressor — the Regression Counterpart

Regression has no "majority class" to vote on, so there's only one aggregation rule: average the numeric predictions from each base regressor (optionally weighted).

from sklearn.ensemble import VotingRegressor
from sklearn.linear_model import LinearRegression
from sklearn.svm import SVR
from sklearn.tree import DecisionTreeRegressor

reg1 = LinearRegression()
reg2 = SVR(kernel='rbf')
reg3 = DecisionTreeRegressor(max_depth=5)

voting_reg = VotingRegressor(
    estimators=[('lin', reg1), ('svr', reg2), ('dt', reg3)]
)
voting_reg.fit(X_train, y_train)

y_pred = voting_reg.predict(X_test)   # = simple/weighted average of reg1, reg2, reg3 predictions

Test Your Understanding

Hard

5 questions on Voting Ensembles. Pick an answer for each, then check.

1. Three classifiers vote on a binary label. Hard voting gives labels [1, 0, 0] → majority 0. Their probabilities for class 1 are [0.49, 0.48, 0.02]. What does soft voting predict, and why does it differ from hard voting here?

Explanation: Averaging [0.49, 0.48, 0.02] gives ≈0.33 for class 1, well under 0.5, so soft voting predicts class 0 — the same as hard voting in this particular case. This is a good trick question: soft and hard voting frequently agree; they only diverge when the probability mass shifts the average across the 0.5 threshold despite the label-count majority pointing the other way (as in the page's spam example, where 2 weak "Not-Spam" votes were outweighed by one strongly-confident "Spam" probability).

2. You build a VotingClassifier with voting='soft' using Logistic Regression, KNN, and an SVC. The SVC was created with default settings (no probability=True). What happens?

Explanation: Soft voting needs probability estimates from every member. sklearn's SVC does not expose predict_proba unless you construct it with probability=True (which fits an extra internal calibration via cross-validation). Without it, a soft-voting ensemble containing that SVC raises an AttributeError.

3. Which statement about ensemble learning as a category is correct?

Explanation: Ensembling is a strategy for combining models (usually supervised base learners), not a learning paradigm of its own, and it applies to both task types. Only boosting methods train sequentially — voting and bagging train their members independently/in parallel.

4. Why does the "wisdom of crowds" effect break down if all the base models in your voting ensemble are near-identical (e.g. three Decision Trees trained with the same hyperparameters on the same data)?

Explanation: The crowd-wisdom effect relies on errors being roughly independent so they cancel out when combined. Identical/near-identical models trained the same way make the same mistakes on the same inputs — their errors are correlated, not independent — so combining them adds almost nothing over using just one of them. Diversity between base learners is what makes voting (and bagging, and random forests) work.

5. For a VotingRegressor combining a Linear Regression, an SVR, and a Decision Tree Regressor, how is the final prediction computed for a single test point?

Explanation: Regression has no discrete classes to vote on, so VotingRegressor's only rule is to average the numeric predictions from each base regressor — a straight mean by default, or a weighted mean if `weights` is supplied.
