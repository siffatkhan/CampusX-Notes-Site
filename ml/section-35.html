35. Gradient Boosting

Fitting residuals instead of reweighting samples · gradient descent in function space · regression & classification

Extended notes — this topic isn't covered in the CampusX playlist notes this site is based on. Written from scratch to continue the curriculum, in the same style as the rest of the site.
Concept

Explained — Fitting the Residuals

Gradient Boosting is boosting's other big idea. AdaBoost corrects mistakes by reweighting samples — misclassified points get louder. Gradient Boosting corrects mistakes a different way: instead of changing sample weights, each new model is trained to directly predict the residual errors — the leftover gap between what the current ensemble predicts and the true answer. Add that prediction (shrunk by a learning rate) onto the running total, and the ensemble gets a little bit closer to the truth. Repeat.

The key insight — gradient descent in function space

In ordinary gradient descent (Linear/Logistic Regression), you take a loss function, compute its gradient with respect to the model's parameters, and step the parameters a little in the direction that reduces loss. Gradient Boosting does the exact same thing, except the thing being adjusted isn't a parameter vector — it's the function \(F(x)\) that the ensemble represents. At each round, the "gradient" is a vector of per-sample values telling you how the loss would change if the prediction on each sample moved a little — and it turns out that for plain squared-error loss, that gradient is exactly the residual, \(y_i - F(x_i)\). Fitting a small tree to those residuals and adding it in (scaled by a learning rate) is, quite literally, one step of gradient descent — except each "step direction" is itself a full decision tree rather than a fixed-size vector.

The general algorithm

  1. Start with a naive initial prediction \(F_0(x)\) — for squared-error regression, that's just the mean of \(y\) for every sample.
  2. Compute the residuals: \(r_i = y_i - F_{m-1}(x_i)\) for every sample (the negative gradient of the loss).
  3. Fit a new small tree \(h_m(x)\) to predict those residuals, not the original targets.
  4. Update the ensemble: \(F_m(x) = F_{m-1}(x) + \eta \cdot h_m(x)\), where \(\eta\) (learning_rate) shrinks the new tree's contribution.
  5. Repeat steps 2–4 for n_estimators rounds. Each round's residuals should get a little smaller as the ensemble improves.

A tiny numeric taste — one point, three rounds

Say the true value is \(y = 40\), the initial prediction is the dataset mean \(F_0 = 23.75\), and learning_rate \(\eta = 0.1\). To isolate exactly what the learning rate does, assume (unrealistically, but usefully) that each round's small tree manages to predict that round's residual perfectly:

RoundF (prediction so far)Residual = y − Fη × tree predictionNew F
0 (init)23.7516.25—23.75
123.7516.250.1 × 16.25 = 1.62525.375
225.37514.6250.1 × 14.625 = 1.462526.8375
326.837513.16250.1 × 13.1625 = 1.3162528.15375

Notice the residual shrinks by a factor of exactly \((1-\eta) = 0.9\) every round (16.25 → 14.625 → 13.1625 — each is 90% of the last) under this perfect-fit simplification. That's the mechanism laid bare: a smaller learning rate means slower, more cautious closing of the gap, requiring more rounds — but each round contributes a smaller, gentler correction, which tends to generalize better than a few large, aggressive corrections. In reality a shallow tree won't perfectly capture the residual pattern in one shot, so real convergence is noisier than this clean geometric decay — but the shrinking-error trend is exactly what actually happens.

Regression

Gradient Boosting for Regression

For regression under squared-error loss, the algorithm from above is used exactly as written, with nothing hidden:

  • Initial prediction: \(F_0(x) = \text{mean}(y)\) for every sample — the simplest possible model.
  • Residual: \(r_i = y_i - F_{m-1}(x_i)\) — literally "actual minus predicted," recomputed fresh every round.
  • Fit a tree \(h_m\) to predict \(r_i\) from the features \(x_i\) — a small regression tree, usually only 3–8 leaves deep.
  • Update: \(F_m(x) = F_{m-1}(x) + \eta \cdot h_m(x)\).
  • Repeat for n_estimators rounds; final prediction is \(F_M(x)\).
0.10

Illustrative decay of the starting residual (16.25) over 30 boosting rounds, under the simplified "tree fits residual perfectly" assumption above — remaining residual after round t ≈ \(r_0 (1-\eta)^t\). A small η needs far more rounds to close the same gap; a large η closes it fast but with bigger, more aggressive per-round jumps that risk overshooting on real (imperfectly-fit) data.

Code — GradientBoostingRegressor

from sklearn.ensemble import GradientBoostingRegressor
from sklearn.model_selection import train_test_split

X_train, X_test, y_train, y_test = train_test_split(X, y, test_size=0.2, random_state=1)

gbr = GradientBoostingRegressor(
    n_estimators=300,
    learning_rate=0.05,   # small steps, many rounds — usually generalizes best
    max_depth=3,          # each tree stays shallow
    subsample=0.8,        # stochastic GB: train each tree on an 80% row subsample
    random_state=1
)
gbr.fit(X_train, y_train)
print("Test R^2:", gbr.score(X_test, y_test))

# staged_predict lets you see the ensemble's prediction after each round
import numpy as np
test_mse_per_round = [
    np.mean((y_test - pred) ** 2) for pred in gbr.staged_predict(X_test)
]
Classification

Gradient Boosting for Classification

Class labels like "0" and "1" aren't things you can meaningfully subtract to get a residual the way you can with a continuous number. Gradient Boosting solves this by working in a different space entirely: instead of predicting the class directly, the ensemble builds up a running log-odds score \(F(x)\), exactly like Logistic Regression's linear score before the sigmoid is applied.

The intuitive bridge — pseudo-residuals from log-loss

At any point, the ensemble's predicted probability is \(p = \sigma(F(x))\) (the sigmoid of the current log-odds score). The loss being minimized is log-loss (cross-entropy). If you take the negative gradient of log-loss with respect to \(F(x)\) — the "how should this score move to reduce loss" signal — it works out to a wonderfully simple quantity:

$$ \text{pseudo-residual} = y_i - p_i $$

That's "actual class (0 or 1) minus predicted probability" — a quantity that looks and behaves just like the regression residual, even though we're really tracking a gradient in log-odds space, not a subtractable target value. A small regression tree is fit to these pseudo-residuals (predicting a continuous adjustment to the log-odds score), that tree's output is added to \(F(x)\) scaled by the learning rate, and the whole cycle repeats — same shape as regression, different space and a different definition of "residual."

Once training finishes, the final probability is \(\hat{p}(x) = \sigma(F_M(x))\), thresholded (commonly at 0.5) to get the predicted class. Multi-class problems generalize this by keeping one log-odds function per class and using a softmax instead of a sigmoid.

Code — GradientBoostingClassifier

from sklearn.ensemble import GradientBoostingClassifier

gbc = GradientBoostingClassifier(
    n_estimators=300,
    learning_rate=0.05,
    max_depth=3,
    subsample=0.8,
    random_state=1
)
gbc.fit(X_train, y_train)

print("Test accuracy:", gbc.score(X_test, y_test))
print("Predicted probabilities:", gbc.predict_proba(X_test)[:5])   # sigma(F_M(x)) per class

Both variants share the same two knobs you saw with AdaBoost — n_estimators and learning_rate — with the exact same tradeoff: more rounds at a lower learning rate is slower to train but usually generalizes better than fewer rounds at a high learning rate. The next page, XGBoost, takes this same gradient-fitting idea and re-engineers it from the ground up for speed, regularization, and robustness.

Test Your Understanding

Hard

5 questions on Gradient Boosting. Pick an answer for each, then check.

1. What does each new tree in Gradient Boosting for regression get trained to predict?

Explanation: Each round computes r_i = y_i - F_(m-1)(x_i) and fits the new tree to predict that residual, not the original y — that's the defining mechanic that separates Gradient Boosting from AdaBoost's reweighting approach.

2. Why is fitting a tree to residuals, then adding a shrunken version of its output to the running prediction, described as "gradient descent in function space"?

Explanation: The residual literally equals the negative gradient of squared-error loss w.r.t. the prediction. Fitting a tree to approximate that gradient, then stepping F in that direction by a shrunk amount, is a direct functional analogue of parameter-space gradient descent.

3. Using the illustrative decay model r_t ≈ r_0·(1-η)^t, roughly how many rounds does it take for the residual to be cut in half, if η = 0.05?

Explanation: Solve 0.95^t = 0.5 → t = ln(0.5)/ln(0.95) ≈ 13.5, so about 14 rounds. This is exactly why a smaller learning_rate demands a correspondingly larger n_estimators to reach the same level of fit.

4. For GradientBoostingClassifier, what exactly is the "pseudo-residual" that each new tree is fit to, and why can't it just be y - F(x) directly the way regression does it?

Explanation: Class labels aren't directly subtractable from a log-odds score. The negative gradient of log-loss w.r.t. F(x) works out to y-p (actual class minus predicted probability) — the classification analogue of a regression residual, hence "pseudo-residual."

5. Compared to AdaBoost, which statement about Gradient Boosting's mechanism is most accurate?

Explanation: Both are sequential boosting methods (ruling out D), but they differ in mechanism: AdaBoost reweights the importance of samples for the next weak learner's training objective, while Gradient Boosting has the next learner directly target the residual/pseudo-residual error itself.
