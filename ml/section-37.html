37. Stacking & Blending

Learning to combine models instead of voting · out-of-fold predictions and why they matter · StackingClassifier/Regressor · Blending as a faster, leakier cousin

Extended notes — this topic isn't covered in the CampusX playlist notes this site is based on. Written from scratch to continue the curriculum, in the same style as the rest of the site.
Ensemble

Stacking

Back on the Voting page you saw the fifth family of the ensemble tree get a one-line mention and get shelved: Stacking. Voting combines several different models with a fixed rule — majority vote, or an average of probabilities. That rule is decided by you, in advance, and never changes no matter how the base models actually perform. Stacking asks a sharper question: instead of hand-picking "average them" or "majority vote," what if a model learned the best way to combine the base models' predictions?

The core idea — a model that learns from other models' outputs

Stacking ("stacked generalization") works in two layers:

  1. Base models (Level 0) — train several diverse models on the training data. Diversity matters more than raw strength: pick models with different biases, e.g. a Decision Tree (captures non-linear splits), an SVM (finds margin-based boundaries), and a Linear/Logistic model (captures linear trends). Each one will make different kinds of mistakes.
  2. Meta-model (Level 1) — instead of averaging or voting on the base models' predictions, train a new model whose inputs are the base models' predictions themselves, and whose target is still the original label. The meta-model learns, from data, how much to trust each base model — and even how to combine them conditionally (e.g. "trust the SVM more when the Decision Tree and Linear model disagree").

Voting — fixed combination rule

You decide upfront: "average the three probabilities" or "take the majority label." The combination weights are implicitly equal and never adapt to how good each base model actually is on this dataset.

Stacking — learned combination rule

The meta-model's own trainable parameters (e.g. a Logistic/Linear Regression's coefficients on top of the base predictions) figure out the best weighting — automatically, from data, potentially even a non-linear combination if the meta-model itself is more complex than linear.

Why the meta-model must NOT train on in-sample predictions

Here's the trap. Suppose you fit each base model on the full training set, then immediately generate their predictions on that same training set to feed the meta-model. A base model like a deep Decision Tree can nearly memorize its own training data — its "predictions" there are suspiciously close to the true labels, sometimes exactly equal to them. If the meta-model trains on those in-sample predictions, it learns to trust whichever base model overfit the hardest, because that's the one whose training-set predictions looked most accurate. At prediction time on genuinely new data, that same base model's predictions will be far less accurate — but the meta-model, having learned the wrong lesson, over-relies on it anyway. This is information leakage: the meta-model is implicitly told information about the training labels that it wouldn't have on unseen data, and the whole stack overfits.

The fix — Out-of-Fold (OOF) predictions

The standard fix borrows the same trick as k-fold cross-validation. To generate the training data for the meta-model:

  1. Split the training set into K folds (e.g. K=5).
  2. For each fold i: train each base model on the other K−1 folds, then predict on fold i — the model has never seen fold i during that training run.
  3. After looping through all K folds, every training row has exactly one prediction per base model, and crucially, that prediction always came from a model that did not see that row while training.
  4. These "out-of-fold" predictions — one honest, held-out-style prediction per row per base model — become the feature matrix the meta-model trains on, paired with the true labels.
  5. Finally, refit each base model on the entire training set (no folds) for use at actual prediction time — the fold-splitting was only a device to generate leak-free meta-features.

Because every OOF prediction reflects how well a model generalizes to data it didn't train on, the meta-model learns realistic, well-calibrated trust in each base model — the same reason cross-validation gives you a fairer performance estimate than train-set accuracy.

Code — sklearn StackingClassifier

sklearn's StackingClassifier / StackingRegressor handle the out-of-fold bookkeeping internally via a cv parameter — you never have to hand-roll the fold loop.

from sklearn.ensemble import StackingClassifier
from sklearn.linear_model import LogisticRegression
from sklearn.svm import SVC
from sklearn.tree import DecisionTreeClassifier
from sklearn.model_selection import train_test_split

X_train, X_test, y_train, y_test = train_test_split(X, y, test_size=0.2, random_state=1)

base_learners = [
    ('tree', DecisionTreeClassifier(max_depth=6, random_state=1)),
    ('svm', SVC(probability=True, random_state=1)),
    ('linear', LogisticRegression(max_iter=1000))
]

stack = StackingClassifier(
    estimators=base_learners,          # Level 0 — the diverse base models
    final_estimator=LogisticRegression(),  # Level 1 — the meta-model
    cv=5,                                # generates out-of-fold predictions internally
    stack_method='predict_proba',        # feed probabilities, not just hard labels, to the meta-model
    n_jobs=-1
)

stack.fit(X_train, y_train)
print("Stacked accuracy:", stack.score(X_test, y_test))

Code — sklearn StackingRegressor

from sklearn.ensemble import StackingRegressor
from sklearn.linear_model import Ridge
from sklearn.svm import SVR
from sklearn.tree import DecisionTreeRegressor

base_learners = [
    ('tree', DecisionTreeRegressor(max_depth=6, random_state=1)),
    ('svm', SVR()),
    ('ridge', Ridge())
]

stack_reg = StackingRegressor(
    estimators=base_learners,
    final_estimator=Ridge(),   # a simple linear meta-model is a common, robust default
    cv=5,
    n_jobs=-1
)

stack_reg.fit(X_train, y_train)
print("Stacked R^2:", stack_reg.score(X_test, y_test))
Ensemble

Blending

Blending is stacking's simpler, faster, and slightly leakier cousin. It solves the same "don't train the meta-model on in-sample predictions" problem, but with a plain holdout split instead of K-fold cross-validation.

The blending recipe

  1. Split the training set once into a training portion (e.g. 80%) and a small holdout/blend set (e.g. 20%).
  2. Train each base model only on the training portion.
  3. Generate each base model's predictions on the holdout set — these are "honest" predictions since the base models never saw the holdout rows.
  4. Train the meta-model on the holdout set's predictions (as features) against the holdout set's true labels — that's it, one single pass, no folds.
AspectStacking (OOF / cross-validation)Blending (single holdout)
Meta-model training dataEvery training row gets an OOF prediction — uses 100% of the training dataOnly the holdout slice (e.g. 20%) generates meta-model training data
Compute costHigher — each base model is trained K times (once per fold), plus once more on the full setLower — each base model is trained just once
Sensitivity to the splitRobust — averages over K different fold arrangementsMore fragile — results depend on which particular rows landed in that one holdout slice, especially on small datasets
Leakage riskVery low, by constructionSlightly higher in practice — easy to accidentally let holdout information leak if not careful, and the meta-model sees fewer effective examples
Implementation complexityHigher — needs the full CV loop (sklearn automates this)Lower — just one extra train_test_split

In short: blending trades robustness for simplicity and speed. It's popular in time-constrained settings (Kaggle competitions with tight deadlines are a classic example) where you want a quick, working combination without setting up a full OOF pipeline — but with more data or more time, stacking's cross-validated approach generalizes more reliably.

Code — Blending from scratch

sklearn has no dedicated BlendingClassifier — blending is simple enough that it's usually hand-rolled with a couple of train_test_split calls.

import numpy as np
from sklearn.model_selection import train_test_split
from sklearn.linear_model import LogisticRegression
from sklearn.svm import SVC
from sklearn.tree import DecisionTreeClassifier

# 1. Carve out a holdout/blend set from the training data
X_train_full, X_test, y_train_full, y_test = train_test_split(X, y, test_size=0.2, random_state=1)
X_base_train, X_holdout, y_base_train, y_holdout = train_test_split(
    X_train_full, y_train_full, test_size=0.25, random_state=1  # holdout = 20% of the original data
)

# 2. Train base models ONLY on X_base_train
tree  = DecisionTreeClassifier(max_depth=6, random_state=1).fit(X_base_train, y_base_train)
svm   = SVC(probability=True, random_state=1).fit(X_base_train, y_base_train)
linear = LogisticRegression(max_iter=1000).fit(X_base_train, y_base_train)

# 3. Predict on the holdout set (models have never seen these rows)
holdout_preds = np.column_stack([
    tree.predict_proba(X_holdout)[:, 1],
    svm.predict_proba(X_holdout)[:, 1],
    linear.predict_proba(X_holdout)[:, 1],
])

# 4. Train the meta-model on holdout predictions -> true holdout labels
meta_model = LogisticRegression()
meta_model.fit(holdout_preds, y_holdout)

# 5. At inference time: get base predictions on new data, feed to the meta-model
test_preds = np.column_stack([
    tree.predict_proba(X_test)[:, 1],
    svm.predict_proba(X_test)[:, 1],
    linear.predict_proba(X_test)[:, 1],
])
final_preds = meta_model.predict(test_preds)

Quick recap — three ways to combine models

  • Voting — fixed rule (average/majority), no meta-model, no leakage concerns at all.
  • Blending — learned combination via a meta-model trained on a single holdout split's predictions. Fast, simple, more variance in the result.
  • Stacking — learned combination via a meta-model trained on out-of-fold predictions across the whole training set. Slower, more robust.

Test Your Understanding

Hard

5 questions on Stacking & Blending. Pick an answer for each, then check.

1. What is the fundamental difference between Voting and Stacking?

Explanation: Voting's combination rule is fixed and hand-chosen. Stacking introduces a trainable meta-model whose job is specifically to learn, from data, how to best weight/combine the base models' outputs — a strictly more flexible (and more expensive) approach.

2. Why must the meta-model in Stacking be trained on out-of-fold predictions rather than each base model's predictions on its own training data?

Explanation: A base model can nearly memorize its own training data, making its in-sample predictions artificially close to the true labels. If fed to the meta-model, this leaks information and biases the meta-model toward trusting the most-overfit base model — a mistake that surfaces as poor generalization on new data. OOF predictions come from folds the base model didn't train on, so they reflect genuine generalization ability.

3. After generating out-of-fold predictions across all K folds to train the meta-model, what should be done with each base model before using the stack to predict on brand-new data?

Explanation: The K-fold splitting is purely a device for generating honest, leak-free training features for the meta-model. Once that's done, each base model is refit on the full training set so it benefits from all available data when actually deployed — this is exactly what sklearn's StackingClassifier/Regressor does internally.

4. Which statement best captures the practical tradeoff between Stacking and Blending?

Explanation: Blending trades robustness for speed/simplicity — it uses only the holdout slice to train the meta-model and each base model is trained just once, but results can shift noticeably depending on the luck of that one split, especially on smaller datasets. Stacking's full K-fold OOF process uses all the training data for meta-features and averages over K different fold arrangements, at the cost of training each base model K+1 times.

5. You're deciding what base models to include in a stacking ensemble. Which set of base models is the best choice, and why?

Explanation: Stacking (like all ensembling) benefits most when base models are diverse — likely to make different, less-correlated errors. Nearly-identical models (many Decision Trees with similar depth, or duplicates of one model) give the meta-model little genuinely new information to combine, since their predictions are highly correlated with each other.
