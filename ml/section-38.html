38. Clustering: K-Means, Hierarchical & DBSCAN

K-Means & the Elbow Method · Agglomerative Hierarchical Clustering & dendrograms · DBSCAN and density-based clusters

Extended notes — this topic isn't covered in the CampusX playlist notes this site is based on. Written from scratch to continue the curriculum, in the same style as the rest of the site.

Every algorithm since Day 1's supervised/unsupervised split — Linear Regression, Logistic Regression, Decision Trees, KNN, Random Forest, Boosting, Stacking — has been supervised: every training row came with a known correct answer. This page is fully unsupervised — the only page besides PCA (Day 47–49) to be so. There is no label column at all. The goal isn't to predict an answer; it's to discover structure that was already sitting in the data.

Unsupervised

K-Means Clustering

K-Means is the workhorse clustering algorithm — simple, fast, and usually the first thing anyone reaches for. The goal: given a pile of unlabeled points, split them into K groups such that points inside a group are similar to each other and different from points in other groups.

Analogy — reshuffling into groups

Imagine dropping K flags at random spots on a large field full of people, then telling everyone: "walk to your nearest flag." Now, at each flag, the group re-plants the flag exactly at their own average position — the group's center of mass. Since the flag moved, some people near the edge might now be closer to a different flag, so everyone re-checks their nearest flag and some people switch groups. Repeat "walk to nearest flag → re-plant flag at group's average position" over and over. Eventually nobody switches groups anymore and the flags stop moving — that's convergence.

The algorithm, step by step

  1. Choose K — decide how many clusters you want up front (K-Means requires this; more on choosing it below).
  2. Initialize centroids — place K centroids, either at random data points or (better, see below) using k-means++.
  3. Assignment step — assign every point to its nearest centroid (typically by Euclidean distance). This partitions the data into K clusters.
  4. Update step — recompute each centroid as the mean position of all points currently assigned to it.
  5. Repeat steps 3–4 until assignments stop changing (or centroids move less than some tiny threshold, or a max iteration count is hit) — this is convergence.

Formally, K-Means is minimizing the within-cluster sum of squares (WCSS) — also called inertia — the total squared distance from every point to its own cluster's centroid:

$$ \text{WCSS} = \sum_{k=1}^{K} \sum_{x_i \in C_k} \lVert x_i - \mu_k \rVert^2 $$

where \(C_k\) is cluster k and \(\mu_k\) is its centroid. Each iteration of assignment + update can only decrease (or hold steady) this quantity, which is why the algorithm is guaranteed to converge — though not necessarily to the global best split.

Choosing K — the Elbow Method

K-Means needs K decided in advance, but you rarely know the "true" number of groups ahead of time. The Elbow Method: run K-Means for a range of K values (say 1 through 10), record the WCSS/inertia for each, and plot K vs WCSS. WCSS always decreases as K increases (more clusters can only fit the data at least as well — at the extreme, K = number of points gives WCSS = 0), so you're not looking for a minimum. You're looking for the "elbow" — the point where adding more clusters stops giving a big drop in WCSS and the curve flattens out. That bend is a reasonable, if fuzzy, choice for K.

from sklearn.cluster import KMeans
import matplotlib.pyplot as plt

wcss = []
K_range = range(1, 11)
for k in K_range:
    km = KMeans(n_clusters=k, init='k-means++', n_init=10, random_state=1)
    km.fit(X)
    wcss.append(km.inertia_)   # inertia_ = WCSS for the fitted model

plt.plot(K_range, wcss, marker='o')
plt.xlabel('K (number of clusters)')
plt.ylabel('WCSS (inertia)')
plt.title('Elbow Method')
plt.show()
# Look for the "elbow" — the K after which the curve flattens

Limitation — shape assumption

K-Means implicitly assumes clusters are roughly spherical (globular) and similarly sized, because it partitions space using distance-to-nearest-centroid, which draws straight boundary lines between centroids. Elongated, crescent-shaped, or nested clusters get sliced incorrectly.

Limitation — initialization sensitivity

Random initial centroid placement can converge to a poor local minimum of WCSS, and different random seeds can give visibly different final clusters. Fix: k-means++ initialization (sklearn's default) picks initial centroids that are deliberately spread far apart from each other, which empirically converges to much better solutions than pure random placement — and running with several random restarts (n_init) and keeping the best result helps further.

Limitation — sensitive to outliers

Since centroids are means, a single far-flung outlier can drag a centroid noticeably away from where the bulk of its cluster actually sits — means are not robust to extreme values (recall the mean-vs-median discussion from the Outliers page).

Limitation — sensitive to feature scale

Distance calculations are dominated by whichever feature has the largest numeric range. A "salary" column in the tens of thousands will swamp an "age" column in the tens — always scale features (e.g. StandardScaler) before clustering.

Code — Fitting K-Means

from sklearn.preprocessing import StandardScaler
from sklearn.cluster import KMeans

X_scaled = StandardScaler().fit_transform(X)   # scale first — distances matter

kmeans = KMeans(
    n_clusters=3,
    init='k-means++',   # smarter centroid initialization (default)
    n_init=10,           # run 10 times with different seeds, keep the best (lowest WCSS)
    random_state=1
)
labels = kmeans.fit_predict(X_scaled)

print("Cluster centers:\n", kmeans.cluster_centers_)
print("Inertia (WCSS):", kmeans.inertia_)

Agglomerative Hierarchical Clustering

Hierarchical clustering takes a completely different approach: instead of committing to K clusters upfront, it builds a whole hierarchy of possible groupings, from every point alone to everything in one cluster, and lets you pick where to "cut" that hierarchy afterward.

The bottom-up (agglomerative) approach

  1. Start with every single data point as its own cluster (N points → N clusters).
  2. Find the two closest clusters (by some distance/linkage rule — see below) and merge them into one.
  3. Repeat step 2 — the number of clusters shrinks by one each merge — until only a single cluster containing every point remains.

Every merge is recorded, in order, which is exactly what builds the dendrogram below. ("Agglomerative" means building up by merging; the opposite, "divisive," starts with one cluster and splits repeatedly — far less common in practice.)

Linkage criteria — what "closest clusters" means

A cluster can contain many points, so "distance between two clusters" needs a rule. This choice — the linkage criterion — meaningfully changes the resulting clusters.

LinkageDistance between two clusters =Tendency
SingleMinimum distance between any point in cluster A and any point in cluster BCan chain together long, straggly clusters ("chaining effect") — good at non-spherical shapes, sensitive to noise
CompleteMaximum distance between any point in A and any point in BTends to produce compact, roughly equal-diameter clusters; breaks up chains
AverageAverage distance across all pairs of points, one from A and one from BA middle ground between single and complete linkage
WardThe increase in total within-cluster variance (like WCSS) that would result from merging A and BMinimizes variance growth at each step — tends to produce clusters similar in spirit to K-Means; a common sensible default
Illustrative aid — generated for this site.

Reading bottom-up: individual points merge into small clusters, which merge into larger ones, until everything joins at the top. Cutting horizontally at a given height (dashed line) selects a cluster count — here the cut crosses 3 vertical lines, giving 3 clusters: {points 1,2}, {points 3,4}, {points 5,6}.

Reading and cutting the dendrogram

The dendrogram's y-axis is merge height — how dissimilar two clusters were when they got merged. Low merges join very similar points early; high merges join very different, already-large clusters late. To decide on a final cluster count, draw a horizontal line across the dendrogram at some height and count how many vertical lines it crosses — that's your K. Cutting low gives many small, tight clusters; cutting high gives few, broad clusters. A good cut height is often chosen by looking for the tallest vertical gap the line can pass through without crossing a merge — similar in spirit to the Elbow Method's "find the bend."

When to prefer Hierarchical over K-Means

  • You don't want to commit to K upfront — the dendrogram lets you decide after seeing the structure.
  • Clusters may be non-spherical or nested — single/average linkage in particular can trace irregular shapes K-Means can't.
  • You want the full hierarchy itself as an artifact (e.g. taxonomies, phylogenetic-style groupings), not just a flat partition.

The catch — scalability

Computing and updating all pairwise cluster distances costs at least O(n²) time and memory (naive implementations are O(n³)), versus K-Means' roughly O(n·K) per iteration. Hierarchical clustering becomes impractical well before K-Means does — typically past a few thousand to tens of thousands of points, depending on implementation.

Code — AgglomerativeClustering

from sklearn.cluster import AgglomerativeClustering
from scipy.cluster.hierarchy import dendrogram, linkage
import matplotlib.pyplot as plt

# Visualize the full dendrogram first (scipy) to pick a cut / cluster count
Z = linkage(X_scaled, method='ward')
dendrogram(Z)
plt.xlabel('Sample index')
plt.ylabel('Merge height (dissimilarity)')
plt.show()

# Then fit sklearn's AgglomerativeClustering with a chosen number of clusters
agg = AgglomerativeClustering(n_clusters=3, linkage='ward')
labels = agg.fit_predict(X_scaled)

DBSCAN

DBSCAN (Density-Based Spatial Clustering of Applications with Noise) throws out the "centroid" idea entirely. Its core insight: a cluster is a region where points are packed densely together, separated from other clusters by regions where points are sparse. This single idea gives DBSCAN two superpowers K-Means and hierarchical clustering don't have: it finds arbitrarily-shaped clusters, and it doesn't require you to specify the number of clusters at all.

Two parameters define "dense"

eps (ε) — the radius of the neighborhood around a point. Two points are "neighbors" if the distance between them is ≤ eps.
min_samples — the minimum number of neighbors (including the point itself, in sklearn's convention) required within a point's eps-radius for that point to count as being in a dense region.

The three point types

  • Core point — has at least min_samples points (itself included) within eps of it. Core points are the "interior" of a dense region.
  • Border point — has fewer than min_samples neighbors within eps of itself, but lies within eps of some core point. It's on the edge of a dense region — part of the cluster, but not dense enough on its own to anchor one.
  • Noise (outlier) — neither a core point nor within eps of any core point. Doesn't belong to any cluster at all.

A cluster forms by chaining together core points that are mutual neighbors (directly, or indirectly through a path of other core points), plus any border points attached to that chain. Because clusters grow by following wherever the density leads — not by measuring distance to a fixed centroid — DBSCAN traces out crescents, spirals, and other irregular shapes that would confuse K-Means. And because "noise" is a first-class outcome rather than being forced into the nearest cluster, DBSCAN naturally flags outliers instead of distorting a cluster to include them.

Code — DBSCAN

from sklearn.cluster import DBSCAN
from sklearn.preprocessing import StandardScaler

X_scaled = StandardScaler().fit_transform(X)

db = DBSCAN(eps=0.5, min_samples=5)
labels = db.fit_predict(X_scaled)

# sklearn convention: noise points are labeled -1
n_clusters = len(set(labels)) - (1 if -1 in labels else 0)
n_noise = list(labels).count(-1)
print(f"Clusters found: {n_clusters}, noise points: {n_noise}")

core_mask = db.core_sample_indices_   # indices of the core points

Practical tip — choosing eps with the k-distance graph

Picking eps by hand is guesswork. A standard trick: for each point, compute the distance to its k-th nearest neighbor (k = min_samples), sort all of these distances in ascending order, and plot them. The plot typically stays low and flat, then sharply bends upward — that bend marks a natural transition from "distances typical within dense regions" to "distances that only happen once you're crossing into sparse space." Pick eps near that bend (the same "find the elbow" instinct as the WCSS plot above).

from sklearn.neighbors import NearestNeighbors
import numpy as np
import matplotlib.pyplot as plt

k = 5  # same as your intended min_samples
neighbors = NearestNeighbors(n_neighbors=k).fit(X_scaled)
distances, _ = neighbors.kneighbors(X_scaled)

k_distances = np.sort(distances[:, k-1])   # distance to the k-th nearest neighbor, sorted
plt.plot(k_distances)
plt.xlabel('Points, sorted by k-distance')
plt.ylabel(f'Distance to {k}-th nearest neighbor')
plt.title('k-distance graph — look for the elbow/knee')
plt.show()

Test Your Understanding

Hard

5 questions on K-Means, Hierarchical Clustering & DBSCAN. Pick an answer for each, then check.

1. In the Elbow Method, why can't you just pick the K that minimizes WCSS?

Explanation: More clusters can only ever fit the data at least as tightly, so WCSS never increases with K — at K = n (one cluster per point), WCSS is exactly 0. Minimizing WCSS directly would always push you to the largest possible K, which is useless. Instead you look for the "elbow" — the point of diminishing returns.

2. Your data forms two concentric rings (a small circle of points inside a larger ring of points), with no gap-free spherical grouping possible. Which algorithm is most likely to correctly separate them, and why?

Explanation: K-Means assigns by nearest centroid, which produces roughly spherical partitions — it would slice the two rings into pie-wedge-like pieces, not respect the rings themselves. DBSCAN follows chains of density regardless of shape, so if each ring is a dense, connected band separated from the other by a sparser gap, DBSCAN can correctly identify each ring as its own cluster.

3. In a dendrogram built with Ward linkage, what does the height at which two clusters merge represent?

Explanation: Ward linkage specifically merges whichever pair of clusters causes the smallest increase in total within-cluster variance. The merge height in the resulting dendrogram directly encodes that variance-increase cost, which is why early (low) merges join very similar points/clusters and late (high) merges join very dissimilar, already-large groups. eps and min_samples are DBSCAN parameters, unrelated to hierarchical clustering.

4. In DBSCAN with min_samples=5, a point has only 3 neighbors within its eps radius, but one of those 3 neighbors is itself a core point. What is this point classified as?

Explanation: With only 3 neighbors and min_samples=5, this point fails the core-point threshold on its own. But because it is within eps of an actual core point, it qualifies as a border point — part of that cluster, just not dense enough to anchor/extend it further. Only points that are neither core nor within eps of any core point are labeled noise.

5. You have 500,000 unlabeled records and need to cluster them, but a full run of AgglomerativeClustering is far too slow on this size of data. What's the most defensible response given what you now know about scalability?

Explanation: Agglomerative clustering's pairwise-distance bookkeeping scales poorly (O(n^2) or worse), which is exactly the tradeoff called out against K-Means' roughly O(n·K) and DBSCAN's roughly O(n log n) with spatial indexing. At 500K records, K-Means or DBSCAN are the practical choices; nothing here suggests switching problem types (supervised vs unsupervised) or a hard universal size cap.
